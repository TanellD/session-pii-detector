# Как мы работаем

## Задачи
- Все задачи — issues в GitHub, все issues — на [доске GitHub Projects](https://github.com/users/TanellD/projects/1).
- Колонки: `Backlog → To do (этот этап) → In progress → Review → Done`.
- Метки: `stage-1..4`, `research`, `data`, `model`, `eval`, `infra`, `docs`, `deliverable`, `question`, `bug`.
- Майлстоуны = чекпоинты: `Ч1 05.11`, `Ч2 01.12`, `Ч3 15.12`, `Ч4 защита`.
- У задачи один исполнитель. Если задача дольше 3 дней, разбей её.
- Темы (данные, эксперименты с моделью, методики) — эпики, а не роли: задачи внутри них — sub-issues, исполнители назначаются на этап и могут меняться от этапа к этапу. Срез распределения — в `docs/project/team.md`.

## Ветки и PR
- `main` защищена: только через PR, минимум 1 апрув, зелёный CI.
- Ветки: `<тип>/<номер-issue>-кратко`, например `research/5-fz152-definition`, `exp/9-short-name`, `docs/7-sources-review`.
- PR закрывает issue (`Closes #12`) и проходит чек-лист из шаблона.
- Squash merge. Ревью — в течение 24 часов.

## Знания
| Что произошло | Куда записать |
|---|---|
| Прочитал статью / нашёл инструмент | `docs/research/sources.md` (строка в таблице), подробно — `docs/research/notes/` |
| Приняли решение, которое дорого менять | `docs/decisions/NNNN-*.md` (ADR) |
| Нашли что-то неочевидное, включая тупики | `docs/insights/YYYY-MM-DD-*.md` |
| Провели эксперимент | `docs/experiments/YYYY-MM-DD-*.md` |
| Встреча команды или с ментором | `docs/meetings/YYYY-MM-DD.md` |
| Возник вопрос без ответа | `docs/project/open-questions.md` |

Правило: **инсайт записывается в тот же день**, 5–15 строк. Лучше короткая заметка, чем никакой.

## Данные
- Реальные ПДн запрещены (ADR-0002). Только синтетика.
- Данные не коммитятся в git. Версии датасета — на Hugging Face (приватный датасет) с тегами `v0.1`, `v0.2`…
- Любое изменение разметки — через PR в `docs/data/annotation-guidelines.md` + новая версия датасета.

## Ритм команды
- **Еженедельный синк — 1 раз в неделю, 30–45 минут**: что сделал, что дальше, где блок, один инсайт; обновляем доску.
- **Подготовка к ментору — за 2–3 дня до каждой встречи с ментором**: собираем результаты, вопросы к ментору (`docs/project/open-questions.md`), перед чекпоинтами — прогон презентации.
- Итоги обеих встреч — в `docs/meetings/`.
- **Ротация «хранителя базы знаний»** раз в 2 недели: чистит дубли, обновляет `docs/index.md`.

## Общение по задачам
- **Задача висит больше 3 дней** (нет движения или непонятно, как продолжить) → пишешь в общий чат или в общую Google-таблицу статусов. Не ждём синка.
- **Не успеваешь со своей задачей** → сообщаешь лиду лично или в отдельную Google-таблицу, доступную только тебе и лиду. Там фиксируем: задача, что мешает, новый срок или нужна помощь.
- Лид по итогам перераспределяет задачи или сдвигает сроки и отмечает это на доске.

## Определение «готово» (Definition of Done)
- [ ] Код/документ смёржен в `main`
- [ ] Числа воспроизводятся командой из репо
- [ ] Обновлена документация / ADR / инсайт (или явно «не требуется»)
- [ ] Нет реальных ПДн и секретов
