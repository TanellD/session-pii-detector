# Правила для AI-агентов (Claude Code, Cursor, Codex и др.)

Этот файл читают агенты. `CLAUDE.md` ссылается сюда.

## Контекст
- Проект: сессионная детекция ПДн (ФЗ-152). Постановка — `docs/project/brief.md`.
- Проект на стадии исследования. Не выдавай предположения за решения; выводы подкрепляй источниками.
- Перед работой над задачей прочитай `docs/index.md`, относящиеся к ней страницы `docs/kb/` и `docs/decisions/`.
- Термины — `docs/project/glossary.md`. Используй их, не изобретай синонимы.

## Жёсткие запреты
1. **Никаких реальных ПДн в репозитории.** Ни в данных, ни в тестах, ни в примерах, ни в логах. Только синтетика или явно обезличенные примеры (см. ADR-0002).
2. Не коммить данные в git: всё из `data/` хранится вне git (см. `data/README.md`).
3. Не меняй принятые ADR в `docs/decisions/`. Если решение надо пересмотреть, предложи новый ADR со статусом `proposed`.
4. Не правь `docs/data/annotation-guidelines.md` молча: изменение разметки меняет датасет, это решение команды.
5. Секреты и токены (HF, OpenAI и т.п.) только в `.env`, который не коммитится.

## Что делать всегда
- Нашёл что-то неочевидное (причину ошибки, результат замера, тупиковый путь) → создай заметку `docs/insights/YYYY-MM-DD-кратко.md` по шаблону `_template.md`.
- Провёл эксперимент → заполни `docs/experiments/` по шаблону, укажи версию данных, конфиг и коммит.
- Любое число в отчёте или презентации должно воспроизводиться командой из репо. Укажи команду рядом с числом.
- Метрики считаются только так, как описано в `docs/kb/metrics.md` (когда они определены).
- Изменения кода и документации — в одном PR.

## Стиль
- Документация на русском, идентификаторы в коде на английском.
- Коммиты: Conventional Commits (`feat:`, `fix:`, `docs:`, `data:`, `exp:`, `chore:`).
- Не указывай AI-агентов соавторами: никаких `Co-Authored-By:` с агентом в коммитах и подписей вида «Generated with …» в PR и issues. Автор — человек, который открывает PR.
