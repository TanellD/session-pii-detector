# API Одноклассников: возможность корпуса ФИ и получение доступа

- Дата проверки: 2026-11-17.
- Статус: документация проверена; приложения и ключей ОК пока нет. Подготовлен ограниченный проверочный скрипт. Фактический доступ к профилям и выгрузка миллиона записей не подтверждены.
- Цель: дополнительный исследовательский источник совместных написаний фамилии и имени. Это не оценка национальных частот и не учебный датасет.

## Что доступно по документации

| Этап | Метод и источник | Что установлено |
|---|---|---|
| Получить участников группы | [group.getMembers](https://apiok.ru/dev/methods/rest/group/group.getMembers) | Требует сессию, `GROUP_CONTENT` и `VALUABLE_ACCESS`. Параметр группы `uid`, пагинация через `anchor`, размер через `count`. Ответ содержит `members[].userId`, `has_more`, `anchor`, `membersHidden`, `totalCount`. Подтверждённый универсальный максимум `count` на странице не указан. |
| Получить имена по ID | [users.getInfo](https://apiok.ru/dev/methods/rest/users/users.getInfo) | Требует `VALUABLE_ACCESS`, для внешних приложений сессию. До 100 ID в `uids` за вызов. В проверенной схеме есть `first_name`, `last_name`, `name`, `gender`, `private`; отдельное отчество не найдено. |
| Альтернативный список | [communities.getMembers](https://apiok.ru/dev/methods/rest/communities/communities.getMembers) | Есть поля профиля и пагинация, но требуются годы вступления/выхода. Эквивалентность произвольной публичной группе не подтверждена; основной маршрут на этом методе не строим. |

Поле `name` не принимаем за три отдельных подтверждённых компонента ФИО. Отчество не выводим из имени или пола. Если оно свободным текстом вписано в имя, нужен отдельный проверенный разбор; миллион таких случаев не предполагаем.

Миллион записей ФИ технически можно пытаться собрать только после выдачи прав, успешного пилота и выбора достаточно большой доступной группы либо нескольких групп. Наличие методов не доказывает полный обход конкретной группы. Даже открытые аккаунты не равны уникальным жителям России. Одинаковые ФИ разных ID сохраняются, повторные ID удаляются, корпуса ОК/VK не объединяются как одна популяционная выборка.

## Как получить приложение и права

Уточнение после проверки [актуальной страницы OAuth ОК](https://apiok.ru/ext/oauth/): для входа пользователей используется VK ID SDK и OAuth 2.1. [Официальный SDK](https://github.com/VKCOM/vkid-web-sdk) показывает один `APP_ID` с провайдерами VK, OK и Mail (`VKID.OAuthName.OK`). Для входа через ОК можно использовать существующее приложение VK ID; необходимость отдельного нового приложения для одной лишь авторизации не установлена. Это исправляет прежнюю слишком общую рекомендацию сначала регистрировать новое приложение. Получение REST-прав ОК и совместимость выданного VK ID токена с `group.getMembers`/`users.getInfo` из этих страниц не следуют и требуют отдельной проверки. Существующий VK ID `client_id` не подставляем автоматически вместо публичного ключа приложения REST API ОК.

1. Открыть [официальную инструкцию создания](https://apiok.ru/dev/app/create). В её начале указано, что новые игры и пользовательские мини-приложения создаются через VK Mini Apps. Ниже остаются прежние шаги через игры ОК. Не считаем старую процедуру гарантированно действующей и не предполагаем, что один ID VK автоматически заменит ключи REST API ОК. Для нашего внешнего исследовательского приложения нужно уточнить текущий маршрут регистрации.
2. У поддержки ОК запросить способ создания внешнего OAuth-приложения с доступом к REST API; после получения ID запросить права `VALUABLE_ACCESS` и `GROUP_CONTENT`, описав задачу и предполагаемый объём. [Страница прав](https://apiok.ru/ext/oauth/permissions) указывает адрес `api-support@ok.ru` и необходимость передать ID и обоснование. Почту агент не отправлял.
3. После одобрения получить публичный ключ, секрет приложения и пользовательский access token. Инструкция создания описывает получение токена владельца в настройках OAuth; после выдачи новых прав ранее полученный токен требуется перевыпустить. Текущую доступность этого интерфейса проверяет владелец приложения.
4. Выбрать открытую группу, записать её числовой ID и начать с пилота. Возможность доступа к чужой группе, полнота выдачи и поддерживаемый размер страницы проверяются фактически, не предполагаются по наличию прав.

Черновик обращения, который пользователь может отправить самостоятельно:

> Тема: Доступ к REST API ОК для исследования совместных частот имён
>
> Здравствуйте. Исследуем статистическую зависимость написаний фамилии и имени для правил разметки персональных данных. Приложение пока не создано. Подскажите актуальный способ регистрации внешнего OAuth-приложения с ключами для REST API ОК после перехода создания мини-приложений в VK Mini Apps.
>
> Нужны group.getMembers и users.getInfo, права VALUABLE_ACCESS и GROUP_CONTENT. Хотим начать с небольшого пилота, затем при разрешённом доступе собрать до миллиона открытых профилей участников доступных групп. Минимальные поля: ID, имя, фамилия, пол и признак приватности. Закрытые профили не включаем. Контакты не запрашиваем, рассылок и публикаций не будет. Исходные записи хранятся локально вне Git; отчёты содержат агрегаты без имён и ID.
>
> Допустим ли такой сценарий, какие условия, квоты и ограничения обхода групп действуют? Есть ли отдельное поле отчества? После регистрации предоставим ID приложения для запроса прав.

## Локальная настройка и проба

Добавить значения только в локальный `.env` (пустые имена уже есть в `.env.example`):

```dotenv
OK_APPLICATION_ID=
OK_APPLICATION_KEY=
OK_APPLICATION_SECRET_KEY=
OK_ACCESS_TOKEN=
OK_GROUP_ID=
```

`OK_APPLICATION_ID` понадобится для регистрации и поддержки; в REST-подписи используется публичный `OK_APPLICATION_KEY`. Секреты не пересылать в чат. Параметры подписываются по [официальному алгоритму](https://apiok.ru/dev/methods/): ключ сессии вычисляется из токена и секрета приложения; отсортированные параметры подписываются MD5, access token исключается из подписываемого списка. Токен передаётся в POST-теле, редиректы запрещены, текст исходных ошибок не выводится.

```powershell
# Не массовая выгрузка: одна страница и до десяти профилей.
python -X utf8 tools/probe_ok_name_access.py
# Или указать группу явно:
python -X utf8 tools/probe_ok_name_access.py --group <числовой_ID_группы>
# Синтетические проверки, без сети:
python -X utf8 -m unittest discover -s tests -p 'test_ok_access_probe.py'
```

Пилот сохраняет только безопасную сводку `data/private/name-dependence/ok-access-probe.json`, без имён, ID и секретов. Скрытый список участников останавливает пилот. Полученные строки профилей не сохраняются. Без ключей команда возвращает `configuration_required` и не выполняет сетевых запросов. Этот путь выполнен; фактический сетевой пилот ещё не выполнялся.

## Масштаб, лимиты и следующий шаг

Только для получения миллиона профилей методом `users.getInfo` потребуется не менее 10000 вызовов при полных пакетах; запросы списка участников добавляются отдельно. Расчёт: `python -c "import math; print(math.ceil(1000000 / 100))"`. Это нижняя оценка числа запросов, не прогноз времени и не гарантия миллиона пригодных записей. После фильтрации и дедупликации останется меньше.

[Документация лимитов](https://apiok.ru/dev/limits) не обещает неограниченный сбор: индивидуальные ограничения возможны, при FLOOD_BLOCKED предусмотрен `wait_millis`. По [справочнику ошибок](https://apiok.ru/dev/errors) у ОК код 8 означает FLOOD_BLOCKED, а код 9 — IP_BLOCKED. Переносить обработку кодов VK по номерам нельзя. Пилот останавливается на ошибке и сохраняет только код и `wait_millis`, без автоматических повторов.

После успешного пилота: подтвердить курсор и `has_more`, поведение закрытых аккаунтов и фактический размер страницы; затем реализовать отдельный коллектор с кешем страниц списка и пакетов профилей, сохранением курсора после успешных записей и дедупликацией ID. До получения прав массовый коллектор и миллион ФИО не объявляются работающими.
