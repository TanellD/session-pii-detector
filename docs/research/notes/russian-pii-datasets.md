## Что можно использовать как train и validation

Все готовые источники сначала проходят проверку русского языка, происхождения,
лицензии, качества разметки и пересечений. Набор может быть полезен для train
извлечения признаков и одновременно непригоден как независимый validation.
Наличие русских текстов не подтверждает соответствие всех меток ФЗ-152.

Готовый допущенный сессионный train/validation с моментом по нашей политике
этим обзором не получен. Правило «использовать всё надлежащего качества» означает
проверить каждого кандидата, а не выбрать заранее один набор.

## Минимальный протокол допуска

1. Зафиксировать revision/хеш, конфигурацию, лицензию данных и происхождение каждого
   принятого среза. Карточка по ссылке `main` может измениться после этого обзора.
2. Оставить русский текст. Проверить смешанные тексты и русские записи с документами
   другой страны; их формат не считать примером документа РФ.
3. Подтвердить полностью синтетическое происхождение по ADR-0002. Замена только
   явных идентификаторов в реальном логе не доказывает синтетичность оставшегося профиля.
4. Согласовать отображение исходных меток на типы фактов проекта. Не превращать
   каждую ORG/LOC/DATE или каждое имя автоматически в положительную сессию.
5. Проверить spans на исходном тексте, пропущенные сущности, отрицательные примеры,
   принадлежность разным людям и повтор. Сохранить замечания без реальных ПДн.
6. До разделения удалить дубликаты; связанные шаблоны, профили, их перефразировки
   и производные примеры держать в одной выборке. Проверить происхождение базовой модели:
   «внешний benchmark» может уже входить в её обучение.
7. Для validation независимо проверить разметку. Для сессионной оценки дополнительно
   разметить людей, факты и момент по принятой политике. Иначе измеряется только NER.
8. Опубликовать результат аудита, команды, версии, принятые/отклонённые срезы и
   ограничения в карточке будущего датасета. Пока этот этап не выполнен.

## Диалоги и агентные сессии

В исследованном пуле не подтверждён открытый русский агентный корпус, который
одновременно синтетический и содержит нужную разметку сессионного момента.
Не делаем из этого вывода о полном отсутствии русских агентных данных.
По актуальному уточнению #13 агентные логи не обязательны для первого чатового MVP.
Их структуру можно создать синтетически после согласования источников сообщений
и правил для кода, цитат и результатов инструментов.

Для возникновения ПДн отдельно рассмотрена [статья P-ONSET](dialogue-onset-data.md).
Её иностранные примеры не входят в русские train/validation.
