# Корпуса сессий для последовательной детекции ПДн

Проверено по первичным карточкам, публикациям и репозиториям 2026-11-19. Задача — пользовательские сообщения, полные сущности нашей таксономии, принадлежность человеку по доступному префиксу и первый алерт. Среди проверенных источников не найден готовый эталон со всеми этими условиями и нашей политикой. Ни один новый корпус в этом проходе не загружался и не допускался автоматически в train/test.

## Основные кандидаты

| Источник | Язык и происхождение | Подтверждённая структура | Применимость к нашей задаче |
|---|---|---|---|
| [CONFIDE](https://github.com/glebis/confide) | Есть русский; собственные терапевтические/коучинговые сессии объявлены вымышленными | Транскрипты диалогов, PII-спаны, синтетические профили | Ближайший уже проверенный русский источник. Отбирать клиентские реплики, заново размечать Ф/И/О и владельцев, исключать неподдерживаемые значения. Терапия не представляет весь чат поддержки. |
| [DialogPII](https://zenodo.org/records/20863452), [публикация](https://arxiv.org/abs/2606.30312) | Синтетические диалоги, созданные с LLM и ручной редактурой; русского в опубликованном перечне языков нет | Диалоги и ASR-транскрипты, JSON со спанами, отдельные guidelines; поддержка, страхование, медицинские и другие сценарии | Очень близок к разговорному извлечению PII. Нужны русская локализация и новая разметка принадлежности/первого алерта. Нельзя считать перевод сохранением исходных offsets. |
| [HiCUPID, карточка](https://huggingface.co/datasets/12kimih/HiCUPID), [публикация](https://arxiv.org/html/2506.01262v1) | Английский; GPT-4o-generated synthetic по статье | `user_id`, `dialogue_id`, `turn_id`, отдельные `user` и `assistant`; profile/persona/schedule metadata | Хорош для постепенного раскрытия свойств пользователя, длинной истории, возраста/пола/профессии. Это персонализация и QA, не готовая PII-разметка. Profile и schedule диалоги в карточке одношаговые; для сессионного накопления выбирать persona-диалоги. |
| [ABCD](https://github.com/asappresearch/abcd), [публикация](https://arxiv.org/html/2104.00783) | Английские человеческие ролевые диалоги клиент–сотрудник | Поддержка, возврат, доставка, восстановление доступа, действия и значения | Наиболее близкий источник бытовых сценариев поддержки: запрос имени, почты, контактных/учётных сведений. Не считать весь корпус автоматически доказанно свободным от реальных ПДн. До прямого использования нужен аудит; для новой синтетики можно использовать структуру сценария с полностью вымышленными значениями. |
| [Multi2WOZ](https://github.com/chiachienhung/Multi2WOZ), [публикация NAACL](https://aclanthology.org/2022.naacl-main.270/) | Включает русский перевод MultiWOZ; это ролевые task-oriented диалоги, не генерация для PII | Целевые диалоги со состоянием/слотами, русские dev/test-переводы исходного корпуса | Хорошая русская основа для бронирований и негативных примеров. Контакт/адрес заведения не равен личному контакту/проживанию; нужна проверка конкретного содержимого. Наших спанов и алертов нет. |
| [Schema-Guided Dialogue](https://github.com/google-research-datasets/dstc8-schema-guided-dialogue) | Английский; симулятор диалогов и краудсорсинговая переформулировка | Явные `USER`/`SYSTEM`, slots, frames, последовательность состояния | Резервный источник сценариев, поправок и сервисных контактов; адаптировать на русский и отдельно размечать PII. DST-слот не является автоматически личным атрибутом. |

Применимость в последней колонке — наша оценка, а не заявление авторов о пригодности для сессионной детекции по нашей политике. У новых источников проверены описания, а не полнота, качество, состав владельцев и контрольные суммы всех файлов.

## Лицензии и степень допуска

- CONFIDE: собственные синтетические данные/документация CC-BY-4.0, код MIT. Другие внешние срезы не наследуют автоматически эту лицензию. Для проекта уже есть [аудит фиксированной ревизии](../../experiments/2026-11-19-confide-annotation-audit.md); нового импорта здесь нет.
- HiCUPID: [карточка данных](https://huggingface.co/datasets/12kimih/HiCUPID/raw/main/README.md) явно указывает Apache-2.0, английский язык и раздельные пользовательские/ассистентские поля. Не путать лицензию самой статьи с лицензией данных.
- ABCD: [репозиторий содержит код и данные](https://raw.githubusercontent.com/asappresearch/abcd/master/README.md), [LICENSE](https://raw.githubusercontent.com/asappresearch/abcd/master/LICENSE) — MIT. Это не доказательство вымышленности каждого свободного текстового поля.
- SGD: [README](https://raw.githubusercontent.com/google-research-datasets/dstc8-schema-guided-dialogue/master/README.md) явно указывает CC-BY-SA-4.0 для SGD/SGD-X. Декларация лицензии не заменяет проверку происхождения персональных значений.
- DialogPII: страница Zenodo доступна, но текстовое представление раздела License не показало название лицензии; обращение к metadata API через браузерный инструмент не удалось. Перед импортом подтвердить лицензию в метаданных/архиве, не подставлять предполагаемую.
- Multi2WOZ: README подтверждает русский и ссылку на файлы в Google Drive. Условия именно этих переводных файлов в этом проходе не подтверждены; не переносить автоматически лицензию исходного MultiWOZ или статьи.

В соответствии с ADR-0002 в наш датасет допускается только синтетика. Открытость корпуса и наличие лицензии не доказывают, что все его идентификаторы вымышлены. До допуска новых материалов фиксируются ревизия, состав файлов, происхождение, лицензия и точный способ адаптации.

## Что придётся сделать в любом случае

- Сохранить только пользовательские реплики с исходным порядком и отдельным соответствием исходной сессии. В человеческом диалоге явно определить, какая роль соответствует пользователю; не назначать её по угадываемому чередованию.
- Переоценить принадлежность без удалённых ответов собеседника. Короткие ответы могут потерять контекст и стать `null`; скрытый ответ нельзя использовать как доказательство.
- Разбить PERSON на наши Ф/И/О только там, где структура действительно определена, сопоставить другие классы. Выделять только цифровые телефон/СНИЛС/возраст, как принято в MVP.
- При переводе и замене персональных значений пересчитать все границы и повторно проверить полный адрес/полный контакт. Англоязычное имя без отчества не превращать автоматически в российское ФИО.
- Разметить по префиксам без будущего, не переопределяя прежние `null`. Исходный профиль/QA из metadata использовать только для проверки, не передавать разметчику раньше явного раскрытия в тексте.
- Рассчитать алерты нашей политикой. Исходные NER-метки, DST-состояния и персонализированные QA не являются готовыми метками `t_gold`.
- Разделять выборку по профилю/пользователю и семейству исходных сценариев, а не только по отдельным репликам. Не смешивать dev/test-переводы одной исходной сессии с её обучающей версией при проверке обобщения.

## Приоритет

Для быстрого русского пилота — собственный синтетический срез CONFIDE, уже прошедший первичный аудит в проекте. Для расширения разговорных PII-сценариев — сначала проверить лицензию и небольшой срез DialogPII. Для русских сценариев бронирований и сложных отрицательных примеров — аудит Multi2WOZ. Для близкой к поддержке новой синтетики — шаблоны ABCD с заменой всех персональных значений. HiCUPID полезен отдельно для жёлтых признаков и длинного контекста, но не заменяет корпус прямых идентификаторов.
