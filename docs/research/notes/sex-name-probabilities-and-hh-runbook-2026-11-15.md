# Пол, подтверждение частот ФИО и сбор статистики hh

> Проверка выполнена 2026-11-16: [происхождение russiannames, уточнение коллизий нормализации, исследования и численное сравнение](full-name-frequency-validation-2026-11-16.md). Подтверждён реестровый тип источников; репрезентативность населения и совместные частоты прежних словарей пока не установлены.

- Дата: 2026-11-15.
- Назначение: основания правил разметки, не метрики детектора.
- Уточнение лида: пол остаётся входным атрибутом калькулятора; возраст отдельным критерием не используется.

## Как сохранить пол без повторного учёта

Маргинальные вероятности можно хранить отдельно, но независимость не появляется из-за разделения таблиц. Для пола `S`, признака имени `X` и известной территории `G` точны оба представления:

`P(X,S | G) = P(S | G) * P(X | S,G)`

`P(X,S | G) = P(X | G) * P(S | X,G)`.

Первое удобно, когда есть частоты имён среди соответствующего пола; второе — когда известна общая частота имени и состав его носителей по полу. Нельзя смешивать `P(X|G)` с `P(S|G)` как будто имя независимо от пола. Если по выбранному справочнику все носители конкретной формы имени имеют указанный пол, условная поправка `P(S|X,G)` равна единице. Повторно сужать круг тем же полом не нужно. Метка рода слова в библиотеке сама по себе не является измеренной долей пола носителей.

Если пол неизвестен, усреднить по нему: `P(X|G) = sum_s P(s|G) * P(X|s,G)`. Это позволяет использовать и маргинальные, и условные таблицы. Национальная частота относится к населению всех возрастов; привязка человека к возрасту не нужна. Региональные условия применяются только при наличии подходящих данных; нельзя выдавать общую частоту за регионально измеренную.

Для полного ФИО точная цепочка:

`P(F,I,O,S|G) = P(S|G) * P(F|S,G) * P(I|F,S,G) * P(O|F,I,S,G)`.

Если совместных частот нет, произведение `P(S|G)*P(F|S,G)*P(I|S,G)*P(O|S,G)` — приближение условной независимости частей при известном поле/регионе. Оно устраняет один источник двойного учёта, но не доказывает независимость частей ФИО. Произвольно «сделать независимыми» эмпирические частоты нельзя, сохранив смысл числа совместимых людей.

## Что означает подтвердить частоты ФИО

Нужно различать проверку счётчиков источника и проверку их применимости ко всему населению. [Агрегаты частей](https://github.com/datacoon/russiannames) и [схема счётчика](https://data.apicrafter.ru/tables/russiannames/names/schema) уже найдены; это ещё не подтверждение национальных частот полного ФИО.

Порядок проверки:

1. Получить описание происхождения выборки: кто включён, какие даты, население/граждане/работники/руководители, какие территории, кто исключён. Проверить условия использования. Если этих сведений нет в публикации, вопрос адресуется держателю данных; письмо без поручения пользователя не отправляется.
2. Получить знаменатель и правила дедупликации: `count` означает уникальных людей, упоминания, записи или взвешенные наблюдения? Имеются ли пропуски и полный хвост редких значений? Суммы разных коллекций не считать автоматически одним населением.
3. Проверить нормализацию: регистр, `ё/е`, дефисы, варианты записи, склонение, инициалы, мужские/женские формы фамилий. Фамильная основа и точная форма — разные определения события; выбрать одно и согласовать с учётом пола.
4. Проверить арифметику агрегатов: неотрицательные счётчики, уникальность ключей, согласованность общих итогов и условных таблиц. Невстреченное значение не означает отсутствие носителей.
5. Для полного ФИО получить совместные агрегаты троек либо таблицы кратности совпадений от держателя репрезентативной выборки. Из трёх отдельных распределений тройки не восстанавливаются однозначно. Исследование [Zhagorina et al.](https://arxiv.org/abs/1811.05361) описывает подходы, но его реестровая выборка не становится общепопуляционной автоматически.
6. Сопоставить частоты с независимым источником сравнимого охвата. Согласие частых значений полезно, но не подтверждает хвост редких ФИО, который особенно влияет на правило малого круга. При доступности только выборки оценить смещение и обоснованность переноса; простое увеличение всех счётчиков до численности России его не устраняет.

Обмениваться только агрегатами и описанием методики; индивидуальные ФИО и записи людей в репозиторий не переносить. Пока происхождение и охват не подтверждены, статус результата — «частота в источнике» либо «приближение для населения с допущениями». Для разметки важно сохранять этот статус рядом с оценкой.

## hh: запуск одной командой

**Исторический вариант:** по последующему решению лида профессиональные частоты берём из [данных Росстата о занятых](rosstat-occupation-reference-2026-11-15.md). Для текущего направления запускать сборщик hh не требуется.

Уточнение пользователя: поддержка API для соискателей прекращена 15 декабря 2025 года. Сборщик ниже — проверка доступа и инструмент для разрешённого источником доступа, а не подтверждённый общедоступный способ получить статистику. Токен соискателя не предлагается как исправление отказа. Прекращение этого вида доступа само по себе не доказывает отключение всех методов для приложений и работодателей; применимость доступа к нашему исследованию нужно установить отдельно. В текущей среде поиск уже вернул HTTP 403, причина отказа из одного кода не определяется.

Из корня репозитория, Python без дополнительных пакетов:

```powershell
python -X utf8 tools/collect_hh_occupation_statistics.py
```

Скрипт делает агрегированный запрос для России с `clusters=true&per_page=0`, извлекает группу `professional_role` и выводит блок `HH_REPORT_BEGIN` … `HH_REPORT_END`. Именно этот блок нужно прислать в чат. Копия результата записывается в `data/reference/hh-occupation-statistics.json`, вне git. Никакие тексты вакансий, контакты, адреса, названия работодателей и идентификаторы вакансий в результат не включаются.

Счётчики кластеров отражают найденные вакансии всего запроса, а не первую страницу. Если группа ролей отсутствует, возвращается `role_cluster_missing`, а не фиктивное распределение. Доли ролей маргинальные: могут пересекаться и не обязаны суммироваться в единицу. Остаток `other` из такой суммы не вычисляется. Число ролей и наличие группы зависят от ответа API, заранее полнота не обещается.

Дополнительный разбор страниц с дедупликацией ID в памяти:

```powershell
python -X utf8 tools/collect_hh_occupation_statistics.py --sample-pages 20
```

В этом режиме вес вакансии делится поровну между её уникальными ролями, без роли — попадает в `other`. Результат этого способа и кластерные маргинальные доли хранятся раздельно. Выборка состоит из последних публикаций и ограничена глубиной поиска API; `truncated` показывает неполный охват относительно начального `found`. Это не случайная выборка работников. Дедупликация ID не устраняет повторные объявления под разными ID. Если сбор прерван, сохраняются частичные агрегаты и причина.

[Официальная документация hh](https://api.hh.ru/openapi/redoc#tag/Poisk-vakansij/operation/get-vacancies) описывает ограничения поиска и возможность капчи без авторизации. Наличие метода в документации не подтверждает доступность для нашего приложения. Скрипт не обходит ограничения: на отказе останавливается, при временных ошибках выполняет ограниченные повторы. Только если разрешённый доступ уже подтверждён, соответствующий токен можно передать через `HH_API_TOKEN` в локальном `.env`; собственное имя приложения с контактами — через `HH_USER_AGENT`. Эти значения не выводятся. Токен не нужен в команде или присылаемом логе. Получение токена само по себе не гарантирует доступа.

Код завершения при полном успехе — `0`, при отказе/неполном результате — `2`; диагностический блок печатается и при отказе. Отсутствие доступа не означает нулевое число вакансий. Лог позволит выбрать следующий способ получения данных без повторного угадывания причины.

```powershell

```
