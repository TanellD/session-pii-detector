# Покрытие классов: что действительно проверено в #12

Дата: 02.11.2026. Автор: `Kopylov-Andrey`. Основание — задача #10 и предложения
[PR #16](https://github.com/TanellD/session-pii-detector/pull/16), снимок
`68b090e5db4664e3802e09a17976f45e1d7601bb`. PR открыт; это не утверждённая политика.
Группировка ниже сохраняет различие четырнадцати групп признаков и отдельного
специального флага из предложения. Организация/должность и возраст/дата рождения
проверяются раздельными extraction labels внутри соответствующей группы.

Набор `task12-smoke-v2`: 30 синтетических фраз. Полные результаты и ID случаев —
в [автоматическом отчёте](../../experiments/2026-11-02-task12-gliner-cpu-v2-auto.md).
Получение всех чисел таблицы:

```powershell
.\.venv-task12-locked\Scripts\python.exe -m benchmarks.pii_smoke.report --input runs/task12-smoke-v2
```

TP/FP/FN ниже относятся к combined и точным границам **указанных случаев**, не ко
всей распространённости класса и не к сессионному качеству. Наличие одного TP
не означает, что класс готов. Все английские labels закреплены в config; порог 0.5.

| Группа проекта | Метка / следующий адаптер | Проверенный ID | TP/FP/FN по случаю | Что подтверждено и что нет |
|---|---|---|---|---|
| ФИО полностью | `person → PERSON`; далее нужен `FULL_NAME` | full_name | 1/0/0 | Три компонента извлечены одним span; отдельная классификация FULL_NAME не реализована |
| Части ФИО | `person → PERSON`; далее FIRST_NAME/LAST_NAME/PATRONYMIC | first_name; surname; patronymic | 0/1/1; 1/0/0; 1/0/0 | Имя ошибочно CITY; фамилия и отчество — PERSON. Разбор частей не доказан |
| Телефон | `phone number → PHONE` + regex | phone | 1/1/0 | Правильный номер найден; GLiNER также дал ложный PHONE на словах |
| Email | `email → EMAIL` + regex | email; code | 1/0/0; 1/0/0 | Найдены обычный адрес и адрес в JSON; принадлежность/истинность не оценивались |
| Точный адрес | `address → ADDRESS` | address | 1/0/0 | Один короткий синтетический адрес; полнота разных форматов не проверена |

| Возраст / дата рождения | `age → AGE`, `date of birth → DATE_OF_BIRTH` | age; birth_date | 1/0/0; 1/0/0 | Проверены два прямых упоминания; пересчёт возраста и нормализация не реализованы |

| Паспорт | regex `PASSPORT` | passport | 1/0/0 | Контекст + форма; выдача номера не подтверждается |
| СНИЛС | regex + checksum `SNILS` | snils | 1/0/0 | Формат и checksum диагностического номера; отрицательный checksum отдельно проверен |
| ИНН | regex + checksum `INN` | inn | 1/1/0 | Верный формат, но тот же span также PHONE; разрешение межтиповых конфликтов — следующий слой |
| Банковская карта | regex + Luhn `CARD` | card | 1/0/0 | Диагностическая последовательность, не реальная карта; Luhn не подтверждает выпуск |
| Специальный флаг | семь labels → `SPECIAL_CATEGORY` | health; religion; politics; nationality; philosophy; intimacy; conviction | 5/0/2 по типу в совокупности | Первые пять упоминаний найдены; последние два пропущены. Ложные PERSON в этих фразах учтены отдельно в отчёте |

Семь labels специального флага: `health condition`, `religion`, `political view`,
`nationality`, `philosophical belief`, `intimate life`, `criminal conviction`.
Их объединение — протокол smoke-проверки, не утверждение правовой классификации.

`two_people` проверяет извлечение нескольких упоминаний, а `correction` — извлечение
обоих упоминаний фамилии. Они **не** доказывают линковку людей, отзыв факта или
накопление риска. Эти возможности только иллюстрируются в draft API.

Новый набор добавлен после аудита покрытия, поэтому не является независимой
оценкой обобщения модели. Старый v1 сохранён. Следующий этап — адаптер частей ФИО,
межтиповые конфликты и независимые примеры после согласования #10/#11, с отдельной
проверкой детекторов. Вывод #12: ограничения покрытия измерены, готовность MVP нет.
