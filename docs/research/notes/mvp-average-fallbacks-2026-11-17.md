# Средние для неизвестной численности: пункты, улицы и дома

Дата: 2026-11-17. Пользователь разрешил среднее/медиану по типу населённого пункта и подтвердил усреднение для улиц и домов. Метод выбран, новые национальные коэффициенты пока не получены и не включены в расчёт.

Обновление 2026-11-18: [полный переписной набор скачан, средние по типам и регионам рассчитаны; подготовлено предложение для МКД](../../experiments/2026-11-18-population-size-means.md). Указанные ниже ограничения старой федеральной таблицы остаются верными, но получение средних населённых пунктов больше не заблокировано отсутствием полного файла. Коэффициенты ещё не включены в основной оценщик.

## Что оцениваем

Для случая проживания человека основной вариант — среднее с весом численности: `sum(n_i²) / sum(n_i)`, где `n_i` — число жителей объекта того же типа. Это размер объекта для случайного жителя данной группы, а не обычного случайного объекта. Обычное среднее `sum(n_i)/k` и медиана размеров объектов сохраняются в подготовленной таблице для сравнения. Все варианты — приближения; ни один автоматически не является консервативной верхней границей.

Сам факт отсутствия конкретного объекта в справочнике может быть неслучайным. Среднее не исправляет это смещение автоматически: в отчёте сохраняется допущение переноса на неизвестный объект. Неизвестный конкретный населённый пункт и фраза «живёт в какой-то деревне России» — разные ситуации: последняя не сужает круг до жителей одной средней деревни.

Группы:

- Населённый пункт: отдельные типы город, ПГТ, село, деревня, посёлок, станица и другие подтверждённые типы. По возможности тот же регион; национальное среднее только при полном согласованном национальном покрытии.
- Улица: один геокодированный объект, известный город/тип населённого пункта, по возможности тип жилой застройки. Численность муниципалитета не равна населению улицы. Нужны жители улицы либо согласованные здания с жителями и привязкой к улице.
- Дом: жилое здание подходящего типа. Квартира, индивидуальный дом, многоквартирный дом и общежитие не смешиваются. Если есть число квартир и принятое среднее жителей квартиры, действует прежняя формула; неизвестное число квартир не заменяется одной квартирой.

Уточнение пользователя о средних для улицы не добавляет неполный адрес как новый спановый тип MVP. В текущем MVP адрес до дома считается полным; улица без дома не размечается как полный `address`. Уличный оценщик готовится отдельно для расширения и внутреннего разрешения географии.

## Что проверено в источниках

[Росстат, том 1 ВПН-2020](https://rosstat.gov.ru/vpn/2020/Tom1_Chislennost_i_razmeshchenie_naseleniya) описывает федеральную таблицу с сельскими пунктами только от установленного порога численности. Это не полный список малых сёл и деревень. Уже используемая таблица не годится для среднего/медианы всех деревень. Отсутствующий пункт нельзя автоматически считать малым. Порог и фактическое ограничение входа зафиксированы также в `tools/build_annotation_geography_reference.py`.

Найден [набор ИНИД «Населённые пункты России: численность населения и географические координаты»](https://data.rcsi.science/data-catalog/datasets/160/). Карточка заявляет поля типа пункта, региона, муниципалитета, ОКТМО и населения; происхождение — Росстат и региональные МИАЦ. В описании указаны неоднородные даты исходной численности. Сайт предлагает вход/регистрацию для доступа; CSV в этом проходе не получен. Это кандидат на проверку полноты и дат, не утверждённый текущий источник коэффициентов. Условия лицензии данных нужно учитывать отдельно от кода проекта.

Проверенные средние занятой квартиры, индивидуального дома и коммунальной квартиры и допущение заселённости многоквартирного дома описаны в [ранее принятых решениях](../../project/annotation-gap-resolution-2026-11-15.md). Они не дают среднее населения улицы либо каждого типа целого дома.

## Подготовленный расчёт

`tools/build_annotation_size_fallbacks.py` принимает согласованный JSON с полями `source_url`, `reference_date`, `unit`, `coverage_complete`, `national_coverage_complete`, `rows`. У строки: уникальный ID объекта, `object_type`, `region`, `population`. Вход содержит только один уровень объектов: без вложенных муниципальных итогов и повторов одного пункта. Единица `unit` — `settlement`, `street` либо `residential_building`.

Неполный заявленный охват, повторные ID и неверная численность отвергаются. Национальные группы не выводятся из регионального файла без явно заявленного полного национального покрытия. Программа не может доказать истинность декларации охвата: её проверяет исследователь по источнику.

```powershell
python -X utf8 tools/build_annotation_size_fallbacks.py --input data/external/verified-size-input.json --output data/reference/prepared-size-fallbacks.json
python -X utf8 -m unittest discover -s tests -p test_annotation_contract.py
```

Первая команда требует подготовленного входа; это контракт следующего импорта, не обещание наличия такого файла. Выход содержит обычное среднее, медиану, среднее с весом населения, число объектов и жителей, дату и хеш входа. Статус `approved_for_annotation=false`: механический расчёт не подтверждает покрытие.

Конфигурация `size_fallbacks` фиксирует выбранный метод и единицы. Пока нет проверенного справочника и подключения его к оценщику, калькулятор возвращает неизвестную численность вместо выдуманного среднего. Это оставшийся пробел **данных и интеграции**, а не невыбранное правило разметки. Для ФИО/пар с полным личным адресом он не блокирует качественный алерт.
