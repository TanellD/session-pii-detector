# Контракт упоминания ПДн

Статус: проект первой реализации адаптера. Версия контракта: `1.0.0`.

## Назначение

Контракт задаёт единый результат для regex и GLiNER и является входом для линковщика (#21).
Адаптер обрабатывает одно исходное сообщение и не хранит историю.

## Поля

| Поле | Тип | Смысл |
|---|---|---|
| `id` | строка | Устойчивый детерминированный идентификатор упоминания |
| `type` | строка | Проектный тип после маппинга `label → TYPE` |
| `text` | строка | Исходный фрагмент сообщения без нормализации |
| `start` | integer | Начальная граница в исходной строке, , Unicode code points (Python string indexing),
не байты и не UTF-16 |
| `end` | integer | Конечная граница, исключённая граница span. Эмодзи/суррогатные пары в тексте не должны сдвигать границы. |
| `confidence` | number или null | Исходный score либо отсутствие score |
| `confidence_kind` | enum | `model_score` для GLiNER, `none` для regex |
| `source` | enum | `regex` или `gliner` |
| `detector_version` | строка | Модель + ревизия или SHA/версия правил |

## Семантика уверенности

- У GLiNER `confidence` — score пороговой модели. Это не вероятность правильности,
  не calibrated probability и не вероятность принадлежности человеку.
- У regex `confidence = null`, `confidence_kind = none`. Фиксированная уверенность
  не задаётся, чтобы не выдавать regex за вероятностную оценку.
- Наличие checksum/Luhn означает проверку формата, а не реальность или выдачу номера.
- При разборе `PERSON`-span на части ФИО (`FIRST_NAME`, `PATRONYMIC`, `LAST_NAME`)
`confidence` наследуется от исходного `PERSON`-span. Это score модели для целого
span, а не отдельная оценка каждой части. Линковщик не должен интерпретировать
одинаковый `confidence` у трёх частей как «все три одинаково уверены».

## Устойчивый ID

ID не является индексом элемента в списке. Он вычисляется детерминированно по
версии контракта, проектному типу, исходным границам, источнику и версию детектора:

`sha256("mention-contract-1.0.0" + ...).hexdigest()[:16]`

Повторный запуск на том же текстовом фрагменте и с той же версией дает тот же ID.
Если изменятся граница, тип, источник или detector_version, изменится и ID.

## Вне контракта

Контракт не назначает владельца атрибута, не делает юридический вывод,
не формирует сессионный алерт, не выполняет entity linking и не нормализует значения.
Адаптер не назначает `person_id`. Принадлежность упоминания человеку — #21.
`person_id=null` — валидное состояние, не ошибка.
Эти функции реализуются отдельно (#21, #24 и сессионным модулем).

## Версионирование

При несовместимом изменении полей или семантики повышается major-версия контракта.
Линковщик должен хранить используемую версию вместе с входными упоминаниями.

## Порядок упоминаний

Упоминания в результате упорядочены по `start`, затем `end`, затем `type`.
Порядок не семантический: для FULL_NAME «Лада Олеговна Макетова» упоминания идут
`FIRST_NAME → PATRONYMIC → LAST_NAME`, потому что так расположены токены, а не
потому что это конвенция ФИО. Линковщик не должен полагаться на порядок для
определения роли части имени.
