# Leaderboard ментора: классы и применимость к проекту

Дата разбора: 2026-11-05. Источник: `_drafts/leaderboard.html`, переданный ментором.
Это статический снимок бенчмарка извлечения, не статистика production-трафика
и не результат нашего эксперимента.

## Как проверено

Без выполнения JavaScript прочитаны lb-data и все встроенные блоки rep-*.
Кнопки отчётов используют встроенные данные и оболочку report-shell: отсутствие
рядом отдельных HTML-файлов не мешает прочитать отчёты из самого leaderboard.

SHA-256 источника:
`cfef700109b7e8753c43520f2e5d63383d5db530c9ee379b59bd6c384baf8e00`.

Все количества, списки классов, агрегированные счётчики и оценки из этой
заметки воспроизводятся командой из корня репозитория:

```powershell
python -X utf8 tools/summarize_mentor_leaderboard.py --output outputs/leaderboard-summary-2026-11-05.json
```

Скрипт экспортирует только метаданные и агрегаты. Тексты документов и значения
упоминаний не извлекаются в новые файлы. Прогоны моделей не повторялись.

## Что внутри

- 35 встроенных отчётов: 7 конфигураций моделей на 5 датасетах.
- Варианты текста: original, lowercase, uppercase, translit, homoglyphs.
- Метки во всех датасетах вместе: 35 типов; это объединение разных таксономий.
- Для оценки доступны strict, exact, partial, ent_type и результаты по классам.
- Страница ранжирует по F2 слабейшего датасета, не только среднему результату.
  Конкретная схема сопоставления и вариант текста влияют на цифры.
- В заголовке дата сборки — август 2026, метаданные прогонов тоже августовские.
  Это не обязательно текущее состояние моделей или production-конфигураций.

Конфигурации: dataclean-fast, dataclean-medium, dataclean-slow,
cloud-ru-guardrails, gliner-guard-omni, gliner2-privacy-filter-pii-multi,
openai-privacy-filter. Наличие названия в отчёте не означает, что все веса,
конфиги и закрытые данные доступны для самостоятельного воспроизведения.

## Сопоставление с нашим MVP

| Наш признак | Что есть в leaderboard | Что нельзя автоматически заключать |
|---|---|---|
| ФИО и части имени | NAME | Нет отдельной проверки FIRST_NAME, LAST_NAME, FULL_NAME, PATRONYMIC |
| Телефон, email, адрес | PHONE_NUMBER, EMAIL, ADDRESS | Качество извлечения не задаёт правило, когда сессия должна алертить |
| Паспорт, СНИЛС, ИНН, карта | PASSPORT_NUMBER, SNILS, INN, BANK_CARD_NUMBER | Тип INN сам по себе не подтверждает разделение ИНН физлица и организации |
| Возраст и дата рождения | AGE, DATE | DATE не равнозначна DATE_OF_BIRTH |
| Место работы | ORGANIZATION | Организация без атрибуции человеку ещё не означает его место работы |
| Город, должность, родство, пол | Отдельных соответствующих меток в объединении нет | Готовое покрытие этих классов не доказано |
| Особые категории | Отдельной нашей метки SPECIAL_CATEGORY в объединении нет | Отсутствует подтверждение покрытия нужных нам смысловых признаков |
| Принадлежность и накопление | Отчёты сравнивают спаны документов | Не представлены наши метрики линковки людей и первого момента срабатывания |

Не расширяем MVP на весь перечень: PASSWORD/TOKEN/AUTH_CODE относятся к секретам,
часть других типов — к реквизитам организаций и инфраструктуре. Таксономия
бенчмарка шире нашей задачи ПДн физлиц. Ментор уже рекомендовал компактный список.

## Что полезно для экспериментов

- Посмотреть не только общую F2, но и ошибки нужных классов, прежде всего
  NAME/ADDRESS/PHONE_NUMBER и документов.
- Учитывать объявленную поддержку меток. Coverage в leaderboard — покрытие
  таксономии конфигурацией, его нельзя подменять recall извлечения или нашим
  coverage_complete сессионного анализа.
- В снимке у GLiNER-конфигураций заявлено широкое покрытие типов; у других
  конфигураций есть unsupported_labels. Это сведения о настройке данных
  прогонов, не независимое доказательство устойчивого распознавания каждого типа.
- Перенять варианты проверки регистра, транслитерации и похожих символов,
  добавляя собственные синтетические случаи после фиксации основного набора.
- Сравнивать в пределах одной версии и схемы. Скорость ms/doc зависит от
  устройства, объёма документа и конфигурации; не переносить её напрямую
  в бюджет нашего CPU-сервиса.

## Чего материал не даёт

- Частот классов и распределения запросов в production. Количество gold-спанов
  показывает состав выбранного бенчмарка, а не реальную распространённость.
- Автоматического обоснования долей синтетики или весов скора: они требуют
  отдельного метода выбора и проверки.
- Готового эталона момента перехода сессии в ПДн. Наличие диалоговых доменов
  в документном бенчмарке не доказывает наличие размеченного момента.
- Доказательства линковки разных признаков одного человека, работы с третьими
  лицами, исправлениями, общими фактами и длительным состоянием.
- Разрешения переносить исходные примеры в наш датасет: происхождение и
  ограничения закрытых материалов здесь не установлены; для наших сценариев
  сохраняется ADR-0002 и генерация своей синтетики.

Следующий полезный вопрос ментору — есть ли спецификация меток и конфигураций
оценивания, которую можно использовать для совместимости адаптера. Запрашивать
вновь частоты трафика не требуется: их отсутствие прямо подтверждено.

Получение leaderboard закрывает ожидание обещанного артефакта. Остальные
исследовательские задачи этим не закрываются; issues на GitHub не менялись.
