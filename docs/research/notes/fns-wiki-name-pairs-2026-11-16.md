# ФНС и Википедия: фамилия и имя вместе, перенос на полное ФИО

- Дата: 2026-11-16.
- Статус: первый воспроизводимый расчёт на локальном кеше; не статистика всего населения.

## Файлы и команды

По прямому разрешению пользователя ФИО сохраняются только локально в игнорируемой Git папке `data/private/name-dependence/`. В Git, документацию, тесты и консольные логи персональные строки не включаются. ИНН использовался для дедупликации в памяти и не сохранён. Принятый ADR-0002 не изменён; область разрешения описана в [предложенном ADR](../../decisions/0003-local-name-research-cache-proposed.md).

```powershell
# Скачивание; при наличии кеша повторного скачивания нет.
python -X utf8 tools/research_name_pairs.py --download fns
python -X utf8 tools/research_name_pairs.py --download wiki
# Все численные результаты ниже пересчитываются из локального кеша без сети.
python -X utf8 tools/research_name_pairs.py
```

Файлы: `fns-rsmp-2026-11-10.json` — ФИО и метаданные источника; `results.json` — обезличенная статистика; `prior-aggregate-results.json` — копии ранее сохранённых сводок; `wiki-last-attempt.json` — статус обращения к Викиданным. Старые персональные строки пилотов не восстанавливаются из сводок: они ранее не сохранялись.

## Что удалось получить

ФНС публикует [открытый реестр субъектов МСП](https://www.nalog.gov.ru/opendata/7707329152-rsmp/), содержащий юридические лица и ИП. Использован опубликованный в паспорте [срез](https://file.nalog.ru/opendata/7707329152-rsmp/data-10112026-structure-12052026.zip) от 10 ноября 2026 года. Из первых читаемых XML-членов ZIP отбирались только записи ИП с тремя заполненными частями ФИО. Архив читался стандартными HTTP Range, без полной загрузки и распаковки на диск.

Это **часть реестра МСП, а не весь ЕГРИП**. Для интеграционной выгрузки самого ЕГРИП ФНС [описывает отдельный доступ с атрибутами абонентского обслуживания](https://www.nalog.gov.ru/rn77/service/egrip2/egrip_vzayim/). Его наличие не предполагалось.

| Результат ФНС | Значение |
|---|---:|
| Обработанные XML-файлы | 15 |
| Записи с полным ФИО после дедупликации по ИНН | 9 519 |
| Различные написания ФИ | 9 255 |
| Различные написания ФИО | 9 501 |
| Различные ФИ, встретившиеся более одного раза | 209 |
| Различные ФИО, встретившиеся более одного раза | 18 |

Порядок файлов задаёт смещение отбора; это не случайная выборка ИП. Совпадающие ФИО разных ИНН не объединяются. Охват — предприниматели из выбранного фрагмента реестра; нельзя масштабировать на жителей России без внешней проверки и весов.

Увеличенный запрос Викиданных для русских меток и заголовков русских статей получил HTTP 429. Повтор после ограничения не выполнялся. Полного нового корпуса Википедии нет. При последующем успешном запуске записи сохранятся в `wikipedia-10000.json`; метки/заголовки имеют отдельное происхождение и не выдаются за проверенные начала статей. [Ранее выполненный пилот](wikipedia-explicit-fullnames-2026-11-16.md) остаётся отдельной совокупностью; его сводки скопированы в локальную папку.

## Как переносилась пара на тройку

Проверяемое приближение:

\[
\widehat P(Ф,И,О)=P(Ф,И)P(О)
=K_{ФИ}\,P(Ф)P(И)P(О),\quad
K_{ФИ}=\frac{P(Ф,И)}{P(Ф)P(И)}.
\]

Это предположение о независимости отчества от пары, не следствие знания частот ФИ. В точной формуле остаётся дополнительный множитель:

\[
P(Ф,И,О)=P(Ф,И)P(О)\,
\frac{P(О\mid Ф,И)}{P(О)}.
\]

Дополнительно проверены приближение `P(Ф,И)P(О|И)` и сглаженная совместная частота тройки. Один коэффициент для всех ФИО не вводится.

## Что видно внутри выборки

MI пары ФИ — 6,986367 бита, средний перестановочный фон — 6,954582, разведочное p = 0,005. Использованы независимые перестановки имён, `permutations=199`, `seed=42`. Большая часть сырой MI воспроизводится разреженностью; превышение фона небольшое.

Внутри мужской формы отчества: 5 205 строк, MI 5,928118 против фона 5,912709, p = 0,005. Внутри женской: 4 112 строк, MI 5,974675 против 5,970543, p = 0,170. Это формы написания, не независимо установленный пол; остальные строки в эти разрезы не вошли. Проверки разведочные, семейные и географические кластеры не контролируются.

Только три пары ФИ встретились не менее пяти раз. Их эмпирический lift находится между 2,907808 и 72,942529. Это отбор повторившихся клеток на тех же данных, без оценки ошибки; такие значения не принимаются как устойчивый коэффициент или диапазон для других ФИ.

Общее TC тройки — 14,946930 бита; после учёта пары описательный остаток — 7,960564. Остаток содержит сильное смещение разреженной таблицы и не измеряет величину реальной зависимости отчества. Синтетическая проверка XOR в тестах отдельно показывает: даже независимость всех пар не доказывает независимости тройки.

## Проверка на отложенных строках

Случайное разделение внутри одного источника: 7 615 строк для оценки, 1 904 для проверки; `seed=42`. Общий для всех вариантов словарь фиксируется только по обучающей части, невстречавшиеся значения сводятся к отдельной категории UNK. Маргинальные частоты сглажены `add-0.5`. Совместные частоты смешиваются с базовым распределением с силой `s`; варианты s исследуются отдельно, лучший по тесту не объявляется окончательным.

| Приближение для ФИО | Log loss, биты, s=100 | s=100 000 |
|---|---:|---:|
| Все три части независимо | 29,497187 | 29,497187 |
| ФИ совместно × отчество отдельно | 35,330369 | 29,540304 |
| ФИ совместно × отчество условно по имени | 34,827241 | 29,537706 |
| Совместная тройка со сглаживанием | 41,052710 | 29,621564 |

Меньше — лучше. Для **самой пары** независимость даёт 21,224018 бита; сглаженная совместная частота — 27,057199 при s=100 и 21,267134 при s=100 000. Сильное сглаживание приближает результат к независимому базовому распределению, но на этой проверке не превосходит его.

При этом среди 79 тестовых строк с уже встречавшейся в обучении парой ФИ совместный вариант улучшает log loss пары с 16,684797 до 12,436285 бита при s=100. На остальных 1 825 строках пара ранее не встречалась, и совместная оценка проигрывает. Полная тройка встречалась в обучении лишь для 8 тестовых строк; у 1 315 строк хотя бы одна часть была неизвестна обучающему словарю.

Это объясняет, почему повторяющиеся сочетания могут быть полезны, но общая оценка пока переобучается. Абсолютные log loss относятся к проекции на общий словарь с UNK, а не к вероятности конкретного неизвестного ФИО. Большой вес UNK и простое сглаживание ограничивают выводы. Нет оценки калибровки числа жителей или качества решений около порога алерта. Отложенные строки одного файлового фрагмента не являются независимым подтверждением на другом источнике.

## Рабочий вывод

Проверяемый перенос `совместная ФИ × отдельное О` реализован и сравнен с полными ФИО. В исследованном фрагменте он помогает для уже наблюдавшихся пар, но пока проигрывает независимому базовому приближению в среднем. Это не доказательство истинной независимости частей. Ни универсальный коэффициент, ни новое правило основного калькулятора не приняты.

Следующие полезные шаги: расширение числа повторяющихся пар из разных фрагментов, независимый источник Википедии после снятия ограничения, выбор сглаживания на отдельной валидации, оценка устойчивости частот и проверка состава совокупности. Все текущие локальные расчёты повторяются без скачивания.
