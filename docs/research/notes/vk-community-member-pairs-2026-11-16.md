# VK: выборка пары «фамилия — имя» из участников сообщества

- Дата: 2026-11-16.
- Основание: пользователь предложил `https://vk.ru/vk` после отказа `users.search`.
- Статус: после обновления доступа сбор выполнен; исправлена потеря записей из-за языка ответа. Получен локальный корпус поддерживаемых кириллических ФИ аккаунтов, без отчеств и без национальной экстраполяции.

## Метод и источник

[Официальная схема groups.getMembers](https://raw.githubusercontent.com/VKCOM/vk-api-schema/master/groups/methods.json) допускает пользовательский, групповой и сервисный токены. Метод принимает ID/короткое имя сообщества, смещение, размер страницы, сортировку и дополнительные поля. Наличие типа доступа в схеме не заменяет проверку фактического ключа и конкретного сообщества.

Для начала выбрано сообщество `vk`, предложенное пользователем. Его место в рейтинге крупнейших сообществ не устанавливалось. Сборщик запрашивает `sex,country`; сохраняет только ID аккаунта, написания фамилии/имени, заявленный пол и ID указанной страны. Закрытые, деактивированные и неподдерживаемые записи исключаются с отдельными счётчиками. Отчество не достраивается.

Доступ к публичному списку участников запрашивается штатным методом. Скрипт не использует cookies, не пытается обойти ограничения сообщества или CAPTCHA. С 2026-11-17 ограниченные автоматические повторы допускаются только для кодов 6 и 9, с нарастающей задержкой и общим бюджетом на запуск; остальные отказы останавливают сбор. Подробности — [обработка Flood control](../../insights/2026-11-17-vk-flood-control-resume.md).

## Локальный кеш и воспроизведение

Секрет берётся из `VK_SERVICE_TOKEN` в `.env`, отдельно от пользовательского `VK_ACCESS_TOKEN`. Чтобы выбрать пользовательский токен, указать `--token-type user`; автоматической подмены типов нет.

```powershell
# После обновления сервисного ключа: ограниченный сбор и сводка.
python -X utf8 tools/collect_vk_group_members.py --group vk --limit 10000 --download
# Повторный анализ без скачивания.
python -X utf8 tools/collect_vk_group_members.py --group vk --limit 10000
# Синтетические проверки.
python -X utf8 -m unittest discover -s tests -p test_vk*.py
```

Папка `data/private/name-dependence/vk-groups/vk/` исключена из Git. В ней находятся `plan.json`, отдельные страницы `page-*.json` и обезличенный `results.json`. Каждая успешно обработанная страница сохраняется до перехода к следующей; повторная команда пропускает страницы с актуальными языком и версией обработки. Возобновление использует прежние тип токена, API-версию и план. При увеличении `--limit` с `--download` старый план и отчёты сохраняются в `snapshots/limit-<прежний лимит>/`, затем создаётся расширенный план. Страницы с совпадающими смещениями используются повторно. Офлайн-команда с прежним лимитом читает сохранённый план. Перечень страниц не выдаётся за моментальный снимок сообщества.

Версия обработки `parser_version=2`, язык ответа явно `lang=ru`. Старые страницы без языка/версии при повторном `--download` архивируются в `legacy-unlocalized/` и обновляются. Без `--download` такие страницы не используются как текущая выборка; отчёт отмечает пропуск. Новые страницы дополнительно сохраняют `source_items`: только ID, имя, фамилию, пол и ID страны открытых активных аккаунтов до проверки написания. Это позволяет исследовать отвергнутые формы без сети; контакты, изображения и другие поля не сохраняются.

План распределяет детерминированные страницы по диапазону списка `id_asc`, чтобы не ограничиться только началом списка. Это не случайная выборка аккаунтов; сортировка, плотность ID и членство создают смещение. Если число участников меняется во время сбора, это отмечается в сводке. Совпадения ID между страницами удаляются; совпадающие ФИ разных аккаунтов сохраняются. Размер, параметры и перестановочный seed задаются в коде и фиксируются в плане/сводке. Для изменения параметров существующий кеш нельзя молча смешать с новым планом.

## Результат первой проверки доступа

`groups.getMembers` с сервисным ключом вернул код 28 и текст `Application authorization failed: access_token has expired.`. Прямой минимальный запрос с пользовательским токеном вернул код 5. Контрольный `utils.getServerTime` ответил с сервисным ключом, однако это не опровергает явный отказ другого метода из-за истечения ключа. Успех метода времени нельзя считать достаточным доказательством действительности ключа для остальных методов.

Сохранены только диагностические результаты, без секретов и профилей:

```powershell
python -X utf8 -c "from pathlib import Path; print(Path('data/private/name-dependence/vk-groups-access-diagnostic.json').read_text(encoding='utf-8')); print(Path('data/private/name-dependence/vk-groups-error-detail.json').read_text(encoding='utf-8'))"
```

Сборщик теперь выделяет из ответа безопасное обозначение `access_token_expired`, не печатая исходный ответ или `request_params`. До замены ключа данных для исследования ФИ нет; ошибка доступа не означает нулевую частоту или отсутствие участников.

## Статистика после успешного сбора

### Исправление нулевого результата и выполненный сбор

Первые страницы действительно содержали записи, но фильтр отклонял все оставшиеся открытые аккаунты как `unsupported_written_name`. Проверка письменности показала латинское представление имён без заданного языка; тот же запрос с `lang=ru` дал кириллические имена. Это дефект конфигурации нашего запроса и отсутствия такой проверки, а не пустой список участников и не отсутствие имён у людей. Старый кеш содержал только принятые записи, поэтому отброшенные написания не восстанавливались из него и потребовался один повторный сбор.

Команда воспроизведения всех чисел ниже без сети:

```powershell
python -X utf8 tools/collect_vk_group_members.py --group vk --limit 10000
```

| Результат текущего кеша | Количество |
|---|---:|
| Страницы | 10 |
| Полученные записи | 10 000 |
| Поддерживаемые пары ФИ после фильтра | 6 303 |
| Исключены закрытые/деактивированные записи | 2 537 |
| Неподдерживаемые написания | 1 160 |
| Различные написания ФИ | 6 219 |
| Различные ФИ с повторениями | 70 |

MI пары — 7,796296 бита, средний перестановочный фон — 7,777064, разведочное p = 0,005 при конфиге `permutations=199`, `seed=42`. Значительная часть сырой MI воспроизводится разреженностью. Пол и другие смешивающие факторы в этой проверке не контролировались; это не коэффициент поправки вероятности ФИ населения.

В текущем ответе страна не заполнена у всех поддерживаемых записей; российское проживание по ним установить нельзя. Численность сообщества менялась между страницами, что отмечено флагом сводки. Страницы относятся к последовательным обращениям, не к единому неизменному срезу.

Сводка содержит число поддерживаемых аккаунтов, различные и повторяющиеся написания ФИ, распределения заполненных пола/страны, MI и перестановочный фон. Категории имён и профили в консоль не выводятся. Это исследование зависимости пары внутри выборки сообщества; полного ФИО в этом источнике нет, для переноса на ФИО понадобится отдельная проверка.

Участник сообщества — аккаунт, не подтверждённый уникальный житель России. Крупное сообщество может иметь международный состав, повторные аккаунты и псевдонимы; указанная страна не доказывает проживание. Для национальных частот результаты не принимаются и с реестром ИП автоматически не объединяются.

## Хватает ли данных для коэффициента ФИ

Выполнена отдельная проверка повторяемости, отложенных аккаунтов и зависимости внутри заявленного пола. Всё считается из кеша без сети:

```powershell
python -X utf8 tools/assess_vk_pair_sample.py --group vk
```

После расширения корпуса числа именно пилота воспроизводятся командой `python -X utf8 tools/assess_vk_pair_sample.py --group vk --snapshot-limit 10000`. Его отчёт находится в `data/private/name-dependence/vk-groups/vk/snapshots/limit-10000/adequacy.json`; без параметра снимка анализируется текущий расширенный план. Хеши исходных страниц включены в отчёт.

- Аккаунтов с поддерживаемыми ФИ — 6 303, различных написаний — 6 219.
- Только один раз встретились 6 149 различных пар; повторяются 70 пар, которым соответствуют 154 аккаунта.
- Максимальное число наблюдений одного ФИ — 4; пар с числом наблюдений хотя бы 5 нет. Сам порог здесь служит диагностикой, не гарантией достаточной точности.
- При разбиении `seed=42`: оценочная часть 5 042, проверочная 1 261. В проверочной части 1 230 пар ранее не встречались, 31 встречалась. У 886 записей хотя бы один компонент отсутствовал в оценочном словаре.

Дополнительно сравнили независимую оценку `p(Ф)p(И)` со сглаженной совместной: `(count(Ф,И) + s × p(Ф)p(И)) / (n + s)`. Маргинальные частоты используют add-0.5, словарь задаётся только оценочной частью; неизвестные компоненты сводятся к UNK одинаково для всех вариантов. Разбиения: `seed=42,43,44,45,46`, доля оценочной части `.8`. Это исследование вероятностного приближения, не метрики сессионного детектора.

| Сила сглаживания s | Средний log loss независимого, биты | Совместного, биты | Разбиения с выигрышем совместного |
|---|---:|---:|---:|
| 100 | 21,688327 | 27,169448 | 0 из 5 |
| 1 000 | 21,688327 | 24,145668 | 0 из 5 |
| 10 000 | 21,688327 | 22,201984 | 0 из 5 |
| 100 000 | 21,688327 | 21,731341 | 0 из 5 |

Меньше log loss — лучше. Сильное сглаживание почти возвращает оценку к независимому приближению. Нельзя из этого делать вывод об истинной независимости: проверена лишь одна семья оценок, а словарь с UNK сильно влияет на результат. Числа относятся к проекции значений на этот словарь, не к вероятностям конкретных неизвестных написаний и не к числу людей в России. Выборка из одного сообщества и случайное разделение аккаунтов не обеспечивают внешней валидации.

После разделения по заявленному полу MI превышает перестановочный фон: для 3 041 аккаунта с кодом пола 1 — 6,776387 против 6,766317 бита, p=0,010; для 3 261 аккаунта с кодом 2 — 7,037482 против 7,023602, p=0,005. Это разведочные проверки без поправки за множественные сравнения; заявленный пол и личность владельца не подтверждались. Связь частей внутри источника может присутствовать, но её обнаружение не означает достаточную точность коэффициента для отдельной редкой пары.

Проверка на подвыборках также не устанавливает достаточный объём: с ростом выборки остаётся много новых пар. Размеры и результаты кривой записаны в adequacy.json, но не используются как прогноз требуемого размера корпуса.

**Решение для текущей работы:** данных достаточно для отладки сбора и первичной диагностики зависимости, но пока нельзя обосновать устойчивый поправочный коэффициент ФИ для новых сочетаний, тем более перенос на население России. Для ФИО этот корпус вообще не содержит отчества. Следующий этап — существенно увеличить число повторяющихся сочетаний, проверить независимую совокупность и выбирать сглаживание на отдельной валидации. Произвольный общий коэффициент не вводится. Точный необходимый объём без целевой ошибки и распределения частот не определён.

### Зависимость и описательные отношения частот

Общая MI равна 6,967962 бита, перестановочный фон — 6,854926, разведочное p=0,005. Внутри кода пола 1: 5,993974 против 5,947741 бита; внутри кода 2: 6,327571 против 6,249339. Для обоих p=0,005 при прежних 199 перестановках. Перестановки диагностируют отличие от случайного сочетания частей внутри источника; p не определяет величину ошибки частоты конкретного ФИ и не заменяет внешнюю проверку.

Для `R = P(Ф,И) / (P(Ф) × P(И))`, рассчитанного по тем же наблюдениям:

| Совокупность | Минимум наблюдений пары | Число отобранных пар | Медиана R |
|---|---:|---:|---:|
| Все поддерживаемые аккаунты | 5 | 184 | 4,519411 |
| Все поддерживаемые аккаунты | 10 | 28 | 4,569235 |
| Код пола 1, вероятности внутри группы | 5 | 65 | 2,375279 |
| Код пола 2, вероятности внутри группы | 5 | 117 | 2,322315 |

Внутри групп медианные отношения ниже, но наборы отобранных пар различаются: это не разложение общего эффекта на долю пола и остаток. Даже внутри пола есть отличие от перестановочного фона. **Умножать все независимые вероятности на 4,52 или 2,35 нельзя.** Это медианы по выбранным повторяющимся клеткам, а не поправка для случайного нового ФИ. Отбор по частоте и оценка на тех же данных завышают отношения. Максимальное наблюдаемое R достигает 3505,44, что дополнительно показывает неустойчивость отношения при редких маргинальных частотах; истинность имён и уникальность людей не подтверждены.

### Перенос на отложенные аккаунты

Прежнее семейство сглаженных совместных оценок пока проигрывает независимой базе во всех пяти разбиениях при каждой проверенной силе сглаживания:

| Сила s | Средний log loss независимого, биты | Совместного, биты | Разность совместный − независимый |
|---|---:|---:|---:|
| 100 | 23,557120 | 31,205619 | +7,648499 |
| 1000 | 23,557120 | 28,276457 | +4,719336 |
| 10000 | 23,557120 | 25,549391 | +1,992271 |
| 100000 | 23,557120 | 23,867643 | +0,310523 |

Меньше — лучше. При seed=42 из 12620 проверочных записей у 11226 сочетание ранее не встречалось; у 5525 хотя бы один компонент отсутствовал в оценочном словаре. Повторов стало существенно больше, но множество сочетаний остаётся разреженным. Абсолютный log loss между пилотом и расширением не сравнивается как улучшение/ухудшение: словарь и доля UNK изменились. Проверена одна семья оценок с фиксированными силами, её проигрыш не доказывает независимость частей или невозможность более подходящей оценки.

**Вывод:** расширенный корпус пригоден для исследования частых ФИ и проверки гипотез зависимости. Устойчивой общей поправки для разметки пока нет. Следующий содержательный шаг — выбирать условную по полу оценку и сглаживание на отдельной валидации, затем проверять на другом сообществе/источнике, удержанном до выбора параметров. Для ФИО требуется корпус с явно указанными отчествами; перенос коэффициента ФИ на ФИО не подтверждён. Правила основного калькулятора не менялись.

Он даёт положительный результат для ограниченного набора частых ФИ после учёта пола и сохраняет ограничения для национального редкого порога и полного ФИО. Завершение миллиона этим не заявляется.

По следующему запросу пользователя запущен план на 1000000 записей. Предыдущая выборка сохранена в `snapshots/limit-100000/`; она остаётся основой чисел раздела выше.
