# Архитектура адаптера детектора

Статус: проект реализации на базе regex + GLiNER.

## Назначение

Адаптер принимает одно сообщение и переводит выходы детекторов в `Mention`.
Он не анализирует историю и не запускает NER повторно по накопленному контексту.

```python
extract(message: str) -> list[Mention]
```

Расширенная внутренняя функция может принимать уже полученные GLiNER-сущности и
config для прогона без загрузки модели:

```python
extract(message, gliner_entities=None, config=None, detector_version=None)
```

## Поток

1. Regex находит технические типы с диагностическими check-суммами.
2. GLiNER находит модельные span-ы и scores.
3. Внешняя метка маппится по `benchmarks/pii_smoke/config.json` в проектный `TYPE`.
4. Правила разбирают общий `PERSON`, организации, часть ФИО и известные конфликты.
5. Межтиповые пересечения и дубли разрешаются priority-правилом.
6. Результат сортируется по границам и сериализуется в mention-контракт.

## Версии

`detector_version` включает rev модели и backbone либо идентификатор хеша правил.
Ревизии берутся из закрепленного config; для полного прогона отдельно фиксируется
SHA-256 config и commit репозитория. Версия адаптера фиксируется в модуле контракта.

## Границы ответственности

Адаптер не назначает владельца, не объединяет повторные упоминания одного человека,
не вычисляет нормализованные даты/телефоны и не формирует алерт.
Общий `PERSON` не считается доказательством поддержки `FULL_NAME`, отдельных частей
ФИО или вывода полa из имени.
