# Архитектура адаптера детектора

Статус: реализованная версия адаптера на базе regex + GLiNER; ограничения и
проверяемые сценарии перечислены в [покрытии адаптера](adapter-coverage.md).

## Назначение

Адаптер принимает одно сообщение и переводит выходы детекторов в `Mention`.
Он не анализирует историю и не запускает NER повторно по накопленному контексту.

```python
extract(message: str) -> list[Mention]
```

Расширенная внутренняя функция может принимать уже полученные GLiNER-сущности и
config для прогона без загрузки модели:

```python
extract(message, gliner_entities=None, config=None, detector_version=None)
```

## Поток

1. Regex находит технические типы с диагностическими check-суммами, адресные цепочки и короткие формы ФИО с инициалами.
2. GLiNER находит модельные span-ы и scores; для benchmark порог можно переопределить аргументом `--threshold`, иначе используется config.
3. Внешняя метка маппится по `benchmarks/pii_smoke/config.json` в проектный `TYPE`.
4. Правила v2 разбирают `PERSON` через `russiannames.NamesParser`, контекст и fallback.
5. К упоминаниям ДР добавляется диагностический атрибут `attributes.age`; исходная дата не нормализуется.
6. Email переклассифицируются в `SERVICE_EMAIL` по `SERVICE_LOCAL_PARTS` и явному
   списку `SERVICE_DOMAINS`.
7. Части `ADDRESS/CITY` склеиваются с сохранением непрерывного span; организации склеиваются по маркерам с provenance `regex`.
8. Местоимения, нецифровые модельные phone и межтиповые конфликты подавляются priority-правилами; непересекающиеся упоминания сохраняются, а из однотипных пересечений остаётся более длинный span.
9. Результат сортируется по границам и сериализуется в mention-контракт.

Версия правил обозначена как `pii_smoke_rules-v2`. Публичный модуль правил находится в
`benchmarks/adapter/adapter_rules.py`, реализация — в `benchmarks/adapter/_rules_impl.py`;
regex-детектор — в `benchmarks/pii_smoke/regex_detector.py`.

## Версии

`detector_version` включает rev модели и backbone либо идентификатор хеша правил.
Ревизии берутся из закрепленного config; для полного прогона отдельно фиксируется
SHA-256 config и commit репозитория. Версия адаптера фиксируется в модуле контракта.

## Границы ответственности

Адаптер не назначает владельца, не объединяет повторные упоминания одного человека,
не вычисляет нормализованные даты/телефоны и не формирует алерт.
Общий `PERSON` не считается доказательством поддержки `FULL_NAME`, отдельных частей
ФИО или вывода полa из имени.
