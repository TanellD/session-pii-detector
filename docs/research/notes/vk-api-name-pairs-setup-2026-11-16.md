# VK API: получение доступа и первый пилот пары «имя — фамилия»

- Дата: 2026-11-16.
- Статус: токен получен и сохранён локально; он принят VK ID user_info, но VK API users.search отклоняет его с кодом авторизации 5. Выборка аккаунтов пока не получена.

Текущее продолжение по предложению пользователя: [groups.getMembers для сообщества vk](vk-community-member-pairs-2026-11-16.md). В проверке участников сервисный ключ отклонён как истёкший; успешный запрос времени сам по себе не доказывает его действительность для других методов.

## Что проверено

### Фактический результат авторизации и проверки API

#### Дополнительная проверка сервисного ключа

Пользователь предоставил сервисный ключ. Он сохранён отдельно как `VK_SERVICE_TOKEN` в игнорируемом `.env`, пользовательский токен не заменён. Контрольный `utils.getServerTime` принят, а минимальный `users.search` отклонён с кодом 1051. Значение кода отсутствует в проверенной общей JSON-схеме ошибок, поэтому точное текстовое толкование по одному номеру не назначается. [Схема users.search](https://raw.githubusercontent.com/VKCOM/vk-api-schema/master/users/methods.json) указывает только `user`, тогда как [utils.getServerTime](https://raw.githubusercontent.com/VKCOM/vk-api-schema/master/utils/methods.json) допускает `service`. Результат согласуется с различием типов доступа: работоспособность ключа приложения не означает доступность поиска.

```powershell
python -X utf8 tools/collect_vk_name_pairs.py --probe-service
```

Команда выполняет отдельную проверку и сохраняет только обезличенные статусы в `data/private/name-dependence/vk-service-token-access.json`. Профили из пробного ответа не экспортируются. Опубликованный в чате ключ рекомендуется перевыпустить; новое значение указывать только локально в `.env`. Ключ в документации, тестах и Git не сохраняется.

После сообщения пользователя об успешном входе подтверждено: `.env` содержит токен, код использует именно сохранённое значение, переменная окружения его не подменяет, срок по сохранённым метаданным не истёк. Запрос POST к `https://id.vk.ru/oauth2/user_info` с этим токеном вернул пользовательский объект; персональные поля ответа в логи и диагностические файлы не выводились и не сохранялись.

Пилот остановился на `database.getCountries` с ошибкой авторизации. Чтобы не делать вывод о поиске по отказу другого метода, отдельно выполнен минимальный прямой `users.search`; он также вернул код 5. [Официальная схема ошибок VK](https://raw.githubusercontent.com/VKCOM/vk-api-schema/master/errors.json) определяет его как `User authorization failed`, отдельно от кода отсутствия разрешения. Значит, подтверждены успешная авторизация VK ID и отказ данного токена в проверенном VK API. Универсальная несовместимость всех токенов VK ID с соцсетью этим не доказана; точное требование к доступу приложения нужно уточнять у платформы.

Проверки и их результаты:

```powershell
python -X utf8 tools/authorize_vk_id.py --check
python -X utf8 tools/collect_vk_name_pairs.py
python -X utf8 tools/collect_vk_name_pairs.py --download
# Просмотр сохранённой обезличенной диагностики без сети:
python -X utf8 -c "from pathlib import Path; print(Path('data/private/name-dependence/vk-users-search-access.json').read_text(encoding='utf-8')); print(Path('data/private/name-dependence/vk-token-access-diagnostic.json').read_text(encoding='utf-8'))"
```

Файлы диагностики не содержат токенов, идентификатора пользователя и ФИО. Успешного кеша выборки VK нет. Для продолжения нужен пользовательский доступ, который VK API принимает для `users.search`; повторять вход с теми же параметрами без изменения условий доступа пока оснований нет. Секреты остаются в `.env`.

В [официальной схеме методов VK](https://raw.githubusercontent.com/VKCOM/vk-api-schema/master/users/methods.json) метод `users.search` указывает тип токена `user`. Для `users.get` перечислены также другие типы; доступ к нему не доказывает доступ к поиску. [Проверенная схема полей](https://raw.githubusercontent.com/VKCOM/vk-api-schema/master/users/objects.json) не содержит отдельного поля отчества. Отображаемые имена не являются подтверждёнными паспортными ФИО.

Схема публикует API-версию `5.199`; это версия проверенного контракта, не заявление о последней версии сервиса. Страницы dev.vk.ru недоступны. Указанную пользователем страницу VK ID удалось прочитать прямым HTTP-запросом после отказа веб-инструмента; поток авторизации и настройки Web-приложения теперь подтверждены в пределах документации. Фактическая выдача токена и доступ к поиску ещё не проверены.

## Проверка присланной инструкции VK ID

Источники: [авторизация Web без SDK](https://id.vk.ru/about/business/go/docs/ru/vkid/latest/vk-id/connection/start-integration/auth-without-sdk/auth-without-sdk-web), [создание приложения](https://id.vk.ru/about/business/go/docs/ru/vkid/latest/vk-id/connection/create-application), [права доступа](https://id.vk.ru/about/business/go/docs/ru/vkid/latest/vk-id/connection/work-with-user-info/scopes). Прочитаны 2026-11-16; содержимое страниц в репозиторий не копируется.

Подтверждён Authorization Code + PKCE: приложение генерирует `code_verifier`, S256 `code_challenge` и случайный `state`; после входа получает `code`, `state`, `device_id`; проверяет `state`, затем обменивает код на токены через POST `https://id.vk.ru/oauth2/auth`. Значение `redirect_uri` должно совпадать с настройкой приложения. Конфиденциальному приложению нужна отдельная настройка сервера и `service_token`, поэтому требования публичного и конфиденциального вариантов нельзя смешивать.

Для Web документация описывает кабинет VK ID → «Мои приложения» → «Добавить приложение» → платформа Web, затем базовый домен и доверенный redirect URL. Описана локальная проверка на `http://localhost:80` с добавлением `localhost` в базовые домены; произвольный другой порт этим указанием не подтверждён. Также описаны вход через VK Бизнес ID и требования подтверждения профиля бизнеса; данные для подтверждения пользователь вводит в официальном кабинете самостоятельно.

Раздел прав перечисляет `vkid.personal_info`, `email`, `phone`, а примеры получения данных относятся к авторизовавшемуся пользователю через `oauth2/user_info`. Это подтверждает получение имени и фамилии участника авторизации. Документация этих страниц не утверждает, что полученный токен позволяет искать другие аккаунты через `users.search`. Нельзя ни обещать этот доступ, ни утверждать несовместимость без проверки метода или официального уточнения. Запрашивать email и phone для нашего исследования пары ФИ не требуется.

Следующий шаг для поиска — выяснить доступ `users.search` для приложения, затем проверить подготовленным ограниченным пилотом. Сам по себе успешный вход VK ID не считается успешной проверкой поиска. Альтернативная совокупность — участники, сами авторизовавшиеся в исследовательском приложении; её отбор и единица наблюдения должны описываться отдельно.

### Ошибка загрузки на стороне VK ID

Пользователь дошёл до страницы провайдера, получил общее сообщение об ошибке загрузки и сообщил о требовании подтверждения профиля в кабинете. Локальный помощник отвечал и ожидал callback; код и токен ещё не получены. Параметры опубликованной пользователем ссылки соответствуют структуре документированного запроса; полная ссылка, state и challenge в заметки не копируются.

Следующий внешний шаг — открыть предупреждение и пройти подтверждение профиля в официальном кабинете VK Бизнес ID. Текущий статус приложения, сохранённость домена/redirect и наличие явной блокировки требуют проверки владельцем. Само напоминание о подтверждении нельзя считать доказанной причиной ошибки загрузки: в ранее прочитанной инструкции описаны и предупреждение со сроком подтверждения, и блокировка при его нарушении. Изменять алгоритм PKCE по одному общему сообщению провайдера оснований нет. После изменения настроек вход начинают со свежей локальной формы, а не с ранее скопированной ссылки.

## Что нужно сделать в кабинете

1. Открыть [портал разработчиков VK](https://dev.vk.ru/) под своим аккаунтом и перейти к управлению приложениями. Прямая ссылка-кандидат: [создание приложения](https://dev.vk.ru/ru/admin/create-app); доступность из этой среды не подтверждена.
2. Создать приложение для исследования, проверив, что выбранная платформа допускает пользовательский **VK API**, включая `users.search`. Приложение для входа через VK ID само по себе не подтверждает этот доступ.
3. Пройти официальный процесс пользовательской авторизации, который предлагается именно этому приложению. Нужен пользовательский access token с доступом к указанному методу. Сервисный ключ и ключ сообщества не считать подходящей заменой. Если кабинет не предлагает нужного доступа, уточнить его возможность у поддержки VK; сообщения от имени пользователя автоматически не отправляются.
4. Сохранить токен только локально в `.env` как `VK_ACCESS_TOKEN`. В `.env.example` добавлены пустое поле и версия API; сам секрет там не хранится. Токен и URL авторизации с секретами не присылать в чат.
5. Запустить сначала локальную проверку, затем пилот ниже. Ошибка авторизации или доступа означает, что выдачу/права нужно уточнить, а не что сбор уже доступен.

Если нужны инструкции по конкретным кнопкам, требуется описание доступных типов приложений в кабинете без токенов и персональных данных: доступ к интерфейсу зависит от текущих возможностей платформы и аккаунта.

```dotenv
VK_ACCESS_TOKEN=
VK_API_VERSION=5.199
```

## Подготовленные команды

### Авторизация локальным помощником

Пользователь разрешил попробовать авторизацию VK ID. Подготовлен `tools/authorize_vk_id.py` для **публичного Web-приложения**: базовый домен `localhost`, доверенный redirect URL `http://localhost/callback`. Тип конфиденциальности выбирается в кабинете VK ID; помощник не использует `service_token` и не предназначен для конфиденциального варианта.

```powershell
# Проверка настройки без вывода значений секретов и без сети.
python -X utf8 tools/authorize_vk_id.py --check
# Локальная форма и callback на стандартном HTTP-порту.
python -X utf8 tools/authorize_vk_id.py
```

Открыть `http://localhost/`, ввести публичный ID созданного приложения, нажать «Войти через VK ID». После отправки открывается локальная страница `/continue` с явной ссылкой «Продолжить в VK ID»: нажать её, затем пройти вход на стороне VK. Внешний переход не выполняется перенаправлением POST-формы. ID можно также записать в `.env` как `VK_CLIENT_ID`. Redirect URL фиксирован и должен совпадать с настройкой приложения. Помощник слушает только `127.0.0.1`; если порт занят или запрещён, он сообщает об ошибке, не заменяя адрес автоматически. ThreadingHTTPServer и тайм-аут соединений предотвращают зависание из-за пустого предварительного соединения браузера; операции изменения PKCE-состояния защищены блокировкой. После перезапуска помощника нужно обновить локальную форму и начать вход заново. Для устаревшей формы, неверного адреса и неожиданного Origin возвращаются видимые сообщения с действием для повтора; GET `/start` также показывает ссылку на форму. `/status` содержит только состояние и безопасное обозначение последнего шага, без ID, query и секретов.

Проверяются `state`, срок действия попытки и однократность callback. Поддержаны параметры в JSON `payload` и отдельные query-параметры; неоднозначные и повторные поля отклоняются. PKCE verifier и state существуют только в памяти. Запрашивается только `vkid.personal_info`. Callback не содержит скриптов и внешних ресурсов; ответы запрещают кеширование, на callback и продолжении запрещена передача Referer. Исходная форма использует Referrer-Policy same-origin; Origin null допускается с действительным nonce, явно межсайтовая отправка и чужой Origin отклоняются. Nonce проверяется и заменяется после успешной отправки под блокировкой. Токен обменивается POST-запросом на официальный фиксированный endpoint без перенаправлений. URL callback, тело ответа и секреты не выводятся в HTTP-логи и консоль.

После успешного обмена токены и служебные данные авторизации записываются атомарно только в `.env`, после проверки исключения файла из Git. Прочие ключи `.env` сохраняются. Используются `VK_ACCESS_TOKEN`, `VK_REFRESH_TOKEN`, `VK_DEVICE_ID`, `VK_CLIENT_ID`, `VK_REDIRECT_URI`, `VK_TOKEN_SCOPE`, `VK_TOKEN_OBTAINED_AT`, `VK_TOKEN_EXPIRES_AT`. Если срок ответа равен нулю, конкретное время истечения не выводится из него; это не обещание бессрочной работоспособности токена. Значения в `.env.example` пустые, кроме несекретных настроек. Refresh-обмен пока не реализован.

Страница `/status` показывает только состояние процесса. После сохранения отображается `/done`; доступ к `users.search` затем проверяется отдельным пилотом ниже. Завершить помощник можно Ctrl+C в его терминале. До регистрации приложения и входа пользователя получение токена выполнить невозможно; рабочее приложение за пользователя не регистрируется.

Проверки на синтетике, включая тест-вектор [RFC 7636](https://www.rfc-editor.org/rfc/rfc7636#appendix-B), отказы неверного state/replay, сохранение остальных переменных и запрет записи секретов в отслеживаемый файл:

```powershell
python -X utf8 -m unittest discover -s tests -p test_vk_id_authorization.py
```

### Пилот после выдачи токена

```powershell
# Только наличие настройки и кеша; секрет не печатается, сети нет.
python -X utf8 tools/collect_vk_name_pairs.py
# После выдачи токена: один ограниченный поиск, затем локальный кеш.
python -X utf8 tools/collect_vk_name_pairs.py --download
```

Сначала определяется код России через `database.getCountries` с ISO-кодом RU по [официальной схеме](https://raw.githubusercontent.com/VKCOM/vk-api-schema/master/database/methods.json). Затем выполняется одна страница поиска без запроса конкретного имени. Это проверка доступности метода и формата, не случайная выборка населения. Размер пилота и порядок заданы в коде. Массовое разбиение поиска на фильтры не реализовано.

Токен передаётся POST-телом, перенаправления запрещены, текст ошибки и `request_params` не экспортируются. Ошибки доступа, CAPTCHA и ограничения частоты останавливают пилот без автоматических повторов. Успешный результат сохраняется в `data/private/name-dependence/vk-name-pairs-pilot.json`; существующий кеш повторно не скачивается. Сохраняются только ID аккаунта, два отображаемых компонента имени и заявленный пол; закрытые и деактивированные записи исключаются. Неподдерживаемые многословные записи учитываются как пропуски, отчество не достраивается.

## Ограничения исследования

Единица — аккаунт, не человек. Поисковая выдача отсортирована и ограничена; страна в профиле не доказывает проживание. Псевдонимы и повторные аккаунты искажают частоты. Сначала нужно проверить доступ и качество полей, затем согласовать рамку отбора и отдельный расчёт пары ФИ. В общий анализ ФИО записи без отчества не подставляются; текущий сборщик ФНС/Википедии их автоматически не объединяет.

Проверки транспорта, исключения закрытых записей и защиты токена выполняются на синтетике:

```powershell
python -X utf8 -m unittest discover -s tests -p test_vk_name_pairs.py
```
