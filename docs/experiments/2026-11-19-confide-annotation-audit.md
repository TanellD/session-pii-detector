# Аудит источников Владимира: сессии для нашей разметки

- Дата: 2026-11-19.
- Базовый коммит проекта: `27ea337`; скрипт аудита и этот отчёт добавлены вместе.
- Гипотеза: среди источников задачи #13 есть русские синтетические сессии с классами нашего ТЗ.

## Настройка и область проверки

Проверена актуальная ветка `research/13-russian-datasets-synthetic-plan`, коммит `0929e1e3b2d28772ddceac1cccd751ba315e41de`; локальный и удалённый указатели совпали. В ней находятся обзор, сценарии и промпты, но не готовый корпус. [Обзор по #13](https://github.com/TanellD/session-pii-detector/blob/0929e1e3b2d28772ddceac1cccd751ba315e41de/docs/project/data-research-summary.md) отдельно говорит, что источники ещё не допущены автоматически в train/validation.

Основной проверенный источник — [CONFIDE](https://github.com/glebis/confide), revision `91fa72f894c83680129c460daa47426101c4d596`. Загружены только `data/sessions-ru/pii-eval-ru.jsonl`, отдельные синтетические adversarial-примеры, notice, лицензия и документация. Не загружались `sessions-ru-real` и внешние реальные срезы. Собственный RU-срез авторы объявляют полностью вымышленным; данные/документация распространяются под CC-BY-4.0, код — MIT. Это проверка авторского заявления о происхождении, не независимая верификация каждого реквизита.

Кеш: `data/external/confide-synthetic/<revision>/`, вне Git. Скрипт использует фиксированный белый список файлов и не запускает внешние модели. Конфиг сопоставления — текущие `configs/annotation-classes.json` и `docs/data/annotation-class-fields.md`.

Команда воспроизведения агрегатов:

```powershell
python -X utf8 tools/audit_confide_for_annotation.py --download
# После загрузки достаточно, сеть не используется:
python -X utf8 tools/audit_confide_for_annotation.py
```

## Результаты

В основном срезе **30 русских сессий, 6 вымышленных профилей**, с повторными сессиями каждого профиля. В JSON обнаружено **1076 исходных спанов**, все совпали со своим `text[start:end]`. У **75** спанов позиции находятся до первой реплики: это шапка/метаданные, их нельзя автоматически включать в чатовый эталон. Все **30** документов содержат выделяемые границы реплик. Количества воспроизводятся командой аудита выше.

Источник `DATASHEET.md` на этой ревизии сообщает прежнее количество 1058 спанов; фактический JSON содержит 1076. Для расчётов используется JSON с записанной контрольной суммой. Согласие символьных границ не доказывает полноту или семантическую правильность разметки.

| Исходная метка | Спанов во всём JSON, включая шапки | Что соответствует нашему ТЗ |
|---|---:|---|
| `PERSON` | 840 | Части имени; требуется переразметка в отдельные Ф/И/О и выбор владельца. Не все спаны являются полным ФИО. |
| `PHONE` | 6 | Телефон, но есть написание словами; числовой валидатор MVP такие значения пока не принимает. |
| `EMAIL` | 8 | Email; личную принадлежность проверять по контексту. |
| `AGE` | 24 | Возраст; значительная часть записана словами, тогда как нынешний валидатор принимает цифровые полные годы. |
| `PROFESSION` | 47 | Профессия/должность; возможны неоднозначные группы ОКЗ. |
| `ORG` | 22 | Организация; не всякая упомянутая организация является работодателем. |
| `LOCATION` | 22 | География, иногда часть адреса; это не готовая разметка полного адреса до дома. |
| `ID` | 36 | Есть 4 кандидата СНИЛС; остальные — технические client ID и страховой полис, их нельзя объявить красными документами нашего списка. |
| `DATE` | 23 | Вне текущего набора, возраст автоматически не вычислять. |
| `MEDICATION` | 48 | Вне текущего набора. |

Это частоты исходных упоминаний, не число уникальных людей и не распространённость признаков в населении.

Отдельный `pii-adversarial-ru.jsonl` содержит **16 коротких фрагментов, 20 спанов**. В нём есть явно подписанные примеры СНИЛС (`ru-adv-07`), ИНН (`ru-adv-08`) и паспорта (`ru-adv-09`). Это короткие проверки извлечения/красного правила, а не полноценные накопительные сессии. Их количества также выводит аудит.

Отдельных исходных меток пола, полного адреса и банковской карты нет. Это не доказывает полного отсутствия любых таких упоминаний в неразмеченном тексте; их покрытие этим аудитом не подтверждено.

## Подготовленные кандидаты

Для малого пилота взяты начала **трёх** исходных dev-сессий, по **16** реплик, всего **48** сообщений. Подготовка не содержит эталона и не вызывает API:

```powershell
python -X utf8 tools/audit_confide_for_annotation.py --prepare-prefixes
python -X utf8 tools/run_compatible_annotation_pilot.py --model Gemma-4-31B-IT --span-mode quotes --input data/experiments/confide-annotation-candidates-2026-11-19/sessions.json --dry-run
```

Первая команда создаёт новый каталог один раз и отказывается перезаписывать существующий. Вторая повторно проверяет готовый вход без сети. Кандидаты и их происхождение:

- `data/experiments/confide-annotation-candidates-2026-11-19/sessions.json`;
- `data/experiments/confide-annotation-candidates-2026-11-19/provenance.json`.

| Исходная сессия | Что есть в выбранном начале |
|---|---|
| `ru-a-s01` | Имена, телефон и email, страховой полис. Полис — контроль против ошибочного красного класса. |
| `ru-c-s01` | Имена, возраст, география, телефон/email и СНИЛС. |
| `ru-e-s01` | Имена, возраст, контакты и номер, который исходный gold относит к СНИЛС; контекст надо проверить отдельно. |

Полные сессии содержат длинную историю и требуют большего бюджета ответа, чем короткие примеры прежнего пилота: модель должна вернуть также исходные сообщения. Поэтому сначала подготовлены начальные фрагменты, а не запущена массовая разметка. Префиксы — удобные отладочные случаи, не независимый test и не свидетельство достаточного разнообразия.

## Анализ несовпадений и условия использования

- `entity_id` источника группирует конкретную сущность, а не автоматически весь профиль человека. `person_role` и `speaker` тоже не заменяют `person_id`: говорящий терапевт может назвать сведения клиента.
- Сведения из шапки и `ANSWER-KEY` нельзя подать модели как уже произнесённые факты. Из входа кандидатов они исключены; исходные координаты каждого сообщения записаны отдельно.
- Существующий gold ориентирован на деидентификацию: он содержит медицинские сущности, даты, общие ID и другую политику маскирования. Его нельзя механически объявить gold нашего алерта.
- Инициалы, неполные/словесные контакты, местоименные и родственные цепочки должны обрабатываться по нашему ограниченному MVP; отсутствие поддержки не исправлять догадками.
- Персоны повторяются между сессиями. При разбиении нельзя разносить один профиль по train/dev/test. Авторы уже дают person-disjoint split, но использование примеров для отладки требует своей маркировки происхождения и не доказывает отсутствия данных в предобучении модели.
- Синтетическое происхождение не включает `is_example=true` автоматически. Этот флаг зависит от содержания самих реплик; служебную пометку источника мы сохранили в provenance, а не в тексте диалога.

## Остальные источники из обзора

[Scanpatch](https://huggingface.co/datasets/scanpatch/pii-ner-corpus-synthetic-controlled) содержит тексты с символьными метками и пересекающимися именами/частями адреса, но это не готовые сессии; нужен фильтр русского языка и переразметка вложенных сущностей. [Meddies](https://huggingface.co/datasets/Meddies/meddies-pii) — преимущественно документы, а не диалоги; для русского среза нужны отдельный аудит и учёт CC-BY-NC-4.0. В этой проверке их файлы не скачивались, качество на них не измерялось.

## Вывод

Гипотеза подтверждена для CONFIDE: есть подходящие кандидаты и существенная часть наших классов. Это найденный Владимиром внешний источник, а не уже подготовленный им размеченный корпус. Подготовлены исходные префиксы для просмотра/LLM-разметки; human review ожидается. API-разметка кандидатов, утверждение gold и метрики качества в этом аудите не выполнялись.
