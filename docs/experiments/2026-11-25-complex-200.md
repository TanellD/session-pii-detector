# Эксперимент: сложные диалоги с несколькими людьми, NER v2 и Gemma

- Дата: 2026-11-25; draft PR #47.
- Статус: корпус создан и размечен; свежий NER и полный прогон запущены.
- Гипотеза: длинные префиксы, несколько владельцев, общие контакты, одноимённые участники и уточнения лучше выявляют ошибки цепочки, чем короткие однотипные кейсы.

## Данные и авторская разметка

Версия: `complex-multiperson-200-v1`; финальный каталог: `data/experiments/complex-200-2026-11-25-final/`. Предварительный каталог без `-final` не используется в оценке: в нём до авторской проверки не был учтён более ранний алерт второго владельца общего номера.

Состав: 200 сессий, 1 420 сообщений пользователя, 1 330 спанов. По 100 сессий с двумя и тремя людьми. Длины: по 40 сессий с 5, 6, 7 и 8 сообщениями, по 20 с 9 и 10. Авторский эталон: 120 положительных и 80 отрицательных сессий. Все числа воспроизводятся:

```powershell
.\.venv-gliner\Scripts\python.exe -X utf8 tools/build_complex_200.py --output data/experiments/complex-200-rebuild
```

Выходной каталог должен быть новым. Генератор не перезаписывает замороженные данные.

Разметка задана автором в явных сюжетах: каждое упоминание содержит тип и владельца, код вычисляет точные границы при подстановке значений. Общие атрибуты имеют список владельцев; неизвестные — null. Все повторные упоминания размечены. Момент алерта и причины заданы отдельно по качественным основаниям ТЗ, без весов сервиса и без ответов оцениваемой модели. Позднее уточнение не меняет предыдущий null задним числом. Служебные контакты отмечены отдельно в авторском реестре, без изменения схемы сущностей.

Это 20 авторских сюжетов с десятью вариантами профилей и вставок, а не 200 независимо придуманных историй. Есть варианты с общим телефоном, общей почтой и общим адресом, контакты разных людей, одноимённые люди с разными фамилиями, смена пишущего, поздний владелец, повторный телефон, псевдоним, служебные контакты, адрес доставки отдельно от проживания. Дополнительные реплики относятся к оформлению заявки и раздвигают важные упоминания по контексту.

Синтетические имена, телефоны с нерабочим кодом 000, почта example.invalid. Ответов бота нет; обращения сформулированы без обязательных скрытых ответов помощника. Внешняя модель не генерировала эталон. Человеческое ревью ещё не выполнено; авторская разметка не является независимой проверкой другим разметчиком.

## Конфигурация и запуск

- Основа кода: `f75beea` плюс генератор, запуск и поддержка v2 в оценщике. SHA генератора — в manifest.json корпуса; SHA адаптеров и записи NER — в результатах.
- Свежий GLiNER: подготовленные локальные веса, исходные `benchmarks/pii_smoke/config.json` и порог.
- Постобработка: `adapter-candidate-v2`, без подстройки правил под новые предсказания.
- Линкер: Gemma-4-31B-IT, `configs/linker-gemma-baseline.json`, окно контекста и промпт сохранены.
- Риск: `configs/runtime-risk-policy.json`, веса не подбираются на этом корпусе.
- Окружение: локальный Windows/CPU для NER; живой внешний API для Gemma.

Команда из корня worktree:

```powershell
.\.venv-gliner\Scripts\python.exe -X utf8 -u tools/run_complex_200.py --input data/experiments/complex-200-2026-11-25-final/snapshot.json --run data/experiments/complex-200-gemma-v2-2026-11-25
```

Сначала выполняется свежий реальный NER с сохранением результатов, затем на тех же модельных спанах сравниваются v1 и v2. После этого автоматически запускается полная бизнес-цепочка Pipeline: NER v2 → фильтры → живой Gemma → риск. Это не HTTP/RPS-бенчмарк: в полном прогоне используются только что сохранённые реальные выходы NER, его исходное время измеряется отдельно. Снимок эталона, владельцы, название семейства и ожидаемый алерт в запрос модели не передаются.

Результаты: `data/experiments/complex-200-gemma-v2-2026-11-25/`. `ner-comparison.json` содержит сравнение извлечения и ошибок; `results/summary.json` — полный сервис; `live-progress.md` — текущий этап и покрытие. Исходные запросы, ответы, неуспешные попытки и частичные предсказания сохраняются локально.

Наблюдение без API:

```powershell
.\.venv-gliner\Scripts\python.exe -X utf8 tools/watch_gemma_linker.py --run data/experiments/complex-200-gemma-v2-2026-11-25
```

Повтор команды запуска использует сохранённые NER-записи и манифест Gemma. Перед продолжением проверить, что предыдущий worker завершился. Нельзя запускать два обработчика одного каталога. Успешные сессии повторно не запрашиваются, попытки и ошибки сохраняются. Супервизор ограничивает повторы транспортных ошибок; невалидные ответы не заменяются эталоном.

## Метрики и ограничения

Свежий NER завершён. Числа ниже воспроизводятся запуском `tools/run_complex_200.py --input data/experiments/complex-200-2026-11-25-final/snapshot.json --run data/experiments/complex-200-gemma-v2-2026-11-25 --ner-only`; сохранённые реальные выходы повторно используются. Не запускать эту команду поверх активного полного прогона; для просмотра достаточно `ner-comparison.json`.

| Метрика извлечения, весь корпус | v1 | v2 |
|---|---:|---:|
| TP / FP / FN | 770 / 833 / 560 | 780 / 832 / 550 |
| Precision | 48,03% | 48,39% |
| Recall | 57,89% | 58,65% |
| F2 | 55,61% | 56,26% |
| Успешные сессии без LLM | 200/200 | 200/200 |

На этом новом корпусе прирост v2 существенно меньше, чем на предыдущих изученных шаблонах. Основная проблема — типизация имён: v2 правильно находит 75 из 600 FIRST_NAME (Recall 12,50%); много упоминаний остаётся PERSON или получает другой тип. Также есть 219 лишних ORGANIZATION и 461 лишний PERSON. Искусственные имена и повторяемые формулировки влияют на сложность; это не оценка частоты ошибок на реальных именах. Все 330 PHONE, 230 EMAIL и 40 ADDRESS извлечены точно на данном синтетическом корпусе, но значения контактов структурно однотипны. Не менять NER по этим ответам до завершения исходного полного прогона.

По `docs/kb/metrics.md`: точное совпадение типа/границ, Precision/Recall/F2 извлечения; pairwise линкера на сопоставленных спанах с отдельным покрытием; полные группы; Precision/Recall/F2-session/F2-timely алертов, FP0 и offsets. Отказы обработки не являются отрицательными сессиями. Метрики алертов успешного поднабора нельзя выдавать за надёжность всего корпуса.

В отрицательном сюжете с двумя неизвестными контактами не утверждается один владелец; такие случаи нужны в том числе для проверки текущей политики риска. Повтор имени, адреса или контакта сам по себе не доказывает тождество людей. Ограничение контекста может скрыть раннее объяснение роли, даже если текст был однозначен при чтении всей сессии.

Синтетика и повторяемые сюжеты не доказывают реалистичность распределения боевого трафика. Не подбирать правила NER и веса на этом срезе, прежде чем сохранить исходный результат. Итоговые метрики публиковать после завершения, с исходными счётчиками и ошибками.
