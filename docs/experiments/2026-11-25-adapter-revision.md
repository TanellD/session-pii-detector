# Эксперимент: отдельная ревизия адаптера без смены GLiNER

- Дата: 2026-11-25, Москва.
- Гипотеза: исправление форматов и типизации улучшает извлечение без изменения весов модели.
- Статус: завершён локальный сравнительный прогон.

## Настройка

- Данные: `random-linker-250-2026-11-24/snapshot.json`, тот же фиксированный синтетический срез. Эталон и политика разметки не менялись.
- Исходные предсказания: замороженные реальные выходы GLiNER + regex из `random-linker-250-gliner-2026-11-24`. Перед использованием проверены конфиг, тексты и манифест весов.
- Модель и порог: исходные `benchmarks/pii_smoke/config.json`, без изменений.
- Новая версия: `src/session_pii/adapter_revision.py`, `adapter-candidate-v1`. Это независимая обёртка `RevisedAdapter(base)`; активный адаптер сервиса и выполняющийся Gemma-прогон не переключались.
- Изменения: восстановление полных адресов с точками после сокращений; проверка каждого кандидата по контракту и отклонение невалидных EMAIL/AGE; расширение контекста паспорта и ИНН с сохранением checksum; отдельные контекстные кандидаты частей имени; ограниченная типизация PERSON по форме и позиции; отбрасывание явно нарицательных ссылок. Неуверенные остатки сохраняются как PERSON.
- Для новых кандидатов источник — правило, без переноса confidence GLiNER.
- Основа: `2172a364f5259ad7bcfd0066caba8a8004fac046` плюс незакоммиченные изменения. Хеши данных, ревизии и записи детектора — в `manifest.json`, окружение — в `environment.json`.
- GPU, LLM и свежий нейронный инференс не запускались. Замер задержки относится только к локальной дополнительной обработке; не ко всему NER.

## Результаты

Сравнение до фильтров сервиса на всех 250 сессиях, exact type-aware micro:

| Метрика | Baseline | Ревизия |
|---|---:|---:|
| TP | 304 | 408 |
| FP | 270 | 142 |
| FN | 221 | 117 |
| Precision | 52,96% | 74,18% |
| Recall | 57,90% | 77,71% |
| F2 | 56,84% | 76,98% |

Ошибки обработки при пропуске через Pipeline без LLM: 28/250 у baseline, 0/250 у ревизии. Для проверки извлечения StubLinker оставляет владельцев неизвестными; алерты при этом не оцениваются.

После фильтров на общем успешном срезе из 222 сессий:

| Метрика | Baseline | Ревизия |
|---|---:|---:|
| TP / FP / FN | 260 / 194 / 201 | 358 / 111 / 103 |
| Precision | 57,27% | 76,33% |
| Recall | 56,40% | 77,66% |
| F2 | 56,57% | 77,39% |

Ревизия после фильтров на всех 250 сессиях: TP=408, FP=119, FN=117; Precision=77,42%, Recall=77,71%, F2=77,66%. Этот результат имеет другой охват, чем исходные 222 успешные сессии; основной контролируемый контраст показан выше.

## Анализ ошибок

- Адреса: 34 пропуска baseline устранены восстановлением найденных regex полных цепочек. Причина — последующий фильтр не узнавал сокращения с точкой, а не неспособность модели выделить адрес.
- Паспорта и ИНН: исправлены контексты «серия и номер» и «физического лица». На этом срезе восстановлены 7 паспортов и 3 ИНН; это маленькие подвыборки, не доказательство общего покрытия документов.
- Невалидные EMAIL/AGE: кандидаты отклоняются по отдельности с сохранением причины. Полные корректные контакты продолжают извлекаться, ошибки всего сообщения исчезли на данном срезе.
- Имена: правильных FIRST_NAME стало 70 вместо 42, LAST_NAME — 61 вместо 29. При этом лишних LAST_NAME стало 10 вместо 5: эвристики окончаний не универсальны.
- Остались 105 FP общего PERSON и 8 пропущенных эталонных PERSON. Часть ошибок связана с общим типом вместо частей имени; часть — с ненужными модельными упоминаниями. Нельзя удалять весь PERSON, поскольку он входит в поддерживаемые жёлтые атрибуты.
- Профессии не исправлялись: 18 пропусков остаются. Лишние организации также остаются.

## Вывод и следующий шаг

Большая часть прироста получена исправлением адаптации, а не изменением модели. Правила создавались с учётом ошибок этого диагностического среза, поэтому результат нельзя считать независимой тестовой оценкой. Нужен новый набор с другими формулировками, незнакомыми именами, дефисными и многословными частями, отрицательными контекстами документов и разнообразными адресами.

Перед интеграцией следует оценить влияние изменённых кандидатов на линковку и риск отдельно. Текущий эксперимент измеряет только извлечение и выполнение контракта. Текущие API- и Colab-промпты не менялись.
