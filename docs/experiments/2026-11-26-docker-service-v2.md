# Интеграция и функциональная проверка Docker runtime v2

- Начало: 2026-11-26; повторная проверка: 2026-11-27.
- Ветка: feat/docker-service-v2, база e548470 плюс интеграционные изменения.
- Постановка: подключить актуальные компоненты, безопасные логи, тайминги и
  режим без внешнего линкера.
- [Сборка, необходимые артефакты и HTTP API](../api/docker-service-v2.md).

## Конфигурация

HTTP/JSON, один Uvicorn worker, состояние сессии в памяти. Адаптер v2,
базовая runtime-risk-v2, regex либо CPU GLiNER с прежним threshold 0.5.
При функциональных проверках линкер bypass, без внешнего API; fallback error.
Политика с порогами validation доступна отдельно, по умолчанию не включена.

Runtime-образ собран и запущен проектом pii-docker-v2 на localhost:8020.
Модельный образ — pii-docker-v2-gliner на localhost:8022, с Linux model volume.
Текущий модельный код проверялся с read-only compose.dev.yaml поверх собранных
зависимостей. Генератор нагрузки и его зависимости из CI исключены; поставка
содержит только сервисные средства измерения: JSON-логи и Server-Timing.

## Повторные функциональные проверки

Только синтетические входы. Из корня worktree, при работающих контейнерах:

```powershell
python -X utf8 tools/smoke_service.py --base-url http://127.0.0.1:8020 --expect-adapter
python -X utf8 tools/smoke_service.py --base-url http://127.0.0.1:8022 --expect-adapter --timeout 60
```

Проверяются создание сессии, анализ, точный retry без повторного изменения
состояния, чтение истории, выделение корректного синтетического СНИЛС и красный
алерт на нужном сообщении. Неполнота bypass ожидаема и явно возвращается в ответе;
regex дополнительно сообщает ner_not_configured.

Оба smoke завершились успешно. Первая попытка модельного smoke с обычным
клиентским timeout 10 секунд прервалась на analyze; повтор с явным timeout 60
секунд прошёл. Причина первой задержки не установлена; успешный повтор не
подтверждает стабильность latency. Параметр smoke не меняет таймауты сервиса.

Сервисные тесты и проверка Compose:

```powershell
python -X utf8 -m unittest discover -s tests/service -q
docker compose config --quiet
docker compose -f compose.yaml -f compose.gliner.yaml config --quiet
```

Тесты покрывают приватность JSON-логов, bypass/fallback, readiness после
initialize, ограничение inflight, timeout очереди линкера и неизменность исходной
модели при переносе конфигурации. Нагрузочный клиент и тест его квантилей не входят
в ветку. Полный подготовленный каталог модели и результаты остаются вне git.

Команда unittest выше: 90 тестов, OK при повторной проверке 2026-11-27.

## Найденные ограничения

Первый build прервался из-за DNS/сети Docker; повтор завершился успешно без
отключения TLS и изменения закреплённых сервисных зависимостей.
Модельная Windows-конфигурация требует переноса абсолютного пути backbone.
Windows bind-mount не подтвердил readiness до остановки проверки; после
копирования проверенных весов в Linux volume и перезапуска startup завершился.
Конкретная причина разницы вариантов отдельно не изолирована.
Локальный Windows-запуск сторонней библиотеки требует Python -X utf8.

Пересечения типов в текущем NER по-прежнему могут приводить к HTTP 502 на
normalization до линкера; fallback линкера не должен скрывать эти ошибки.
Внешний Gemma, предельная нагрузка, gRPC и несколько реплик не проверялись.
Общего хранилища и промышленного gateway нет. Это функциональная интеграция,
а не подтверждение качества модели или предельной производительности.
