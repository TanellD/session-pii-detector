# Сравнение Gemma и Qwen на авторских синтетических сессиях

- Дата: 2026-11-19.
- Задача: создать разнообразные сессии, составить авторский эталон и посмотреть реальные ошибки внешних LLM.
- Связано: draft PR #44, [ТЗ](../data/annotation-guidelines.md), [метрики](../kb/metrics.md).
- Базовый коммит: `633f8fe`; генератор, сравнение и изменения runner поставляются вместе с этим отчётом. Точное состояние генератора и инструкций зафиксировано хешами локального манифеста, результаты API — манифестами отдельных прогонов.
- Эталон составлен текущей LLM до запросов внешним моделям. Пользователь проверяет его в читаемом файле. Это авторский диагностический набор, не независимый человеческий benchmark и не случайная выборка рабочих сессий.

## Данные

Материализация:

```powershell
python -X utf8 tools/build_annotation_comparison_set.py
```

Результат команды: **10 сессий, 34 сообщения, 32 сущности; 5 положительных и 5 отрицательных сессий** по текущей политике. Одна сессия полностью чистая. Покрыты все текущие спановые классы: Ф/И/О, пол, возраст, география, профессия, организация, телефон, email, адрес, паспорт, СНИЛС, ИНН физлица, банковская карта. Пары и ФИО не являются отдельными спановыми классами.

| Сценарий | Ожидаемое поведение |
|---|---|
| `clean` | Нет сущностей, нет алерта |
| `yellow_profile` | ФИО и жёлтые факты без достаточного основания алерта |
| `fi_email` | ФИ из разных сообщений + личный email, алерт на `m3` |
| `io_phone` | ИО + полный личный телефон, алерт на `m3` |
| `fo_address` | ФО + полный адрес проживания, алерт на `m3` |
| `contacts_correction` | Исправление телефона; телефон + почта одной персоны, алерт на `m3`; повтор не усиливает факт |
| `separate_owners` | ФИ, телефон и служебная почта не объединяются в одного человека; нет алерта |
| `address_only` | Один адрес проживания не алертит |
| `red_unknown_example` | Учебный пример и неизвестный владелец не отменяют красное правило, первый алерт на `m2` |
| `single_name_and_words` | Одна часть имени + телефон не завершают качественное правило; слова, инициалы и маски исключены |

Все значения вымышлены: телефоны с нулевым кодом, документы — нулевые суррогаты, email в `.invalid`. Синтетическое происхождение не включает `is_example`: этот флаг ставится только при явном учебном контексте внутри сообщения. Числовая статистика для возраста/частей имени не выдумывается; неуверенность префиксов сохраняет обработчик. Результаты без алерта с такой пометкой остаются отрицательными по рабочей политике.

Локальный каталог `data/experiments/annotation-comparison-2026-11-19/`:

- `sessions-for-review.md` — тексты, выделенные фрагменты, персоны и ожидаемые алерты для чтения пользователем.
- `sessions.json` — только исходные сообщения для внешних моделей, без эталона.
- `gold.json` — эталон со спанами и принадлежностью.
- `gold-assessments.json` — авторские ожидания и вычисленное состояние после каждого сообщения.
- `manifest.json` — происхождение, исходный коммит и хеши инструкции, конфигов и генератора.

Новый набор не перезаписывает прежний пилот или CONFIDE. Генератор отказывается перезаписывать существующий каталог. Для повторной материализации нужен новый `--output`.

## Запросы к моделям

Политика `2026-11-18-working-v2`, схема `annotation-mvp-v2`, транспорт `annotation-quotes-v1`. Модель выбирает точный фрагмент и его вхождение, а инструмент находит Unicode-границы без исправления текста. В модель передаются только исходная сессия и общие инструкции/конфиг; авторские эталоны, описания сценариев и ожидаемые алерты не передаются.

```powershell
python -X utf8 tools/run_compatible_annotation_pilot.py --model Gemma-4-31B-IT --input data/experiments/annotation-comparison-2026-11-19/sessions.json --output data/experiments/radeon/2026-11-19-comparison-gemma-01 --span-mode quotes --limit 10 --timeout 120 --max-tokens 4000 --delay 3 --continue-on-failure
python -X utf8 tools/run_compatible_annotation_pilot.py --model Qwen3.8-27B --input data/experiments/annotation-comparison-2026-11-19/sessions.json --output data/experiments/radeon/2026-11-19-comparison-qwen-01 --span-mode quotes --limit 10 --timeout 120 --max-tokens 4000 --delay 3 --continue-on-failure
```

Каждая модель обрабатывает сессии последовательно; два отдельных прогона выполняются одновременно. Повторов запросов нет. Явный `--continue-on-failure` разрешает перейти к следующей сессии после тайм-аута или невалидного ответа; HTTP-ошибка останавливает прогон. Стандартный режим runner сохраняет прежнюю остановку при первой ошибке. Незавершённый на клиенте запрос мог продолжиться у провайдера; его usage не считается нулевым.

## Сравнение

После завершения запросов, без сети:

```powershell
python -X utf8 tools/compare_annotation_models.py --gold data/experiments/annotation-comparison-2026-11-19 --runs data/experiments/radeon/2026-11-19-comparison-gemma-01 data/experiments/radeon/2026-11-19-comparison-qwen-01 --output data/experiments/annotation-comparison-2026-11-19/model-comparison.json --check
```

Первоначальная сборка выполняется без `--check`: создаются JSON со счётчиками и читаемый `model-comparison.md`. Приведённая команда проверяет уже сохранённые результаты без перезаписи и выводит сводку. Вычисляются exact/type-aware извлечение, F2-session, F2-timely и диагностические offset. Ранний алерт положительной сессии даёт только FP-timely, поздний — FN-timely. Неуспешные запросы не подменяются отрицательными предсказаниями: метрики считаются по валидным ответам с явным покрытием. В FP0 входят только уверенно отрицательные эталоны по текущему тексту протокола; остальные отрицательные с пометкой остаются в F2-session.

Принадлежность дополнительно проверяется строгим совпадением всех спанов и их групп с точностью до переименования локальных ID персон; неизвестные владельцы не образуют общую персону. Это диагностический счётчик, а не изолированная pairwise-метрика линковки. Ответы и рассчитанные алерты хранятся отдельно; модель сама не назначает эталонную причину алерта.

## Проверки реализации

`python -X utf8 -m unittest discover -s tests` — **170 тестов прошли**. Добавленные проверки подтверждают переход к следующей сессии после тайм-аута без повторного запроса, остановку на HTTP 429 даже в таком режиме, протокол раннего/позднего алерта и независимость группировки от названий локальных ID. Проверка синтаксиса и `git diff --check` также прошли. Это проверки кода, а не качество внешних моделей.

## Результаты завершённых прогонов

Все числа таблицы воспроизводятся командой сравнения с `--check` выше; типы технических ошибок можно проверить через `python -X utf8 tools/summarize_annotation_runs.py data/experiments/radeon/2026-11-19-comparison-gemma-01 data/experiments/radeon/2026-11-19-comparison-qwen-01`.

| Показатель | Gemma-4-31B-IT | Qwen3.8-27B |
|---|---:|---:|
| Запросов | 10 | 10 |
| Валидных ответов | 8 | 2 |
| Тайм-аутов, полного ответа нет | 2 | 8 |
| Exact-извлечение TP / FP / FN на валидных ответах | 23 / 0 / 0 | 3 / 0 / 0 |
| Спаны и группировка полностью совпали с авторским эталоном | 8 / 8 | 2 / 2 |
| F2-session TP / FP / FN / TN | 4 / 0 / 0 / 4 | 1 / 0 / 0 / 1 |
| F2-timely TP / FP / FN / TN | 4 / 0 / 0 / 4 | 1 / 0 / 0 / 1 |
| Исходные флаги модели совпали с эталоном | 3 / 8 | 1 / 2 |
| Флаги после обработчика совпали | 8 / 8 | 2 / 2 |

На валидных ответах извлечение и обе F2 равны 1, но эти результаты условны относительно покрытия и авторского эталона. У Gemma оценены четыре положительных и четыре отрицательных случая; у Qwen только один положительный и один отрицательный. Все имеющиеся offset равны нулю. FP0 у Gemma — 0/2 уверенно отрицательных, у Qwen — 0/1. Нулевые FP/FN не означают успешную обработку всего набора.

Gemma не ответила на `separate_owners` и `red_unknown_example`. Qwen ответила только на `clean` и `fi_email`. Все отсутствующие ответы — `TimeoutError`, а не отказ формата или доказанная ошибка аннотации. Из-за разного покрытия ранжировать качество моделей по этим F2 нельзя. Облако вернуло aliases `self-dploy/Gemma-4-31B-IT` и `self-dploy/Qwen3.8-27B`; конкретные ревизии весов не подтверждены.

Содержательный найденный разрыв — [исходные и вычисленные флаги неуверенности](../insights/2026-11-19-model-flags-and-processed-flags.md). Модели не поставили часть исторических пометок недостатка статистики; обработчик их добавил без изменения исходных ответов. На цифровых/словесных значениях, повторе и исправлении в полученных ответах Gemma расхождений с эталоном нет. Для разных владельцев и красных маркеров качество в этом запуске не установлено.

Следующий шаг — проверка пользователем `sessions-for-review.md`, затем целевой отдельный прогон на неотвеченных сценариях при изменённых и явно зафиксированных условиях доступа. Результаты этого запуска не заменяются успешными повторами.

Ограничение последовательности: в этом офлайн-прогоне модель видела всю сессию. Расчёт F2-timely показывает совпадение моментов по её итоговой разметке, но не доказывает работу без будущего контекста. Для проверки онлайн-поведения создан отдельный [последовательный прогон пользовательских сообщений](2026-11-19-user-only-sequential-pilot.md).
