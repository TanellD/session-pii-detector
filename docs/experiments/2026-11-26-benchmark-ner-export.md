# Выгрузка только regex + GLiNER для бенчмарка

- Дата: 2026-11-26.
- Данные: `session-benchmark-2400-v5`; train, validation и test.
- База: `b6f75b8` плюс рабочие изменения; точные хеши фиксируются в identity.json и manifest.json выгрузки.
- Цель: сохранить предсказания экстракции для дальнейшего использования без линкера и риска.

```powershell
.venv-gliner/Scripts/python.exe -X utf8 tools/export_benchmark_ner.py --dataset data/experiments/session-benchmark-2400-v5-2026-11-26 --output data/experiments/benchmark-ner-only-2026-11-26 --reuse-run data/experiments/benchmark-validation-gemma-risk-2026-11-26
```

Каталог результата: `data/experiments/benchmark-ner-only-2026-11-26`.
`live-progress.md` и `status.json` обновляются во время обработки текстов.
В `train|validation|test/predictions.jsonl` каждая строка содержит сессию,
сообщения и объединённые спаны regex + GLiNER после RevisedAdapter v2, до
фильтрации сервисом. Сохраняются границы, тип, исходное значение, provenance,
доступный score, признак полноты обработки и причины неполноты.
Неразрешённые пересечения здесь могут сохраняться: это выход экстрактора.

Выгрузка не включает владельцев, эталонную разметку, риск и алерты. Эталон test
не используется для оценки или подбора; обрабатываются только входные тексты.
GLiNER использует прежний конфиг с порогом confidence 0.5. Входы, зависимости
и модель проверяются по хешам; совместимый кэш validation копируется отдельно.
Новые результаты сохраняются по текстам, поэтому повтор той же команды после
остановки продолжает работу. Не запускать одновременно два экспортера одного каталога.

Проверка перед запуском полного экспорта: тот же скрипт с `--splits validation`
успешно выгрузил сохранённые результаты без нового инференса. При полном запуске
манифест заменяется окончательным составом только после завершения; до этого
состав готовых частей следует смотреть по файлам и status.json.

Это сохранение предсказаний, не замер качества. Данные остаются вне git.
