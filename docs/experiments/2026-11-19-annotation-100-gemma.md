# Сто синтетических сессий: уточнённая инструкция и последовательная Gemma

- Дата / автор: начат 2026-11-19, продолжен 2026-11-20; команда проекта.
- Связано: PR #44; продолжение [проверки русских префиксов CONFIDE](2026-11-19-russian-session-dataset-gemma-review.md).
- Гипотеза: явные правила для обобщённой профессии, литературных персонажей, притяжательных форм и точных вхождений уменьшают неоднозначность предварительной разметки.

## Настройка

- Базовый коммит: `b60fa67`; инструменты и уточнения поставляются вместе с этим отчётом.
- Схема: `annotation-mvp-v2`; политика алерта `2026-11-18-working-v2`, без изменения достаточных правил.
- Данные: `data/experiments/annotation-100-2026-11-19/`. Все сведения синтетические; адреса и имена придуманы, контакты используют нулевые номера и `example.invalid`, документы — нулевые суррогаты формата.
- Набор формируется до API-запуска: 100 сессий, 210 пользовательских сообщений, 225 эталонных сущностей, 45 сессий с алертом. Воспроизведение чисел: `python -X utf8 tools/build_annotation_100.py --output data/tmp/annotation-100-reproduction` (нужен новый каталог).
- Это 20 семейств по 5 вариантов: чистые сообщения, общая и личная профессия, литературные персонажи, разговорные/падежные имена и повторы, притяжательные прилагательные, пары ФИ/ИО/ФО с контактом/адресом, ФИО без контакта, разные владельцы, служебные контакты, позднее раскрытие владельца, исправление, четыре красных класса, демографические признаки, словесные числа и маски.
- Авторский эталон составлен текущей LLM до запуска. Независимая человеческая проверка ожидается. Набор предназначен для контролируемой проверки правил, а не для оценки качества на естественных диалогах. Пять вариантов одного семейства не являются независимыми сценариями.
- Модель: `Gemma-4-31B-IT`, Radeon Cloud API, temperature=0, max_tokens=4000, timeout=120 с, пауза 3 с. Аппаратная конфигурация провайдера не известна.

```powershell
python -X utf8 tools/build_annotation_100.py
python -X utf8 tools/run_sequential_annotation.py --input data/experiments/annotation-100-2026-11-19/sessions.json --output data/experiments/radeon/2026-11-19-annotation-100-gemma-02 --model Gemma-4-31B-IT --timeout 120 --max-tokens 4000 --delay 3
python -X utf8 tools/report_annotation_100.py
python -X utf8 tools/report_annotation_100.py --check
```

Для уже работающего прогона `python -X utf8 tools/report_annotation_100.py --wait` ожидает завершения и автоматически сохраняет итоговые файлы, не отправляя новых API-запросов. В этом эксперименте отчёт первоначально сохранён этим режимом. Для другого каталога прогона передайте `--run`.

Повторные запуски требуют новых выходных каталогов. Эталон не включается в API-запросы. На каждом шаге видны только пользовательский префикс и прежнее предсказание этой модели; прежние спаны и владельцы заморожены. Системная инструкция фиксируется в начале запуска и сохраняется с каждым запросом. Её хеш позволяет отличить фактический промпт от последующих редакционных правок документации.

Сохранённый `comparison.fp0` по существующей реализации показывает только уверенно отрицательное подмножество: 0 ложных алертов на 20 таких сессий. Это не знаменатель всех 55 отрицательных сессий; область этого поля явно указана в сводке. Неуверенные отрицательные сессии остаются отрицательными по рабочей политике и не считаются ошибками запроса.

Основной запуск занял примерно 49,48 минуты, включая паузы и локальную обработку. Воспроизведение длительности:

```powershell
python -X utf8 -c "import json,pathlib,datetime; d=json.loads(pathlib.Path('data/experiments/annotation-100-2026-11-19/overview.json').read_text(encoding='utf-8')); print((datetime.datetime.fromisoformat(d['finished_at'])-datetime.datetime.fromisoformat(d['started_at'])).total_seconds()/60)"
```

Результаты находятся в локальных `overview.json`, `overview.md`, `gemma-annotations-for-review.md`. Последний файл содержит все пользовательские сообщения, авторские спаны и предсказания Gemma. Производные файлы можно явно обновить `python -X utf8 tools/report_annotation_100.py --refresh-derived`: исходные сообщения, эталон и API-ответы эта команда не меняет.

Отчёт сравнивает точные типизированные спаны, группировку по людям, первый момент и основание алерта, исходные флаги модели и флаги после обработчика отдельно. Публикуются покрытие, ошибки, результаты по семействам и длительность запросов, измеренная монотонным таймером. Сессионные и временные метрики рассчитываются существующим `tools/compare_annotation_models.py` по [протоколу](../kb/metrics.md). Сессии с ошибкой не превращаются в отрицательные метки и не входят в условные метрики валидных ответов. Неуверенные валидные сессии остаются в бинарной оценке согласно текущей политике.

Предыдущее состояние содержит уже обработанные флаги: совпадение позднего флага модели не доказывает самостоятельное распознавание недостатка статистики. Измеренное время включает очередь провайдера и сеть; оно не характеризует скорость собственной установки модели.

Набор проверяет извлечение, владельцев, качественные и красные правила. Он не валидирует все численные формулы и поиск адресов. В частности, [«бухгалтером» не сопоставляется текущим точным словарём с ОКЗ](../insights/2026-11-20-inflected-occupation-lookup.md), поэтому в семействе `employment` сохраняется недостаток статистики. Совпадение алертов с эталоном на одном обработчике не является независимой проверкой правильности статистических расчётов.

Первая попытка `.../2026-11-19-annotation-100-gemma-01` остановлена после сетевых `URLError`, без ответов модели. Она сохранена отдельно и не считается свидетельством качества Gemma. Повторный запуск с доступом к сети получает ответы API.

## Анализ ошибок

Во время прогона пользователь подтвердил: строка «ИНН физического лица: …» без конкретного человека остаётся с `person_id=null`; красный алерт не зависит от этой принадлежности. Авторский эталон уже содержал `null`, поэтому не изменялся. Явный пример добавлен в рабочую инструкцию для следующих запусков; весь основной API-прогон использовал первоначально зафиксированный промпт. Поздние редакционные уточнения строки таблицы `is_example` также не подменяют сохранённый промпт.

Все пять расхождений группировки относятся к этому семейству: `synthetic-002`, `synthetic-010`, `synthetic-015`, `synthetic-026`, `synthetic-086`. Модель выделила ИНН правильно, но создала персону без достаточного основания. На первый алерт это не повлияло. В остальных семействах спаны и группировки совпали полностью. Падежные формы и точные повторы имени, притяжательные прилагательные, общая профессия и литературный персонаж прошли контролируемую проверку.

Разбирать прежде всего отказы валидации, пропущенные и лишние сущности, смешение владельцев, ранние/поздние алерты, расхождения флагов литературных и учебных ситуаций. Исходные ответы не исправляются и не заменяются эталоном. Файлы с полными текстами и спанами остаются только в игнорируемом `data/`.

## Отдельная проверка уточнения владельца ИНН

После подтверждения пользователем явного `null` выполнен отдельный повтор того же семейства. Исходная сотня, её эталон и ответы не изменялись. Подготовка и API-запуск:

```powershell
python -X utf8 tools/subset_annotation_family.py --source data/experiments/annotation-100-2026-11-19 --output data/experiments/annotation-100-inn-clarification-2026-11-20 --family inn
python -X utf8 tools/run_sequential_annotation.py --input data/experiments/annotation-100-inn-clarification-2026-11-20/sessions.json --output data/experiments/radeon/2026-11-20-annotation-100-inn-gemma-01 --model Gemma-4-31B-IT --timeout 120 --max-tokens 4000 --delay 3
```

Все пять сессий завершены: десять валидных шагов, пять точных спанов и правильных группировок, во всех пяти сохранён красный алерт на втором сообщении. Неподтверждённые владельцы остались `null`. Это повтор знакомых шаблонов с уточнённой инструкцией, а не независимый набор; он не добавляется к знаменателю основной сотни.

Воспроизведение сохранённых итогов без API:

```powershell
python -X utf8 tools/compare_annotation_models.py --gold data/experiments/annotation-100-inn-clarification-2026-11-20 --runs data/experiments/radeon/2026-11-20-annotation-100-inn-gemma-01 --output data/experiments/annotation-100-inn-clarification-2026-11-20/model-comparison.json --check
python -X utf8 tools/audit_sequential_annotation.py --source data/experiments/annotation-100-inn-clarification-2026-11-20 --run data/experiments/radeon/2026-11-20-annotation-100-inn-gemma-01 --output data/experiments/annotation-100-inn-clarification-2026-11-20/sequential-audit.json --check
```

## Вывод и следующий шаг

Уточнения задают проверяемые решения по обнаруженным спорным случаям. Контролируемый набор пройден с расхождениями владельца ИНН; отдельный повтор подтвердил новую формулировку на этих же шаблонах. Сравнение с прежними десятью префиксами не является контролируемым A/B, потому что набор данных другой. После проверки шаблонов нужна независимая человеческая выборка и расширение естественных синтетических диалогов.

Проверки кода: `python -X utf8 -m unittest discover -s tests` — 184 теста прошли. Отдельно выполнена воспроизводимая сверка всей сотни `python -X utf8 tools/report_annotation_100.py --check`; она проверяет фактические префиксы всех запросов, отсутствие эталона в них и неизменность прежних сущностей. Секреты и локальные артефакты остаются вне Git.
