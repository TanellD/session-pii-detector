# Примеры семейств сценариев средней сложности

- Дата: 2026-11-26; ветка интеграции, PR #47.
- Цель: подготовить по три читаемых примера каждого семейства [политики генерации](../data/synthetic-session-generation-policy.md) с авторской разметкой и проверкой первого алерта.
- Данные: `medium-scenario-examples-33-v1`, `data/experiments/medium-scenario-examples-33-2026-11-26/`.
- Основа кода: `2b48014` плюс `tools/build_medium_scenario_examples.py` и текущие локальные изменения документации; хеш генератора и исходного плана сохраняется в манифесте.
- Конфиг: `configs/annotation-estimator-policy.json`, рабочая версия `2026-11-22-working-v3`; версии и хеши справочников — в manifest.json.
- Железо: локальный CPU. Генерация детерминированными слотами в отдельно написанных авторских диалогах; вызовов сервиса и LLM нет.

## Воспроизведение

Из корня worktree; выходной каталог должен быть новым:

```powershell
.\.venv-gliner\Scripts\python.exe -X utf8 tools/build_medium_scenario_examples.py --plan data/experiments/medium-scenario-examples-33-plan-2026-11-26/authored-plan.json --output data/experiments/medium-scenario-examples-33-rebuild
```

План и данные хранятся вне git. Команда требует доступного исходного плана и подготовленных локальных справочников калькулятора. Это не генерация произвольного размера из одного промпта: сюжеты авторские, код материализует значения и разметку.

## Результат подготовки

Числа воспроизводятся указанной командой и публикуются в manifest.json:

| Показатель | Значение |
|---|---:|
| Семейства сценариев | 11 |
| Примеры на семейство | 3 |
| Диалоги | 33 |
| Пользовательские сообщения | 165 |
| Размеченные упоминания | 175 |
| Сессии с алертом калькулятора | 20 |
| Отрицательные с недостатком статистики на последнем шаге | 10 |

Каждый диалог содержит пять сообщений. Чистые отрицательные контроли не содержат личных сведений; остальные вводят двух участников. Средняя сложность достигается переключением контекста, разнесёнными атрибутами, повтором, исправлением, общим контактом или различением служебного и личного использования. Для чистых контролей сложность относится к развитию обращения, а не к линковке отсутствующих сущностей.

Каждый вариант имеет отдельный сюжет, а не только замену значений. Все контакты и документы синтетические. Для ИНН, СНИЛС и карт checksum проверяется локально; неверный СНИЛС, маска карты и `abc12` оставлены отрицательными контролями без полных документных/телефонных спанов. Существование документов не проверяется и не утверждается.

## Разметка и проверка

Границы и владельцы материализуются из авторских меток в плане, затем проверяются существующим `annotation_contract.validate`. Общий личный атрибут получает список владельцев; неизвестный остаётся `null`, служебность контакта хранится отдельно. Старые неизвестные упоминания после уточнения не перепривязываются.

Алерты вычисляются существующим калькулятором. Для каждого сценария результат дополнительно сравнивается с ожидаемым автором контрольным моментом; несовпадение останавливает сборку. Веса сервиса не используются. Адресные признаки подтверждены автором: квартира проживания, среднее из рабочей политики. Сохранён адресный sidecar с хешем итоговой аннотации. Вымышленным городам население не назначается.

`examples-for-review.md` содержит все диалоги, таблицы сущностей, владельцев, первый алерт и итоговую неопределённость. `sessions.json` содержит только исходные сообщения. `gold.json` — минимальные аннотации, `snapshot.json` — аннотации вместе с ожидаемыми алертами и служебными контактами. `calculator-assessments.json` сохраняет причины и историю префиксов; `address-enrichment.json` — подтверждения типа жилья; `generation-plan.json` — использованный авторский план.

## Ограничения и следующий шаг

Разделение — development_only: примеры предназначены для чтения и ревью новой политики генерации, а не для независимого подтверждения качества. Сложность назначена по механике сценария, не измерена по ошибкам модели. Авторская разметка и проверка калькулятором не заменяют независимое ревью. Неуверенные отрицательные метки означают недостаток основания по рабочей политике, а не доказанную безопасность. После ревью можно отдельно запланировать модельный прогон; в этой подготовке метрики сервиса не измерялись.
