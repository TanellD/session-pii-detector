# Перенос ревизии адаптера на авторский набор по сценариям Андрея

- Дата / автор: 2026-11-25, Москва; команда проекта.
- Статус: сравнение извлечения завершено; отдельный прогон полного сервиса с Gemma запущен.
- Гипотеза: замороженная ревизия `adapter-candidate-v1` улучшает извлечение на другом банке формулировок, без дальнейшей подстройки правил.

## Настройка

- Источник: `data/experiments/andrey-scenarios-500-2026-11-23/`, версия `andrey-original-scenarios-500-2026-11-23`.
- Это авторские новые варианты реплик по исходным сценариям Андрея, а не неизменённые исходные сообщения Андрея. Спаны и владельцы взяты из `gold.json`; Qwen/Gemma-разметка не используется. Независимая человеческая проверка авторского эталона ещё не выполнена.
- Выбор: первые 250 записей после сортировки ID, `andrey-500-0001`–`andrey-500-0250`. Присутствуют все 16 исходных семейств. Снимок содержит 918 сообщений, 644 спана и 120 положительных сессий по сохранённому авторскому первому алерту. Все числа воспроизводит команда подготовки ниже.
- Авторский первый алерт взят из `gold-assessments.json`, поле `author_expected_first_alert`, и сохранён в снимке отдельно от входов модели. Эталон не подгоняется под веса сервиса.
- Хеши `gold.json`, манифеста, плана, авторских оценок и журнала алертов сохранены в `snapshot.json`. Эталонные спаны/владельцы копируются без исправлений.
- Baseline: исходные GLiNER + regex; `benchmarks/pii_smoke/config.json`, локальные подготовленные веса `outputs/gliner-prepared`, CPU, 2 потока, порог 0,5.
- Ревизия: `src/session_pii/adapter_revision.py`, SHA-256 `82547bfed89d08459211a4a309edb1740df49318988ce4e9d21c0dbefe96ff73`. Хеш проверяется до и после эксперимента. Веса и порог одинаковы, baseline и ревизия используют одни модельные предсказания.
- Коммит-основа: `2172a364f5259ad7bcfd0066caba8a8004fac046` плюс текущие незакоммиченные изменения; хеш оценщика и окружение сохраняются в `results/environment.json`.

## Воспроизведение

Из корня worktree `outputs/session-adapter-integration`:

```powershell
.\.venv-gliner\Scripts\python.exe -X utf8 tools/select_andrey_adapter_250.py
.\.venv-gliner\Scripts\python.exe -X utf8 tools/evaluate_adapter_revision.py --snapshot data/experiments/andrey-adapter-250-2026-11-25/snapshot.json --recordings data/experiments/andrey-adapter-250-2026-11-25/ner --output data/experiments/andrey-adapter-250-2026-11-25/results --record-fresh
```

Подготовка требует отсутствующего снимка. После первого инференса повторить вторую команду без `--record-fresh`: результаты воспроизводятся из сохранённых предсказаний без загрузки модели.

## Результаты

Полные результаты сохранены в `data/experiments/andrey-adapter-250-2026-11-25/results/summary.json` и `report.md`. Числа таблиц воспроизводятся командой оценки выше без `--record-fresh`. Нейронный инференс выполнен на 556 уникальных текстах; ревизия до и после прогона имеет тот же зафиксированный хеш.

Exact type-aware micro до сервисных фильтров, все 250 сессий:

| Метрика | Baseline | Ревизия |
|---|---:|---:|
| TP / FP / FN | 443 / 314 / 201 | 557 / 177 / 87 |
| Precision | 58,52% | 75,89% |
| Recall | 68,79% | 86,49% |
| F2 | 66,46% | 84,14% |
| Завершено после сервисных фильтров | 186 | 218 |
| Ошибки контракта | 64 | 32 |

После фильтров на одинаковом успешном срезе из 186 сессий:

| Метрика | Baseline | Ревизия |
|---|---:|---:|
| TP / FP / FN | 266 / 185 / 168 | 377 / 92 / 57 |
| Precision | 58,98% | 80,38% |
| Recall | 61,29% | 86,87% |
| F2 | 60,81% | 85,49% |

У ревизии на её собственном успешном срезе из 218 сессий Precision=81,12%, Recall=87,55%, F2=86,18%. Это другой охват, поэтому для сравнения версий используется общая таблица. Невалидные сессии не становятся отрицательными примерами и не скрываются за высокой метрикой успешного подмножества.

Этот этап не измеряет линкер и алерты: `StubLinker` нужен только для проверки контракта Pipeline. Полный сервис с исправленным NER и Gemma оценивается отдельным прогоном на том же снимке; live-отчёт — `data/experiments/andrey-gemma-revised-250-2026-11-25/live-progress.md`.

## Анализ ошибок

- Все 32 оставшиеся ошибки ревизии — `Unresolved cross-type overlap`, пара EMAIL+ORGANIZATION. GLiNER выделяет `neighborhoodclub` внутри `neighborhoodclub.2@example.invalid`, либо `trainingdiscount` внутри `trainingdiscount.12@example.invalid`, как организацию. EMAIL проходит проверку, но правило разрешения таких пересечений в сервисе отсутствует. Диагностика: `.\.venv-gliner\Scripts\python.exe -X utf8 tools/profile_andrey_adapter_errors.py`, результат `results/error-profile.json`. Правило по найденной ошибке не менялось.
- Адреса: ревизия находит все 59 эталонных спанов без лишних адресов против полного пропуска baseline. При этом исчезают 59 лишних вложенных GEOGRAPHY.
- FIRST_NAME: 84 правильных из 126, остаются 42 пропуска. LAST_NAME: 46 из 57; PATRONYMIC: 35 из 39. Форма синтетического имени и контекст всё ещё влияют на типизацию.
- Общий PERSON: 88 лишних спанов при отсутствии положительных PERSON в эталоне. Это расхождение с более конкретной типизацией и ложные выделения, а не доказательство того, что класс PERSON нужно выключить.
- OCCUPATION: только 2 правильных из 28; ORGANIZATION: 15 правильных, но 66 лишних. Эти классы ревизия существенно не улучшает.

## Вывод

Прирост извлечения переносится на авторский набор другого источника формулировок. При этом сервисная обработка всё ещё завершается ошибкой на существенной части среза из-за вложенной организации в email. Высокая метрика извлечения не заменяет проверку покрытия и полного сервиса. Правила сохранены без изменений; исправление нового конфликта следует оценивать отдельной версией.

## Ограничения

Это другой источник формулировок, но по-прежнему контролируемые банки реплик, знакомые концепции сценариев и синтетические значения. Проверка не считается независимым человеческим benchmark. Предыдущая работа уже использовала материалы Андрея в интеграции.

На выбранном срезе есть `first_name`, `last_name`, `patronymic`, `sex`, `age`, `occupation`, `organization`, `geography`, `address`, `phone`, `email`, `passport`; отсутствуют положительные `person`, `individual_inn`, `snils`, `bank_card`. В исходных сценариях неверные checksum сохранены как отрицательные примеры по политике источника. Результат не подтверждает полноту этих четырёх классов.

Нельзя объединять эту метрику с предыдущими 250 сессиями без отдельного указания источников и покрытия. Правила не меняются по ошибкам текущего среза.
