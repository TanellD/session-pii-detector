  диагностические шаблоны первого корпуса, но не создают независимый benchmark.


объединённых данных.

## Авторская разметка и происхождение

Новые реплики составлены в текущей работе в явных авторских банках формулировок.
Сценарии и роли людей взяты из материалов Андрея; новые точные спаны рассчитаны
по новым текстам. Старые позиции и прежние алерты не копировались. Это авторская
разметка до внешнего вызова, но не слепая независимая проверка исходного сценария.

Сохранены `scenario-plan.json`, `sessions.json`, `gold.json`,
`gold-prefixes.json`, `gold-assessments.json`, `author-alert-ledger.json`,
`sessions-for-review.md`, `generation-prompt.md` и манифест с хешами источников.
Роли/типы наследуются из сценария, границы проверяются на новых репликах,
первый алерт явно задан автором по ТЗ и сверяется обработчиком без весов сервиса.
Статистические флаги по-прежнему вычисляет общий калькулятор; его корректность
совпадением с этими же результатами не доказывается.

Варьируются обращения, просьбы, порядок ФИО внутри реплики и нейтральные
сообщения. Смысл задачи и последовательность раскрытия атрибутов остаются
исходными. Это комбинации авторских формулировок, а не свободная генерация
внешней LLM и не 500 независимо придуманных сюжетов.

Все значения синтетические: вымышленные имена/организации/адреса, почта
`example.invalid`, телефон с нерабочим кодом 000 и нулевые документные суррогаты.
Данные и полные ответы API находятся вне Git. Проверка человеком ожидается.

## Внешняя проверка

Qwen доступна по короткой пробе, первый валидный шаг второго корпуса получен.
Второй проход запущен одним потоком, пока Gemma продолжает первый. Модель
получает только текущий пользовательский префикс и собственную предыдущую
разметку; авторский gold и будущие реплики не передаются. Ранее размеченные
спаны и неизвестные владельцы заморожены.

Пример запуска в **новый** каталог:

```powershell
python -X utf8 tools/run_annotation_batch.py --source data/experiments/andrey-scenarios-500-2026-11-23 --output data/experiments/radeon/andrey-500-qwen-new --model Qwen3.8-27B --workers 1 --env-file C:\Users\данил\Desktop\session-pii\.env
```

Текущий второй прогон: `data/experiments/radeon/andrey-500-qwen-2026-11-23/`.
Текущий первый: `data/experiments/radeon/annotation-1000-gemma-2026-11-23-v2/`.
Оба ещё требуют завершения. Первый проход Gemma v2 остановился после тайм-аутов
и HTTP 429. Завершённые 5 сессий сохранены; оставшиеся 995 выделены в новый
`data/experiments/radeon/annotation-1000-gemma-2026-11-23-recovery/batches/`.
Числа воспроизводятся по `recovery-manifest.json` командой подготовки:

```powershell
python -X utf8 tools/prepare_annotation_recovery.py --source data/experiments/annotation-1000-2026-11-23 --previous data/experiments/radeon/annotation-1000-gemma-2026-11-23-v2 --output data/tmp/annotation-recovery-new
```

В продолжении тайм-аут увеличен до 300 секунд; временные сетевые ошибки,
HTTP 429 и серверные ошибки повторяются ограниченное число раз с паузой.
Валидационные ошибки модели не исправляются. Каждый повторный API-вызов
учтён отдельно; один логический запрос может иметь несколько попыток.
Ошибки API не означают отрицательную метку.
Сырые ответы не исправляются под авторский эталон; диагностика неверных checksum
и расхождения сохраняются отдельно.

Разные модели не образуют контролируемое сравнение качества генераторов.
Чтобы сравнивать именно согласие модели с автором, потребуется общий
разметчик на сопоставимом срезе обоих наборов.

## Результаты сравнения данных

Воспроизведение всех чисел таблицы и диагностики, без API:

```powershell
python -X utf8 tools/compare_synthetic_corpora.py --first data/experiments/annotation-1000-2026-11-23 --second data/experiments/andrey-scenarios-500-2026-11-23 --output data/tmp/corpus-comparison-new
```

| Показатель | Первый | По Андрею |
|---|---:|---:|
| Сессии | 1000 | 500 |
| Семейства | 40 | 16 |
| Сообщения | 2855 | 1821 |
| Среднее сообщений в сессии | 2,855 | 3,642 |
| Различные тексты после маскирования значений | 360 | 500 |
| Сессии с несколькими людьми | 150 | 94 |

| Сессии с неизвестным владельцем | 150 | 31 |

Маскирование заменяет авторские спаны их типами, удаляет номер заявки,
нормализует числа, регистр и пунктуацию. Оно отделяет изменение значений от
изменения формулировок. Это диагностика лексических повторов, не утверждённая
метрика реалистичности и не число независимых сценариев.

У второго нет положительных спанов `person`, `individual_inn`, `snils`,
`bank_card`: исходные сценарии Андрея используют неверные checksum, которые
по текущим правилам исключены из gold. Отрицательные документы остаются в
тексте. Первый набор дополняет эти пробелы.

Полных совпадений нормализованных текстов между источниками не обнаружено.
При этом есть 4 общих шаблона последовательности типов и владельцев;
188 сессий второго набора используют такие структуры. Это сигнал для проверки
смыслового пересечения, не автоматический критерий удаления всех этих примеров.

## Анализ реалистичности и пригодности

Второй набор ближе к прикладным обращениям: восстановление билета, запись на
обучение, перенос посылки, возврат товара, выгрузка операций и восстановление
доступа. У каждой сессии есть задача, а сведения появляются в связи с ней.
Формулировки разнообразнее первого набора по описанной диагностике.

Оба набора остаются контролируемой синтетикой: короткие пользовательские
последовательности, явные слова «мой», «фамилия», «личный», регулярный порядок
фактов, вымышленные имена и одинаковые маркеры тестовых контактов. Подтверждений
соответствия распределению реальных обращений нет. Ответы помощника,
длинные разговоры, систематические опечатки, обрывки, неоднозначные местоимения,
цитаты/пересылки и переходы между задачами не покрыты достаточно.
Наличие этих пробелов не означает автоматического расширения текущего MVP:
нужно различать поддерживаемые случаи и проверку корректного воздержания.

Для разработки сервисного MVP материал полезен: извлечение и фильтры,
изолированные профили, совместная принадлежность, повторы, позднее уточнение,
коррекция и первый момент алерта. Он не подтверждает готовность к production
и не заменяет отдельные проверки идемпотентности, сброса, TTL, параллельных
запросов и задержки. Линкер в текущем сервисе остаётся заглушкой; gold-владельцев
нельзя выдавать ему на вход и затем считать линковку проверенной.

## Объединение

Схема, версия политики и ID совместимы. Можно создать общий пул разработки,
сохраняя источник, исходный сценарий, версию и статус проверки разметки.
Сами корпуса сейчас не объединяются автоматически.

Для честного теста требуется завершить LLM-проверку и разобрать расхождения,
после чего группировать варианты по исходному сценарию, близкие формулировки
и смысловые пересечения между источниками. Нельзя просто дописать первый
набор к development второго: его сценарии могут пересекаться с test Андрея.
Результаты двух источников нужно показывать отдельно даже при общем обучении.

## Состояние и следующий шаг

### Продолжение 2026-11-24

После повторяющихся сетевых ошибок старые процессы остановлены и их манифесты
зафиксированы с резервными копиями. Запущены новые очереди в
`data/experiments/annotation-resume-2026-11-24/{first,second}/batches/`.
Уже завершённые сессии исключены; новые очереди содержат только оставшиеся
сессии. Происхождение, команды воспроизведения чисел и проверки сохранности —
в [заметке о перезапуске](../insights/2026-11-24-annotation-checkpoint-restart.md).
Наблюдатель восстановил прежние каталоги из `watch-state.json` и учитывает
прежние и новые результаты совместно. После перезапуска получен валидный
новый шаг Gemma; полная внешняя проверка ещё не завершена.

Статическое сравнение сохранено в `data/experiments/corpus-comparison-1000-500-2026-11-23/`.
Фоновый наблюдатель обновляет `llm-comparison-status.json` и `combined-review.md`
и после окончания обоих прогонов собирает отчёты без новых API-запросов.
Прогресс можно воспроизвести:

```powershell
python -X utf8 tools/watch_corpus_comparison.py --first-run data/experiments/radeon/annotation-1000-gemma-2026-11-23-v2 --first-run data/experiments/radeon/annotation-1000-gemma-2026-11-23-recovery/batches --second-run data/experiments/radeon/andrey-500-qwen-2026-11-23 --comparison data/experiments/corpus-comparison-1000-500-2026-11-23
```

Наблюдатель также запущен с `--watch --recover-failures`: он сохраняет
`watch-state.json` с каталогами дальнейших повторов, если они понадобятся.
В повтор попадают только сессии без завершённой разметки во всех прежних
попытках. Частично неудачная сессия начинается с первого сообщения в новом
каталоге; прежние запросы, ответы и успешные завершённые сессии не меняются.
Число дополнительных проходов ограничено. Если лимит попыток исчерпан,
непроверенное покрытие остаётся явно указанным, а не объявляется завершённым.

Авторская разметка и структурное сравнение готовы; полная внешняя проверка и
разбор её расхождений ещё не завершены. Проверки кода:

```powershell
python -X utf8 -m unittest discover -s tests -p test_andrey_500.py
python -X utf8 -m unittest discover -s tests -p test_annotation_recovery.py
python -X utf8 -m unittest discover -s tests
```
