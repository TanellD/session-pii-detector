- Дата / автор: 2026-11-23; команда проекта.
- Issue: продолжение интеграции адаптера, совместных владельцев и LLM-разметки.
- Гипотеза: расширенный контролируемый набор обнаруживает ошибки принадлежности,
  повторов, фильтрации номеров и накопления между сообщениями.

## Настройка

- Базовый коммит: `2172a36`; новые инструменты поставляются с этим отчётом.
- Данные: `data/experiments/annotation-1000-2026-11-23/` в рабочей копии
  `outputs/session-adapter-integration`.
- Версия: `annotation-1000-ownership-v2-2026-11-23`.
- Политика: `2026-11-22-working-v3`; `document_checksum=extraction_filter`.
- Схема: `annotation-mvp-v2`, совместная принадлежность `ownership-v2`.
- Проверяющая модель: alias `Gemma-4-31B-IT`, Radeon Chat Completions;
  фактический ID сохраняется в каждом ответе. Ревизия весов провайдером не доказана.
- Runtime: локальный Python; модель работает на оборудовании провайдера.
- Температура нулевая, максимум ответа 4000 токенов, тайм-аут 120 секунд.

Подготовка из корня указанной рабочей копии:

```powershell
python -X utf8 tools/build_annotation_1000.py --output data/experiments/annotation-1000-2026-11-23
```

Команда воспроизводит: 1000 сессий, 2855 пользовательских сообщений, 2075 спанов,
375 сессий с авторским ожидаемым алертом; 40 семейств по 25 вариантов.
Выходной каталог должен быть новым. Исходные данные и ответы находятся вне Git.

## Авторская разметка

Разметка составлена до вызова внешней модели, через явный авторский список
фрагментов, типов и владельцев в генераторе. Точные цитаты материализуются в
Unicode-границы. Сохранены `gold.json`, `gold-prefixes.json`, `gold-assessments.json`,
`sessions-for-review.md`, `generation-prompt.md` и манифест происхождения.

Ожидаемый первый алерт задан автором по правилам ТЗ и проверен обработчиком;
веса runtime-сервиса для назначения gold не используются. Это не независимая
проверка самого обработчика: численные оценки и часть кейсовых флагов получены
через общий калькулятор. Проверка человеком ожидается.

Покрытие включает раздельных и совместных владельцев, неизвестную принадлежность,
позднее уточнение с новым упоминанием, ФИО в нескольких сообщениях, повторы,
исправления, служебные контакты, вложенные имена, PERSON, положительные и
отрицательные checksum, российские телефоны, маски и исключённые классы.
Документы — нулевые суррогаты; телефоны используют нерабочий код 000;
почта — домен example.invalid. Исследовательские кеши реальных имён не копируются
в корпус и не передаются модели.

## Внешняя проверка

Первый прогон остановлен после HTTP 429 и HTTP 400 до получения валидных аннотаций.
Обнаружена и исправлена [несовместимость uniqueItems с xgrammar](../insights/2026-11-23-xgrammar-shared-owners.md).
Прежний прогон не перезаписывается.

Повтор подготовлен и запущен одним потоком. Пример команды воспроизведения
для **нового** выходного каталога; значение ключа не передаётся аргументом:

```powershell
python -X utf8 tools/run_annotation_batch.py --source data/experiments/annotation-1000-2026-11-23 --output data/experiments/radeon/annotation-1000-gemma-new --workers 1 --env-file C:\Users\данил\Desktop\session-pii\.env
```

Текущий повтор: `data/experiments/radeon/annotation-1000-gemma-2026-11-23-v2/`.
Сессии независимы; внутри каждой модель видит только пользовательский префикс
и собственную прежнюю разметку. Gold не передаётся. Старые спаны и владельцы
заморожены. Общие владельцы сохраняются списком, а не несколькими копиями спана.

## Результаты

Внешний проход начат, первые валидные ответы получены. Полные метрики качества
до завершения не заявляются. Актуальное покрытие, ошибки и расхождения:

```powershell
python -X utf8 tools/run_annotation_batch.py --output data/experiments/radeon/annotation-1000-gemma-2026-11-23-v2 --report-only
```

Команда создаёт `overview.json` и `overview.md` без новых API-запросов.
В конце фонового запуска эти файлы создаются автоматически.
У завершённых батчей отдельно сохраняются `comparison.json` и
`protocol-audit.json`. Сравнение использует существующий модуль оценки по
[протоколу метрик](../kb/metrics.md). Сбой API не становится отрицательной меткой.
Невалидные checksum в ответе модели вынесены в отдельный список, не удаляются
из исходных ответов и не принимаются как проверенный gold.

## Анализ ошибок

До завершения сохраняются только диагностические ошибки транспорта и текущие
расхождения. Принудительное исправление ответа под авторскую разметку не
выполняется. Подробные тексты, исходные ответы и все спаны остаются в `data/`.

## Вывод и следующий шаг

Авторский корпус готов; независимый модельный проход требует завершения и
разбора расхождений. Варианты внутри семейства зависимы: число сессий не означает
такое же число независимых сценариев. Нельзя случайно делить почти одинаковые
варианты между обучением и тестом; нужен отложенный набор иных сценариев.

Проверки реализации:

```powershell
python -X utf8 -m unittest discover -s tests -p test_annotation_1000.py
python -X utf8 -m unittest discover -s tests
```

Первая команда: 6 проверок. Полный набор: 229 тестов, один пропущен.
