# Эксперимент: план выгрузки миллиона записей участников VK

- Дата / автор: 2026-11-16, команда проекта.
- Основание: пользователь попросил увеличить выгрузку до миллиона записей.
- Гипотеза: увеличение числа наблюдений даст больше повторяющихся ФИ для исследования зависимости частей.
- Статус на 2026-11-17: сбор остановился с кодом VK 9, полный план не завершён. Последующий запуск пользователя также получил код 9 и сетевой таймаут; дефект записи диагностики исправлен, см. [разбор](../insights/2026-11-17-vk-timeout-diagnostic-json.md). Анализ с `--wait-for-limit 1000000` был запущен ранее, но сам факт его запуска не доказывает готовность анализа. Завершение проверяется по `complete_plan` в отчёте и наличию всех страниц плана. Сам установленный лимит не означает, что записи уже получены.

## Настройка

- Источник: `groups.getMembers`, сообщество `vk`, сервисный токен из локального `.env`, API 5.199, `lang=ru`, версия обработки 2.
- Лимит: 1000000 запрошенных записей, страницы по 1000; детерминированные смещения по исходному диапазону `id_asc`. Новая сетка не обязана включать все прежние смещения. Совпадающие актуальные страницы используются повторно, остальные прежние файлы не удаляются.
- Фильтр и дедупликация: прежние; совпадающие ФИ разных аккаунтов сохраняются. Сырые строки, токены и ID в документацию и Git не попадают.
- План и отчёты предыдущей выборки сохранены в `data/private/name-dependence/vk-groups/vk/snapshots/limit-100000/`. Страницы всех планов находятся в общей локальной папке; хеши каждого завершённого анализа фиксируются в его отчёте.
- Коммит основы: `68b090e5db4664e3802e09a17976f45e1d7601bb`, изменения рабочего дерева.
- Среда: Windows, Python, CPU, стандартная библиотека.

## Команды воспроизведения

```powershell
# Сбор или продолжение: актуальные страницы пропускаются.
python -X utf8 tools/collect_vk_group_members.py --group vk --limit 1000000 --token-type service --download
# После завершения — офлайн-сводка и анализ:
python -X utf8 tools/collect_vk_group_members.py --group vk --limit 1000000
python -X utf8 tools/assess_vk_pair_sample.py --group vk
# Автоматически дождаться завершённого сбора и затем выполнить анализ:
python -X utf8 tools/assess_vk_pair_sample.py --group vk --wait-for-limit 1000000
# Прежний корпус доступен отдельно:
python -X utf8 tools/assess_vk_pair_sample.py --group vk --snapshot-limit 100000
```

## Критерии анализа

Повторяемость ФИ, распределение описательного отношения совместной частоты к произведению маргинальных, перестановочный фон внутри пола и проверка прежнего семейства сглаженных оценок на отложенных аккаунтах. Процедура описана в [предыдущем эксперименте](2026-11-16-vk-expanded-pair-sample.md).

Миллион записей не равен миллиону людей или миллиону принятых ФИ. Размер после фильтра и дедупликации устанавливается только по завершённому отчёту. Источник не содержит отчества и не подтверждает охват населения России. Правила разметки и коэффициенты основного калькулятора не меняются.

Ожидание анализа ограничено тремя часами и само не выполняет сетевых запросов. При отказе API коллектор останавливается, сохраняя успешные страницы; ожидающий процесс не считает неполную выгрузку завершённой. Отчёт ожидания и основной анализ содержат только обезличенные агрегаты.
