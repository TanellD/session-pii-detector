# Эксперимент: компактный MiniCPM как линкер владельцев

- Дата: 2026-11-25, Москва.
- Статус: полный прогон запущен; итоговые значения — в сохранённой сводке.
- Гипотеза: компактная текстовая LLM может назначать владельцев с приемлемой потерей качества относительно Gemma. Ускорение проверяется измерением, не предполагается из размера модели.

## Настройка

- Данные: тот же синтетический `data/experiments/random-linker-250-2026-11-24/snapshot.json`, что у Gemma. Размер выбранного среза и покрытие выдаёт команда отчёта ниже.
- Вход: эталонные спаны, текущее сообщение, окно прошлых сообщений и карточки из предсказаний; эталонные владельцы и будущие сообщения не передаются.
- API-модель: `MiniCPM5-2B`; наличие и поддержка structured outputs проверены в каталоге настроенного провайдера. Точная ревизия весов провайдером не подтверждена.
- Источник о семействе: [официальная карточка OpenBMB](https://huggingface.co/openbmb/MiniCPM5-2B). Поддержка русского в нашей задаче проверяется экспериментально.
- Конфиг: `configs/linker-minicpm-baseline.json`; тот же промпт и окно контекста, что у Gemma, но `reasoning_effort=low` и `max_tokens=2048`. Различие бюджета вывода нужно учитывать при сравнении задержки.
- Коммит основы: `2172a364f5259ad7bcfd0066caba8a8004fac046`, реализация в незакоммиченных изменениях worktree. Хеши исходников и копия конфига — в `provenance.json` и `config.json` каталога запуска.
- Инференс удалённый; локальные веса не скачивались. Время API включает сеть и очередь; это не нагрузочный тест.

## Предварительная проверка

В `data/experiments/minicpm-linker-pilot-2026-11-25` сохранён первый неуспешный ответ: лимит вывода исчерпан рассуждением, итогового JSON нет. В соседних каталогах `minicpm-linker-reasoning-probe-2026-11-25` и `minicpm-linker-low-reasoning-probe-2026-11-25` сохранены проверки `none` и `low`: первый вернул пустые назначения, второй — полный JSON для исходного сообщения с двумя людьми. Это отладка конфигурации, не оценка качества модели.

## Запуск и результаты

Из корня worktree:

```powershell
.\.venv-gliner\Scripts\python.exe -X utf8 -u tools/evaluate_gemma_linker.py --config configs/linker-minicpm-baseline.json --output data/experiments/minicpm-linker-250-2026-11-25/results --all-sessions --env-file '../../.env'
```

При остановке добавьте `--resume`; не запускайте два оценщика в один каталог одновременно. Ответы и старые попытки сохраняются. Невалидные ответы не исправляются автоматически и не считаются успешными.

Результаты, счётчики, покрытие, неизвестные владельцы, точные группы, pairwise Precision/Recall/F1, F2-session/F2-timely и задержка API:

```powershell
.\.venv-gliner\Scripts\python.exe -X utf8 tools/evaluate_gemma_linker.py --output data/experiments/minicpm-linker-250-2026-11-25/results --report-only
```

Живой отчёт: `data/experiments/minicpm-linker-250-2026-11-25/live-progress.md`. Обновление без API:

```powershell
.\.venv-gliner\Scripts\python.exe -X utf8 tools/watch_gemma_linker.py --run data/experiments/minicpm-linker-250-2026-11-25
```

После завершения или остановки процесса наблюдатель выходит. Для однократного обновления добавьте `--once`.

## Анализ ошибок и ограничения

На первых сессиях полного запуска даже с `low` сохраняются обрезанные ответы (`finish_reason=length`). Поэтому модель пока нельзя рекомендовать для замены Gemma в сервисе: прогон должен измерить и долю успешных обработок. В `data/experiments/minicpm-v-1b-probe-2026-11-25` отдельно сохранена проверка доступной `MiniCPM-V-4.7-1B`: JSON завершён, но оба явно названных человека оставлены без владельца. Быстрый ответ сам по себе не доказывает пригодность линкера. Эту модель на полный срез не запускали.

Прогон не измеряет ошибки NER. Выборка короткая, шаблонная и частично использована для отладки; высокие оценки не доказывают качество на реальных чатах. При разном числе успешных сессий сравнивать модели нужно на пересечении одинаковых ID, публикуя также долю неуспешных обработок. Нельзя выбирать меньшую задержку, игнорируя пустые или обрезанные ответы.

## Подключение к сервису

Общий Chat Completions линкер переиспользуется через существующий режим `gemma`, имя которого осталось совместимым с текущим сервисом:

```powershell
$env:PII_LINKER_MODE='gemma'
$env:PII_LINKER_CONFIG='configs/linker-minicpm-baseline.json'
```

Ключ берётся из `RADEON_API_KEY`; текущий запуск оценщика читает его из игнорируемого `.env`. Переменные работающего сервиса этим экспериментом не менялись. Без альтернативного конфига остаётся прежняя Gemma.
