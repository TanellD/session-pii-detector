# Два параллельных прогона: исправленный NER и Gemma

- Дата: 2026-11-25, Москва.
- Статус: оба обхода завершены; оставшиеся ошибки сохранены, итоговый срез ниже.
- Гипотеза: прирост извлечения после исправления адаптера улучшает итоговые алерты, а не только метрики спанов.

## Данные и конфигурация

Первый срез — прежний `random-linker-250-2026-11-24/snapshot.json`. Второй — `andrey-adapter-250-2026-11-25/snapshot.json`, выборка из авторского эталона 500-сессионного набора по сценариям Андрея. Происхождение и хеши второго набора сохраняются в его снимке; это производный синтетический набор, а не утверждение личной ручной проверки всех примеров Андреем.

Второй срез получает свежие реальные предсказания GLiNER. Для двух адаптеров используются одни и те же модельные спаны; затем новая версия и Gemma запускаются на тех же текстах. Эталонные владельцы, ожидаемые алерты и название сценария в запросы модели не передаются. В оценке Андрея используется сохранённый авторский `expected_first_alert`, включая отрицательные сессии; текущие веса риска его не заменяют.

Ревизия — `adapter-candidate-v1`, `src/session_pii/adapter_revision.py`, без изменений по результатам новых прогонов. GLiNER и порог — `benchmarks/pii_smoke/config.json`; Gemma — `configs/linker-gemma-baseline.json`, исходный API-промпт. Риск — `configs/runtime-risk-policy.json` без подгонки. Основа кода: `2172a364f5259ad7bcfd0066caba8a8004fac046` плюс незакоммиченные изменения; фактические SHA сохраняются в манифестах и provenance.

## Запуски

Первый корпус, исправленный адаптер поверх проверенной записи реального NER:

```powershell
.\.venv-gliner\Scripts\python.exe -X utf8 tools/supervise_gemma_run.py --run data/experiments/gemma-revised-250-2026-11-25 --input data/experiments/random-linker-250-2026-11-24/snapshot.json --ner-recordings data/experiments/random-linker-250-gliner-2026-11-24
```

Второй корпус, после завершения и сохранения его NER-инференса:

```powershell
.\.venv-gliner\Scripts\python.exe -X utf8 tools/supervise_gemma_run.py --run data/experiments/andrey-gemma-revised-250-2026-11-25 --input data/experiments/andrey-adapter-250-2026-11-25/snapshot.json --ner-recordings data/experiments/andrey-adapter-250-2026-11-25/ner --wait-for-extraction-summary data/experiments/andrey-adapter-250-2026-11-25/results/summary.json
```

Супервизор явно ограничивает число стартов (`--starts`, по умолчанию четыре) и продолжает после временных транспортных ошибок с паузой. Каждый старт и каждая попытка сессии сохраняются. Успешные сессии повторно не вызывают API; после транспортного сбоя накопленные неуспешные сессии могут получить новую попытку. Эту политику следует учитывать при оценке надёжности: ошибки попыток сохраняются даже после успешного повтора. Невалидный ответ не исправляется автоматически и не заменяется эталоном.

После подтверждённых ошибок соединения оба прогона продолжены повторным запуском супервизора. Нумерация журналов продолжается, предыдущие файлы не перезаписываются. Детерминированные ошибки контракта на неизменных NER-спанах (пересечения типов и неверный формат) сохраняются как ошибки и не вызывают повторные LLM-запросы при сетевом продолжении. Транспортные ошибки и неуспешные ответы модели могут получить новую попытку. Ревизия адаптера и промпт не менялись; хеши кода продолжения — в `resume-provenance.json`.

## Метрики и живые документы

Для первого корпуса:

```powershell
.\.venv-gliner\Scripts\python.exe -X utf8 tools/evaluate_gemma_linker.py --input data/experiments/random-linker-250-2026-11-24/snapshot.json --output data/experiments/gemma-revised-250-2026-11-25/results --report-only
.\.venv-gliner\Scripts\python.exe -X utf8 tools/watch_gemma_linker.py --run data/experiments/gemma-revised-250-2026-11-25
```

Для Андрея:

```powershell
.\.venv-gliner\Scripts\python.exe -X utf8 tools/evaluate_gemma_linker.py --input data/experiments/andrey-adapter-250-2026-11-25/snapshot.json --output data/experiments/andrey-gemma-revised-250-2026-11-25/results --report-only
.\.venv-gliner\Scripts\python.exe -X utf8 tools/watch_gemma_linker.py --run data/experiments/andrey-gemma-revised-250-2026-11-25
```

В корне каждого запуска находится `live-progress.md`, в `results/summary.json` — полные счётчики, Precision/Recall/F2 извлечения, pairwise Precision/Recall/F1 линкера на сопоставленных спанах, точные группы, Precision/Recall/F2-session/F2-timely алертов, ошибки выполнения и задержки. Охват линковки и успешных сессий публикуется отдельно; метрики успешных поднаборов нельзя выдавать за надёжность на всём наборе. Полные группы одновременно зависят от ошибок NER и линкера.

## Ограничения

Проверяется вся бизнес-цепочка Pipeline с живым Gemma API и зафиксированными реальными выходами NER. Локальный NER не повторяется внутри каждого LLM-запроса; его исходные задержки и текущие задержки пайплайна публикуются отдельно. Это не новый HTTP- или RPS-бенчмарк.

Корпуса оцениваются раздельно. Первый использовался при разработке правил; второй происходит из другого набора сценариев, но также синтетический и мог ранее изучаться. Оба не являются доказательством качества реального чат-бота. Итоговые значения будут доступны по завершении процессов; начальные метрики не фиксируются как финальные.

Эти числа воспроизводятся командой сравнения, указанной в [отчёте набора Андрея](2026-11-25-andrey-adapter-250.md), и сохраняются в `data/experiments/andrey-adapter-250-2026-11-25/results/summary.json`. Высокий F2 спанов не устраняет ошибки исполнения при пересечениях типов. Полный Gemma-прогон не скрывает эти случаи и оценивает алерты с явным отчётом покрытия.
