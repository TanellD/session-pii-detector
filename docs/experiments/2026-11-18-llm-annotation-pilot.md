# Первый проход LLM-разметки синтетических сессий

- Дата: 2026-11-18.
- Задача: начать разметку нескольких сессий по текущему ТЗ.
- Гипотеза: минимального формата достаточно для выделения спанов, принадлежности и последующего расчёта первого алерта в базовых случаях.
- Данные: только новые синтетические сессии; нулевые номера документов, несуществующий телефонный код, домен `.invalid`, вымышленные люди и адреса.

## Настройка и происхождение

Базовый коммит `68b090e5db4664e3802e09a17976f45e1d7601bb`, скрипты и документация добавлены в рабочем дереве. Windows / Python. Инструкция — `annotation-mvp-v2`, таблица классов и минимальный формат; их SHA-256 сохранены в манифесте.

**Первый проход выполнила LLM в текущем интерактивном диалоге. Отдельный внешний API не вызывался.** Скрипт `build_llm_annotation_pilot.py` материализует сохранённую здесь разметку, а не выполняет новую генерацию. Точные границы вычисляются по выбранным LLM фрагментам текста, поэтому качество самостоятельного предсказания числовых границ этим проходом не проверяется. Идентификатор отдельной API-модели отсутствует; метаданные не подменяют его предположением.

Создание примеров, их предварительная разметка и ожидания выполнены в одном диалоге. Это отладочный проход; ни независимого эталона, ни проверки человеком ещё нет. Полученное совпадение ожиданий с правилами не является измерением качества LLM или детектора. Метрики определены в `docs/kb/metrics.md`, но в этом пилоте не измерялись. Отчёт описывает историческую политику прохода; текущие правила и хеши могут отличаться. Старые файлы не перезаписываются новой оценкой.

## Воспроизведение сохранённого прохода

```powershell
python -X utf8 tools/build_llm_annotation_pilot.py
python -X utf8 -m unittest discover -s tests -p test_llm_annotation_pilot.py
python -X utf8 -m unittest discover -s tests -p test_annotation_contract.py
```

Первая команда воспроизводит все количества и результаты в таблице ниже. В каталоге `data/experiments/llm-annotation-pilot-2026-11-18/`:

- `sessions.json` — только сообщения без подсказки аннотаций и ожидаемых алертов;
- `in-session-annotations.json` — предварительные аннотации текущего диалога;
- `review.json` — результат обработчика и сравнение первого алерта с сохранённым ожиданием;
- `manifest.json` — происхождение, хеши, количество сессий и сущностей.

Данные находятся вне git; исходник воспроизведения содержит только синтетику.

## Результаты

Подготовлены **10 сессий, 24 сущности**. Все аннотации прошли формальный валидатор. Проверки момента/причины алерта совпали с сохранёнными ожиданиями во всех **10** случаях. Это проверка согласованности, не оценка точности.

| Сессия | Содержание | Первый алерт обработчика | Что проверить человеку |
|---|---|---|---|
| `pair_then_email` | ФИ → посторонний вопрос → личная почта | `m3`, сочетание | Имя и фамилия — два спана одной персоны |
| `full_name_only` | Ф/И/О без отдельного оранжевого факта | Не найден; неуверенность из-за статистики | Не выдавать отсутствие качественного правила за доказанный отрицательный итог |
| `office_phone` | ФИО и общий телефон службы | Не найден; неуверенность из-за статистики | Телефон имеет `person_id=null`, ФИО связано с человеком |
| `two_people_contacts` | Телефон А и почта Б | Не найден | Не объединять людей ради контактной пары |
| `same_person_contacts` | Телефон А и почта А | `m2`, сочетание | Безымянная, но явно обозначенная персона допустима |
| `initials_and_masks` | Полная фамилия, инициалы, скрытые контакты | Не найден; неуверенность из-за статистики | Выделить только полную фамилию |
| `red_document` | Вопрос → СНИЛС | `m2`, красное правило | Нулевой суррогат используется как формат, не проверка действительности документа |
| `fictional_person` | ФИ и почта вымышленного клиента | `m2`, сочетание; `is_example=true` | Флаг примера не выключает правило |
| `residence_without_name` | Полный адрес до дома без других фактов | Не найден | Адрес один не алертит; город не дублировать вложенным спаном |
| `correction_after_alert` | ИО → почта → исправленное имя | `m2`, сочетание | Старый спан и исторический первый алерт сохраняются |

### Пример: накопление признаков

1. «Здравствуйте! Я Макетов Образимир.»
2. «Хочу уточнить статус заявки.»
3. «Моя личная почта — obrazimir@example.invalid.»

Разметка: `Макетов` → `last_name`, `Образимир` → `first_name`, почта → `email`; все связаны с одной персоной. Обработчик собирает ФИ и на последнем сообщении применяет правило сочетания. Типа `fio` в аннотации нет.

### Пример: контакты разных людей

1. «Посетитель А: мой личный телефон +7 (000) 000-00-03.»
2. «Посетитель Б: моя личная почта visitor-b@example.invalid.»

Телефон относится к `p1`, email — к `p2`. Контактная пара одного человека не собралась. Для сравнения в корпусе есть соседний случай с двумя сообщениями явно обозначенного посетителя А.

### Пример: служебный контакт

1. «Я Образцов Тестимир Макетович.»
2. «У справочной службы телефон +7 (000) 000-00-02. Это общий контакт службы.»

Три части имени относятся к `p1`, у телефона `person_id=null`. Соседство с ФИО не делает телефон личным. Полное ФИО само по себе не даёт качественного алерта. Численный путь пока не подтверждён частотами, поэтому кейс отмечен неуверенным, а не уверенно безопасным.

## Отдельный API-запуск

Подготовлен `tools/run_llm_annotation_pilot.py` по [официальной документации Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs). Модель получает инструкции и только исходную сессию, без сохранённых аннотаций/ожиданий. Выход ограничен JSON Schema; после ответа проверяются неизменность сообщений, контракт и расчёт алерта. Ответ, модель, использование токенов и состояние сохраняются по каждой сессии. Невалидный ответ не исправляется молча; запуск останавливается с сохранением уже полученного. Автоматических платных повторов нет.

Проверка локальной конфигурации обнаружила незаполненный `OPENAI_API_KEY`; попытка запуска завершилась `blocked_missing_OPENAI_API_KEY`, **0 API-запросов**. API-качество, доступность модели и расходы не проверены. Сам ключ в отчёт и лог не попадает.

После добавления локального ключа можно запустить, указав доступную модель:

```powershell
python -X utf8 tools/run_llm_annotation_pilot.py --input data/experiments/llm-annotation-pilot-2026-11-18/sessions.json --output data/experiments/llm-annotation-pilot-2026-11-18/api-run-01 --model gpt-4.1-mini
```

Это пример явного выбора модели, а не обещание доступа к ней. Выходной каталог должен быть новым, чтобы не переписать прежний эксперимент. Запросы отправляются только в официальный OpenAI API, с `store=false`; серверные правила обработки данных этим параметром не определяются.

## Что осталось проверить

Обновление после уточнения пользователя: неизвестная принадлежность спана сама по себе больше не включает неопределённость вердикта. Прямое самоотнесение разрешено, служебные контакты остаются без персоны. Контекст конфигурации теперь прикладывается API-runner автоматически. [Зафиксированная семантика и конфиг](../project/annotation-context-config-2026-11-18.md). Прежний каталог первого прохода сохранён; повторная оценка сохранённых LLM-аннотаций с уточнённой политикой выполнена отдельно:

```powershell
python -X utf8 tools/build_llm_annotation_pilot.py --output data/experiments/llm-annotation-pilot-2026-11-18/refined-policy
```

Это повторный расчёт по прежним аннотациям, не новая генерация LLM. Манифест фиксирует хеш конфига и то, что контекст снят на этапе материализации. Проверки оснований/момента алерта по-прежнему совпадают с сохранёнными ожиданиями.

Человеку сначала проверить спорные привязки и флаги неуверенности. Отдельно запустить модель без доступа к ожиданиям, изучить ошибки спанов/принадлежности/флагов, затем расширять разнообразие диалогов. В этом пилоте нет численного пути через новые географические средние, проверок на границе порога и измерения качества на независимой выборке. Новые средние не были автоматически включены в калькулятор в ходе запуска разметки; действующее ТЗ не менялось.
