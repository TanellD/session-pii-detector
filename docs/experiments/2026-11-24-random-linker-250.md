# Эксперимент: случайный линкер и раздельная оценка компонентов

- Дата / автор: 2026-11-24; команда проекта.
- Задача: взять завершённые сессии Gemma, использовать исправленный авторский
  эталон и измерить случайный baseline и компоненты отдельно.
- Гипотеза: раздельные проверки покажут вклад извлечения, принадлежности и
  политики риска, который теряется при одном общем результате.

## Настройка

- Базовый коммит: `2172a36`; новые инструменты, тесты и документация поставляются вместе.
- Данные: `data/experiments/random-linker-250-2026-11-24/`, фиксированный
  `snapshot.json`, исходный корпус `annotation-1000-ownership-v2-2026-11-23`.
- Выборка: первые по ID завершённые уникальные сессии Gemma на момент снимка.
  Это отбор по успешности завершения, а не случайная выборка всех диалогов.
- Эталон: `corrected-gold.json`. По разрешению пользователя повторно использована
  исходная авторская разметка; проверены шаблоны семейств и разногласия Gemma.
  Журнал — `review-ledger.json`; исходные ответы модели и исходный gold не менялись.
  Независимой человеческой проверки нет. Неоднозначные имена сохраняют роль,
  заданную авторским сценарием: это ограничение эталона, а не доказательство
  ошибки Gemma. Правила общей разметки этим экспериментом не меняются.
- Runtime: regex-адаптер и фильтры сервиса, `RandomLinker`, `runtime-risk-v2`.
  Эталонные алерты вычислены независимой политикой разметки
  `configs/annotation-estimator-policy.json`. Хеши конфигов — в `evaluation.json`.
- GLiNER: пакет и подготовленные локальные веса в текущем окружении отсутствуют.
  Качество реальной NER-модели этим прогоном не измерено; coverage runtime явно неполное.
- Железо: локальная Windows-машина; CPU, без GPU и внешних API.

Все числа ниже и подробный отчёт воспроизводятся из корня worktree командой:

```powershell
& '..\..\.venv-service\Scripts\python.exe' -X utf8 tools/evaluate_random_linker.py --directory data/experiments/random-linker-250-2026-11-24 --seeds 0 1 2 3 4
```

Команда пересоздаёт результаты на фиксированном эталоне, не меняя его.
Временные замеры зависят от машины. Подробный отчёт —
`data/experiments/random-linker-250-2026-11-24/report.md`; машиночитаемые
счётчики, разрезы по типам и отдельные предсказания лежат рядом.

## Протокол

Для каждого упоминания линкер равновероятно выбирает каждого из `n` известных
людей, нового человека или неизвестного владельца: всего `n+2` исхода.
При отсутствии людей исходов два. Человек, созданный в текущем сообщении,
сразу доступен следующим кандидатам. Поток случайности отдельный для сессии,
детерминирован из общего seed и ID сессии. Совместные владельцы и служебные
контакты этим baseline не предсказываются. Линкер подключается явно через
`create_app(linker=RandomLinker(seed))`; поведение сервиса по умолчанию не менялось.
Для изолированных сессий следует создавать отдельный экземпляр.

Извлечение оценивается exact match с типом и штрафом за дубли. Линкер получает
правильные спаны; pairwise F1 считается на конечном состоянии, неизвестные
эталонные владельцы исключаются с отчётом покрытия. Риск получает правильные
спаны и владельцев. Для служебных контактов в этой изолированной проверке
также задаётся эталонная маска. В общем прогоне runtime получает только тексты,
ID сессии и seed; правильные владельцы и family ему не передаются.

Алерты оцениваются по [протоколу метрик](../kb/metrics.md). CPE Match не
вычисляется: численный эталон и допуск пока не определены. Дополнительная
абляция подставляет правильные спаны, сохраняя случайный линкер и runtime-риск.

## Результаты

Выборка содержит 250 сессий, 718 сообщений и 90 положительных сессий.

| Проверка | Результат |
|---|---:|
| Извлечение regex до фильтров, F2 | 0.5013 |
| Извлечение после фильтров сервиса, F2 | 0.5013 |
| Извлечение из сохранённых ответов Gemma, F2, отдельно от runtime | 0.9556 |
| Случайный линкер на правильных спанах, средний pairwise F1 | 0.2729 |
| Риск на правильных спанах и владельцах, F2-timely | 0.9825 |
| Вся доступная цепочка, средний F2-timely | 0.2182 |

Средние считаются по указанным seed на одних и тех же данных, это не macro
по группам и не доверительный интервал. Сохранены результаты каждого seed.
Для основного seed=0 общий результат: TP=17, FP=9, FN=73, TN=151;
F2-session=F2-timely=0.2202. HTTP-прогон всех 250 сессий дал те же спаны,
владельцев и первый алерт, что прямой Pipeline.

## Анализ ошибок

- Извлечение: 234 точных спана, 291 пропуск, лишних нет. Имена, адреса и
  другие модельные категории без GLiNER в основном пропускаются. Например,
  `synthetic-1000-0007` содержит части ФИО и общий адрес.
- Документы: `synthetic-1000-0011` содержит «паспорт: серия и номер …»,
  тогда как regex ожидает номер непосредственно после слова «паспорт».
  Положительные ИНН записаны с оборотом «ИНН физического лица: …», также
  выходящим за узкую форму regex. Нельзя объяснять эти пропуски checksum.
- Принадлежность: случайный выбор дробит один профиль и иногда объединяет
  чужие атрибуты. Совместные владельцы недостижимы по заданной политике
  baseline. Это ограничение нужно учитывать при сравнении с настоящим линкером.
- Изолированный риск: 8 ложных алертов, все в `unknown_contact_pair`.
  Например, `synthetic-1000-0046`: неизвестная почта и неизвестный телефон
  суммируются как 0.3+0.3, что выше `unknown_threshold=0.5`. По эталонной
  политике алерта нет. Это расхождение двух политик даже при верных входах.
  Веса и эталон под результат не подгонялись.
- Фильтры не изменили набор спанов на этом срезе. Это не подтверждает их
  качество на всех пересечениях: нужны отдельные направленные примеры.

## Вывод и следующий шаг

Есть воспроизводимый baseline, отдельные оценщики и проверка HTTP-цепочки.
Низкий общий результат объясняется одновременно отсутствием модельного
извлечения и случайной принадлежностью. Следующий содержательный прогон —
с подготовленным GLiNER и обучаемым либо правиловым линкером на том же срезе.
Политику неизвестных атрибутов стоит рассмотреть отдельно, сохраняя эталон
независимым от текущих весов. Метрики на шаблонной синтетике не подтверждают
готовность к реальным диалогам.
