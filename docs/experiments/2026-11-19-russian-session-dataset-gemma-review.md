# Русские клиентские префиксы CONFIDE: Gemma и выборочная проверка

- Дата: 2026-11-19.
- Базовый коммит: `55bbb82`; генератор, инструменты ревью и отчёт поставляются вместе.
- Задача: сформировать русскоязычный набор, разметить Gemma, отдельно проверить случайный материал без меток и с метками, посчитать алерты и отсутствие алертов.
- Политика: `2026-11-18-working-v2`, схема `annotation-mvp-v2`.
- Все проверки в этом отчёте выполнены текущей LLM. Независимого человеческого эталона всего набора нет.

## Отбор данных

Использован только собственный синтетический русский файл CONFIDE на ревизии `91fa72f894c83680129c460daa47426101c4d596`, уже прошедший [аудит в проекте](2026-11-19-confide-annotation-audit.md). Синтетичность — заявление авторов, а не независимая верификация каждого значения. Данные/документация этого среза — CC-BY-4.0; код — MIT. Другие корпуса с неподтверждённой лицензией или синтетичностью не импортировались.

```powershell
python -X utf8 tools/build_russian_session_dataset.py
```

Команда формирует **10 коротких префиксов, 40 клиентских сообщений**. Исходный файл содержит 30 документов; все прошли проверку доступности клиентского префикса и доли кириллицы. Отбор: первые сессии всех вымышленных профилей плюс случайная подвыборка последующих сессий, seed `20261119`. У каждого выбранного документа взяты первые четыре клиентские реплики в исходном порядке. Это не полные исходные сессии и не равномерная случайная выборка всего корпуса.

Фильтр: русский исходный namespace и доля кириллицы среди букв префикса не ниже 0,7. Он не отбрасывает телефон, email или цифровую реплику из русскоязычного контекста. Это воспроизводимая проверка отбора известного RU-среза, а не универсальный детектор языка.

Терапевтические реплики, шапки с профилями, таймкоды и роли исключены. Исходные тексты клиентских реплик сохранены; удалены только внешние пробелы и служебные маркеры. Сопоставление с исходным документом, профилем, ролью, индексом реплики и границами хранится в `provenance.json`. Сведения из удалённого ответа терапевта не считаются известными разметчику. Исходные NER-спаны не использовались для новой разметки или выбора сессий.

В выборке присутствуют документы исходных dev/test-профилей. Это исследовательский набор для ревью; его нельзя впоследствии объявлять нетронутым test. Сессии одного профиля не являются независимыми людьми.

## План проверки до прогноза модели

`review-plan.json` фиксирует случайный порядок и раздельные подвыборки:

- Без просмотра меток: `ru-session-07`, `ru-session-02`.
- С просмотром меток: `ru-session-09`, `ru-session-03`.

Слепые решения и оценки сохранены в `blind-review-frozen.json` до начала API-прогона; время и контрольные суммы записаны. Проверяющий видел только пользовательские тексты, не исходные NER-спаны и не ответы Gemma. Это слепота к меткам, а не независимый человеческий эксперимент: проверяющий — та же текущая LLM, ранее знакомая с тематикой источника.

```powershell
python -X utf8 tools/review_russian_session_dataset.py --freeze-blind
```

Дополнительно до завершения прогона зафиксировано правило стратифицированного ревью в `stratum-review-rule.json`: после прогнозов случайно выбрать сообщения без найденных сущностей и сообщения с сущностями, seed `20261120`, по два сообщения в каждой группе. Разметка проверяется с доступным предыдущим пользовательским контекстом, без будущего. Это отдельно покрывает возможные пропуски и ложные выделения.

Пользователь уточнил во время работы: целиком написанные разговорные имена «Соня», «Тёмка» выделяются как `first_name` без восстановления официальной формы. Слепая разметка изначально использовала это толкование; историческая пометка сомнения сохранена. Уточнение записано в ТЗ и `review-adjudications.json`. Уже запущенный API-процесс продолжил использовать зафиксированный прежний промпт; новые запросы не подменяют его содержимое. Это следует учитывать при трактовке спорных форм, а не объявлять модель заведомо нарушившей более позднее уточнение.

## Последовательный прогон Gemma

```powershell
python -X utf8 tools/run_sequential_annotation.py --input data/experiments/russian-session-dataset-2026-11-19/sessions.json --output data/experiments/radeon/2026-11-19-russian-dataset-gemma-01 --model Gemma-4-31B-IT --timeout 120 --max-tokens 4000 --delay 3
```

Провайдер Radeon Cloud, транспорт `annotation-quotes-v1`, temperature=0. Модель видит только текущий пользовательский префикс и собственное прежнее предсказание; эталон и будущие реплики не отправляются. Новые сущности добавляются только текущему сообщению. Старые спаны и владельцы заморожены; обработчик сохраняет исторические флаги и считает алерт. При ошибке останавливается текущая сессия, следующая начинается с пустого состояния; HTTP-ошибка останавливает прогон. Повторов нет.

В отчёте **«бан» означает наличие вычисленного первого алерта по нашему ТЗ**, а не реально выполненную блокировку и не суждение внешней модели о юридической допустимости. Вызовы разметки возвращают сущности, а алерт вычисляет наш обработчик. Незавершённые сессии не считаются «небаном».

## Проверка и воспроизведение сводки

После завершения модельных запросов:

```powershell
python -X utf8 tools/review_russian_session_dataset.py --sample-strata
# Проверить зафиксированную случайную выборку и сохранить её решения отдельно.
python -X utf8 tools/review_russian_session_dataset.py
```

Для воспроизведения чисел уже сохранённого обзора без сети и перезаписи:

```powershell
python -X utf8 tools/review_russian_session_dataset.py --check
```

Модельные результаты не исправляются; мнения проверяющего и спорные случаи сохраняются отдельно. Отчёт включает число алертов, отрицательных и неуверенных отрицательных сессий, ошибки API, типы и число сущностей, покрытие ревью, пропуски/лишние спаны и принадлежность на проверенной части. Из ограниченной подвыборки не выводится точность на всём корпусе.

Локальный каталог `data/experiments/russian-session-dataset-2026-11-19/` содержит:

- `sessions-for-review.md` — весь выбранный пользовательский текст без меток.
- `gemma-annotations-for-review.md` — исходные сущности/владельцы Gemma с текстами.
- `overview.md`, `overview.json` — итоговые счётчики, проверки и ограничения.
- `blind-review-frozen.json` — слепая проверка до прогноза.
- `visible-review-selections.json` — решения при просмотре меток.
- `stratum-review-sample.json`, `stratum-review-verdicts.json` — случайные сообщения без меток и с метками, затем их проверка.
- `sequential-audit.json` — проверка сохранённых запросов и неизменности истории, без придуманного эталона непроверенных сессий.

Исходные тексты, метки и ответы API остаются вне Git.

## Итоги завершённого прогона

Все счётчики ниже воспроизводятся командой `python -X utf8 tools/review_russian_session_dataset.py --check`.

| Показатель | Значение |
|---|---:|
| Выбранные префиксы / сообщения | 10 / 40 |
| Полностью обработанные префиксы | 9 |
| Незавершённые префиксы | 1 |
| API-запросы / валидные ответы | 38 / 37 |
| Алерт («бан») среди завершённых | 2 |
| Без алерта среди завершённых | 7 |
| Из них с исторической неуверенностью | 5 |
| Без алерта и без такой пометки | 2 |
| Сущности в завершённых префиксах | 24 |

Незавершённый `ru-session-08` не включён ни в «бан», ни в «небан». Ошибка на втором сообщении остановила оставшиеся сообщения именно этого префикса; поэтому число API-запросов меньше размера набора. Тайм-аутов не было: это ошибка формата ответа. Варианты написания имени получили счётчики вхождения как для последовательных упоминаний одного человека, хотя каждая точная строка встречается один раз. Сохранённый ответ отклонён, не исправлен. [Диагностика](../insights/2026-11-19-quote-occurrence-per-exact-string.md).

Типы выделенных Gemma сущностей: имя — 12, фамилия — 3, отчество — 4, email — 2, телефон — 2, география — 1. География не присоединена человеку, поскольку контекст не устанавливает проживание. Полных адресов и красных документов в этих коротких пользовательских префиксах не выделено; этим запуском их качество не подтверждено.

## Что именно перепроверено

- Два случайных префикса до просмотра модельных меток: восемь сообщений. Слепая разметка зафиксирована до API-прогона.
- Два других заранее случайно выбранных префикса после получения их модельных меток: восемь сообщений. ФИО и повторы частей имени соответствуют авторскому прочтению ТЗ, владельцы не перепутаны.
- Дополнительно по два случайных текущих сообщения без сущностей и с сущностями. Пустая разметка возраста словами/описания состояния обоснована рамками MVP; личная почта и имена разных людей выделены корректно. Эти сообщения могут пересекаться с полными проверенными префиксами.
- Целевым способом проверены оба модельных алерта, с полным доступным пользовательским контекстом. Оба поддерживаются сочетанием личного телефона с email. Страховой полис не принят за ИНН, имя не восстановлено из email или удалённой реплики терапевта.
- Отдельно разобран невалидный ответ. Это целевая диагностика ошибки, а не часть случайного сэмпла.

С учётом пересечений проверено **25 уникальных сообщений**. Счётчик включает перечисленные проверки с текстом и метками, но не объявляет все 25 сообщений независимо размеченными вслепую. Проверены границы, типы, владельцы, пропуски, ложное достраивание и моменты алерта. Весь прогон дополнительно прошёл технический аудит допустимых префиксов и неизменности старых сущностей; это не семантическая проверка всех текстов.

В слепой подвыборке найдены два расхождения с Gemma: обобщённая профессия «психологу» с неизвестным владельцем и фамилия литературного персонажа. Авторская проверка включает оба спана; модель их пропустила. Эти различия не меняют отсутствие алерта. Обобщённые профессии и применение флага примера к вложенным литературным цитатам стоит независимо проверить человеком; в литературном кейсе сохранена пометка пробела ТЗ. Целиком написанные разговорные имена пользователь уже разрешил, прежние пометки сомнения не сняты.

Нельзя переносить результаты на все русские чаты: источник терапевтический, префиксы короткие и смещены к началу сессий. «Нет алерта» не означает отсутствие чувствительного медицинского содержания — такие факты вне текущей таксономии. На всей выборке нет независимого gold, а проверка с видимыми метками подвержена эффекту привязки. Поэтому точность или полнота на всём наборе не заявляются.

Для явного обновления только производных отчётов после новых комментариев используется `--refresh-derived`; фиксированные выборки, слепой эталон, исходные тексты и ответы API не перезаписываются. Обычная команда без флага отказывается перезаписывать отчёты.

## Проверки реализации

`python -X utf8 -m unittest discover -s tests` — **181 тест прошёл**. Новые проверки подтверждают отбор клиентских ролей, исключение шапок/таймкодов, сохранение цифровой реплики в русском контексте, точное сопоставление границ с источником, запрет поздней фиксации слепой разметки и запрет перезаписи замороженного эталона при обновлении отчётов. Проверка `--check` воспроизвела сохранённую сводку; `git diff --check` прошёл. Эти проверки кода не подменяют оценку правильности модельных меток.
