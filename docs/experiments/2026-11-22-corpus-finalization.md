## Команды

```powershell
python -X utf8 -m unittest discover -s tests
python -X utf8 tools/migrate_session_corpus.py --source "data/experiments/data for testing/session-alerts-v1" --output data/session-alerts-v3 --add-review-scenarios

python -X utf8 -m benchmarks.eval_gold --gold data/session-alerts-v3/sessions.json --split all --output runs/session-alerts-v3-regex.json
```

Путь --source указывает на переданный локальный пакет и при необходимости меняется. Повторный запуск использует новый выходной каталог. В этой рабочей копии источник находится через ../../data/experiments/data for testing/session-alerts-v1, результат — data/session-alerts-v3-final; для проверки расширения использованы те же команды с этими путями.

## Результат и ограничения

Миграция сохраняет старый набор, исключает неверные checksum из эталона извлечения и переносит совместных владельцев непосредственно в person_id. Добавлены контролируемые сценарии общего телефона/адреса, повторов, отдельных валидных документов, неправильных телефонов и общего person. Gold не переиспользуется: нужен новый авторский реестр и независимая проверка. Это не оценка качества модели и не новый полный сессионный baseline.

Тесты проверяют качественные алерты на синтетических сценариях с несколькими владельцами, корректность доказательств и отсутствие связи с весами сервиса. Новый baseline использует общий адаптер. Исторические показатели v2 не являются метриками новых правил. Контракт списка владельцев совместим с прежними строкой/null; старые схемы review46 требуют явной миграции.

## Проверенные результаты

Команда python -X utf8 -m unittest discover -s tests: 223 теста, один явно пропущен. Миграция и сборка по командам выше: 24 сессии, 61 сообщение; неверные документные спаны исключены в 3 случаях. Команда оценки извлечения на этом наборе: TP=28, FP=0, FN=27, F2=0.565 (округление). Это regex-only на контролируемой синтетике, не результат GLiNER и не сессионная метрика.

Дополнительно локально проверен HTTP-сервис ветки feat/session-service с новым regex-адаптером и тестовым линкером: общий телефон p1/p2 и почта p1 дают риск 0.6 для p1, 0.3 для p2 и первый алерт на втором сообщении. Это интеграционная проверка с вручную заданными владельцами, не проверка качества линкера. Регрессия аналогичного контракта сохранена в tests/test_multi_owner_annotation.py; сервисные тесты находятся в ветке сервиса. Живой LLM/GLiNER-прогон и Docker в этой проверке не запускались.
