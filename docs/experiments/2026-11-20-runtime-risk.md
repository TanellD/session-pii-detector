# Проверка сессионной суммы риска

- Дата / автор: 2026-11-20, команда проекта.
- Связано: PR #44, [API](../api/service-scaffold.md).
- Гипотеза: сумма риска по людям и отдельная ветка неизвестных фактов могут проверяться независимо от будущих NER и линкера.

## Настройка

- Данные: синтетические фикстуры в `tests/service/`; реальные данные не использовались.
- Конфиг: `configs/runtime-risk-policy.json`, версия `runtime-risk-v1`.
- Код: рабочие изменения поверх `cba98ae`; воспроизводить на коммите с этой заметкой.
- Окружение: Windows, Python из `.venv-service`; отдельная проверка Docker на Linux.

## Проверка

Команда `.venv-service\Scripts\python.exe -X utf8 -m unittest discover -s tests/service -v` проверяет строгую границу суммы, разделение людей, полный исторический пересчёт, красные без владельца, согласованные сочетания, повторы и исправления, исключение служебных контактов, отсутствие скрытого суммирования частей ФИО, отдельную неизвестную ветку и атомарность HTTP-состояния.

Результат этой команды: **26 тестов прошли**. Исследовательские проверки `python -X utf8 -m unittest discover -s tests` также прошли: **184 теста**; это проверка сохранности прежней политики, а не совпадения её алертов с новой.

Docker: `$env:PII_HOST_PORT='8018'; docker compose -p session-pii-scaffold-smoke up --build -d --wait --wait-timeout 60`, затем `.venv-service\Scripts\python.exe -X utf8 tools/smoke_service.py --base-url http://127.0.0.1:8018`. Образ собран, контейнер healthy, HTTP smoke и точный retry успешны. Внутри образа импортирован `RiskEvaluator`, подтверждены версия конфига и срабатывание суммы неизвестных контактов без правила сочетаний. После проверки тестовый проект остановлен через `docker compose -p session-pii-scaffold-smoke down`.

Это интеграционные проверки логики; они не измеряют качество будущих NER/линкера и не являются повторной оценкой Gemma или старого статистического эталона. Зависимости и Docker-команды описаны в API-инструкции.
