# Проверка формата v2 и таблицы классов

- Дата / автор: 2026-11-18 / исследование проекта.
- Issue: запрос пользователя о таблице полей для основной LLM-разметки.
- Цель проверки: исключить ФИО/родство из спановых классов, сохранить сборку имени обработчиком и разнести сущности и флаги всего кейса. Это проверка правил, не обучение и не оценка качества модели.

## Настройка

- Данные: `tests/fixtures/annotation-mvp-cases.json`, `annotation-mvp-v2`, полностью вымышленный учебный набор.
- Конфигурация: `configs/annotation-estimator-policy.json`, `annotation_schema=annotation-mvp-v2`, оператор порога `le`.
- Коммит-основа: `68b090e5db4664e3802e09a17976f45e1d7601bb` и незакоммиченные рабочие изменения; это не хеш фиксированной реализации v2.
- Среда: локальный Windows / Python, CPU.

```powershell
python -X utf8 tools/build_annotation_mvp_examples.py
python -X utf8 tools/annotation_contract.py --check-cases tests/fixtures/annotation-mvp-cases.json
python -X utf8 -m unittest discover -s tests -p test_annotation_contract.py
python -X utf8 -m unittest discover -s tests -p test_annotation_calculator.py
```

## Результаты и ограничения

Команда `--check-cases` воспроизводит успешную проверку **30 синтетических сценариев**. Проверяются первый момент/причина алерта; отдельные тесты проверяют отказ от `fio`/`relationship`, кейсовые флаги, предлог на границе, неизвестную принадлежность и отдельную безымянную персону.

Основные пограничные случаи: пример с явной персоной и сработавшим сочетанием; неизвестные контакты без общего владельца; запрет поздней перепривязки по «его»; создание отдельной персоны до появления имени; разбор непрерывного ФИО на отдельные компоненты.

Вход v1 сохраняет техническую совместимость, но не является разрешённым форматом новых аннотаций. Существующие реальные аннотации автоматически не мигрировались. Внешний LLM API не вызывался, измерение качества LLM и согласованности людей не проводилось; цифры учебных проверок не являются F1/F2.
