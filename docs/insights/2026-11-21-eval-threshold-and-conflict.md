# Threshold и сохранение упоминаний при конфликте

- Дата: 2026-11-21
- Автор: Сизова Олеся
- Связано: эксперимент [оценки адаптера](../experiments/2026-11-21-adapter-improvements.md)

## Что увидели

`eval_gold --threshold` принимал значение, но GLiNER продолжал использовать threshold из config. Кроме того, `resolve_conflicts` терял любое упоминание без однотипного пересечения: append выполнялся только в ветке `replaced=True`.

## Доказательство

После исправлений dev exact F2 при порогах 0.5/0.6/0.7 равен 0.611/0.562/0.568. До исправления три отчёта были идентичны. Регрессионный unit-тест проверяет передачу override и fallback к config; тесты адаптера проходят.

## Что это значит для проекта

Результат подбора порога имеет смысл только если override доходит до модели. Разрешение конфликтов должно сохранять непересекающиеся mentions; иначе любая оценка extraction некорректна. Качество address regex отдельно не подтверждено: см. smoke failures и gold-метрики в эксперименте.
