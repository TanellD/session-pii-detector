## Что это значит для проекта

Предыдущую оценку готовности к merge нельзя менять только по дате обновления
PR: новая активность относится к обсуждению. Для повторного содержательного
ревью нужны изменения документов или явное согласование оставшихся вопросов.

## Дополнение после повторной проверки обсуждения

В комментариях TanellD от 8 ноября появились уточнения, которых не было
при первой проверке:

  формулу и не доказывает качество политики. Изолированная проверка агрегации
  должна получать эталонные атрибуты и принадлежность.
- [Ранний алерт — FP; ошибки разбираются по компонентам](https://github.com/TanellD/session-pii-detector/pull/19#discussion_r4506696250).
  Предложено пробовать набор метрик на данных, а не откладывать из-за всех
  возможных пограничных случаев. Для F2-timely остаётся важным явно указать,
  что ранний первый алерт дополнительно означает FN своевременного события;
  на F2-session это правило не переносится.
