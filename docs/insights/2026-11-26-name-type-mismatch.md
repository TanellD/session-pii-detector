# Низкое качество частей имени включает расхождение типов и неоднозначность эталона

- Дата: 2026-11-26.
- Источник: кэш validation бенчмарка session-benchmark-2400-v5.

## Наблюдение

В просмотренных сообщениях «Отправитель обращения — Демоодар, это я» размечен
как first_name, а адаптер возвращает person. В «Параллельно обращается
Шаблономысл» модель возвращает organization. Есть и пропуски частей имени.
Поэтому строгие ошибки экстракции нельзя целиком называть отсутствием выделения:
часть относится к неверной или менее конкретной типизации.

Фраза «отправитель обращения» указывает на человека, но сама по себе не
доказывает, что следующее слово является именно именем, а не фамилией или
псевдонимом. Генератор знает роль подставленного значения; модель не должна
получать это скрытое знание. Требуется аудит однозначности эталона, без молчаливой
смены правил разметки или замороженных данных.

## Проверка

Из рабочего каталога воспроизвести примеры входного PERSON/ORGANIZATION:

```powershell
.venv-gliner/Scripts/python.exe -X utf8 -c "import json; from pathlib import Path; p=Path('data/experiments/benchmark-validation-gemma-risk-2026-11-26'); d=json.loads((p/'input-snapshot.json').read_text(encoding='utf-8')); print(d['records'][0]['gold']); print(json.loads(next((p/'ner/by-text').glob('*.json')).read_text(encoding='utf-8')))"
```

Для систематического сравнения нужны точные границы, типы и тексты из
input-snapshot.json и ner/by-text; отдельная диагностика совпадения только границ
не заменяет основную type-aware метрику.

## Следующий шаг

Проверить однозначность частей имени и составить матрицу перепутанных типов.
Контекстные правила добавлять по явным конструкциям («имя», «фамилия»), не
по вымышленным корням или точным репликам генератора. Сравнивать новую ревизию
отдельно, сохраняя текущий замер. Пороги типов подбирать на validation; test
не использовать для исправления правил.
