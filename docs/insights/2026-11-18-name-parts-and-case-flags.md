# ФИО собирается из частей, а контекст примера относится ко всему кейсу

- Дата: 2026-11-18.
- Автор: исследование проекта.
- Связано: [таблица классов](../data/annotation-class-fields.md), [формат v2](../data/schema.md).

## Что увидели

Пользователь исключил отдельную сущность ФИО и обработку местоимений/родства. Принадлежность отдельных Ф/И/О задаётся разметкой, составные маркеры формирует обработчик. Явно отдельному безымянному человеку можно сразу назначить свою персону; ранее неизвестные сущности задним числом не переназначаются.

Пометка примера и неуверенная разметка из-за отсутствия статистики относятся к кейсу, а не к каждому спану. Синтетическое происхождение всего учебного датасета не равно наличию вымышленного примера в содержании каждого диалога. Пометка примера не подавляет алерт: срабатывания можно исследовать отдельно.

## Доказательство

```powershell
python -X utf8 tools/build_annotation_mvp_examples.py
python -X utf8 tools/annotation_contract.py --check-cases tests/fixtures/annotation-mvp-cases.json
python -X utf8 -m unittest discover -s tests -p test_annotation_contract.py
```

Тесты отвергают `fio`/`relationship` в v2, проверяют сборку из отдельных частей, сохранение неизвестной принадлежности, отдельную безымянную персону и пример со сработавшим правилом.

## Что это значит для проекта

Новая разметка — `annotation-mvp-v2`; v1 читается только для совместимости старых входов. Основную предварительную разметку создаёт LLM, человек проверяет выборку и спорные кейсы. Валидация структуры и учебные сценарии не являются оценкой качества LLM-разметки или модели детекции.
