## Исправить до заявления о полной готовности

### P2. Воспроизводимость установки не проверена на чистой среде

README использует `--system-site-packages --without-pip`. PyTorch и pip берутся
из системы, полное окружение лежит только в игнорируемом `runs/.../freeze.txt`.
`requirements.txt` фиксирует верхнеуровневые зависимости, но не torch и не все
транзитивные библиотеки. `prepare.py` зависит от внутреннего `pip._vendor.truststore`.
Повтор на этой машине подтвердил текущий запуск, но не независимое развёртывание.

Кроме того, `prepare.py:29` скачивает backbone по `revision="main"` и только затем
сравнивает SHA. Проверка предотвращает незаметную подмену версии, но после смены
main процедура перестанет воспроизводиться даже при доступном закреплённом SHA.

Нужно: проверенная чистая установка, явная установка/версия PyTorch и TLS-зависимости,
снимок релевантных зависимостей, подготовка backbone по закреплённой revision.
Не подменять подтверждение чистой установки успешным pip check текущего окружения.

### P2. Отчёт не поддерживает результат regex-only

`report.py:59` безусловно читает `model_load_seconds`, далее обращается к combined.
При отчёте отдельного запуска правил получен `KeyError: 'model_load_seconds'`.

```powershell
.\.venv-research\Scripts\python.exe -m benchmarks.pii_smoke.run --regex-only --output runs/task12-audit-regex
.\.venv-research\Scripts\python.exe -m benchmarks.pii_smoke.report --input runs/task12-audit-regex --output runs/task12-audit-regex/report.md
```

Нужно либо поддержать этот результат, либо явно ограничить report полным прогоном
и выдавать понятную диагностическую ошибку. Текущий CLI ограничения не объясняет.

### P2. Выводы отчёта зашиты в коде и могут расходиться с измерением

`report.py:124` всегда утверждает, что должность и родство не обнаружены, и называет
конкретные ошибки; дата и часть описания также постоянны. Контрольная проверка
на искусственных копиях результатов с безошибочными predictions прошла с кодом
возврата 0, но оставила прежнюю негативную формулировку.
Копии лежат в `runs/task12-audit-report-probe/`; это тест инструмента отчётности,
не новый результат модели и не доказательство улучшения качества.

Нужно отделить автоматические числа от ручного анализа конкретного run либо
выводить утверждения из результатов с проверками. Исходный вывод текущего
эксперимента подтверждён; дефект касается будущих прогонов и других конфигов.

### P2. API не описывает восстановление клиента после конфликта

`session-pii-v0.1.md:81` требует сверить состояние после старого retry или
смешанного batch. Но нет операции получения epoch/state_version/следующего ID,
а schema Error содержит только code/message. Если квитанция запроса уже заменена
другим запросом, протокол не даёт клиенту описанного способа продолжить работу.

Нужно предложить чтение состояния либо структурированные метаданные конфликта,
уточнить bootstrap/reset и добавить пример продолжения существующей сессии.
Реализовывать HTTP-сервис для исправления черновика не требуется.

### P2. Проверка API-примеров не покрывает ключевые смысловые противоречия

В копиях JSON-примеров текущий `validate_task12.py` принял все изменения:

- неполное покрытие с `no_alert` без предыдущего алерта и без причины;
- историческое первое срабатывание при сессионном `no_alert`;
- `person_id` сущности, отсутствующий среди возвращённых людей;
- `has_signals=false` при непустых entities.

Проверка выполнялась на копиях в `runs/task12-audit-contract/`, оригинал не менялся.
Нужно уточнить инварианты контракта и добавить отрицательные примеры для них.
Также нет примеров retry/изменённого payload, продолжения с expected version,
исправления факта и reset. Проверка JSON не заменяет будущие runtime-тесты.

## Что остаётся ограничением исследования

- Полное ФИО с отчеством и отдельное отчество не проверены. Случай `full_name`
  содержит имя и фамилию; все части объединены в PERSON. Нужна явная таблица
  «класс #10 → метка/адаптер → проверенный пример → результат». До этого нельзя
  считать классы MVP полностью проверенными.
- Natasha, Presidio и Guard Omni сравнивались по документации, не в эксперименте.
  Для #12 требовался практический запуск regex + GLiNER, поэтому отсутствие
  измерений всех альтернатив само по себе не является незавершённым пунктом.
- Лицензии backend/расширений Presidio и возможность использовать их в production
  не подтверждены. Это ограничивает окончательную рекомендацию, но не мешает
  представить их как кандидатов с явным статусом «проверить».
- Совместимость с внутренним NER API HiveTrace и мотив совета ментора неизвестны.
  Внешние решения по классам, порогам, ролям и хранению ещё не согласованы.

## Что не следует добавлять в объём #12 задним числом

Работающий сессионный HTTP-сервис, качество линковки, сессионный F2, нагрузочные
испытания, подбор окончательного порога и обучение модели — этап MVP/смежные задачи.
Публикация и merge исключены пользователем. Их отсутствие не является недоделкой
локального исследовательского задания. Реализация данных исправлений в этом аудите
не выполнялась; обзор и ADR остаются предложениями.
