# Пустое соединение браузера блокировало локальную авторизацию VK ID

- Дата: 2026-11-16.
- Автор: команда проекта.
- Связано: `tools/authorize_vk_id.py`, `tests/test_vk_id_authorization.py`.

## Что увидели

После ввода ID локальный помощник перестал отвечать даже на `/status`. Сервер использовал последовательный HTTPServer: принятое соединение без строки запроса могло задержать обработку остальных соединений браузера. В частности, такой сценарий возможен при предварительном открытии браузером соединения.

## Доказательство

Добавлена синтетическая регрессионная проверка: открыть TCP-соединение и не отправлять запрос, затем через другое соединение получить `/status` и отправить форму `/start`. Команда: `python -X utf8 -m unittest discover -s tests -p test_vk_id_authorization.py`.

Сервер заменён на ThreadingHTTPServer, соединения имеют тайм-аут, изменение состояния PKCE защищено блокировкой. Перезапущенный локальный сервер отвечает на `/status` при параллельном пустом соединении. Реальные параметры авторизации в тестах и логах не сохранялись.

## Что это значит для проекта

Локальную авторизацию нужно проверять не только чистыми последовательными HTTP-запросами: поведение браузера включает дополнительные соединения. После перезапуска пользователь должен обновить форму, поскольку её nonce и незавершённый PKCE-запрос существуют только в памяти.
