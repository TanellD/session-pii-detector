# Origin null может возникать у корректной локальной POST-формы

- Дата: 2026-11-16.
- Автор: команда проекта.
- Связано: `tools/authorize_vk_id.py`, `tests/test_vk_id_authorization.py`.

## Что увидели

Пользователь получил сообщение об отказе Origin на локальной форме. Реальное значение заголовка его браузера не записывалось. Обнаружен воспроизводимый дефект: помощник отклонял Origin null даже с правильным случайным nonce. Ранее на форме устанавливался Referrer-Policy no-referrer.

## Доказательство

[Документация Mozilla по Origin](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Origin#description) перечисляет некоторые Referrer-Policy для обычного POST как причину null-Origin. Следовательно, по одному null нельзя отличить поддельную отправку от законной.

На исходной форме теперь используется same-origin, а на callback и остальных шагах сохранён no-referrer. Null-Origin разрешается только с обязательной проверкой nonce; Sec-Fetch-Site cross-site и посторонние Origin отклоняются. Проверка и ротация nonce атомарны под блокировкой.

Команда: `python -X utf8 -m unittest discover -s tests -p test_vk_id_authorization.py`. Синтетический HTTP-тест проверяет успешный null-Origin с nonce, отказ при неправильном nonce, чужом Origin и явно межсайтовом запросе.

## Что это значит для проекта

Нельзя считать null-Origin самостоятельным доказательством чужого источника. Защита формы сохраняется за счёт случайного одноразового nonce и дополнительных проверок. Для повторной проверки в браузере после перезапуска требуется свежая форма.
