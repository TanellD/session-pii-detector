# Калькулятор должен использовать ту же семантику неопределённости, что и разметка

- Дата: 2026-11-18.
- Связано: [инструкция](../data/annotation-workflow.md).

## Что увидели

В интерфейсе калькулятора оставались отдельные ФИО/родство и флаг неуверенности сущности. Ручной оценщик считал любой атрибут без владельца причиной неопределённости всей сессии, хотя обработчик JSON уже применял другое правило. Часть подписей статистических полей была испорчена.

## Доказательство

`python -X utf8 -m unittest discover -s tests -p test_annotation_calculator_http.py` проверяет страницу, режим без таблиц, общий контакт без алерта/неопределённости и обработку JSON-сессии тем же `annotation_contract.assess`. Отдельные ФИО/родство и флаг неуверенности сущности из основного интерфейса исключены. В JSON-пути проверяются сообщения, спаны и принадлежность; в ручном пути индекс относится к атрибуту, а не сообщению.

## Что это значит для проекта

Использовать JSON-проверку для первого сообщения с алертом, ручной режим — для исследования сочетаний. Не обещать численную оценку, если таблица не подключена. Нормативные инструкции описывают действующие правила напрямую; история изменений хранится в Git и исследовательских заметках.
