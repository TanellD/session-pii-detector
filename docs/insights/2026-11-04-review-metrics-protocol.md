# Ревью постановки: эталон момента и проверка скора

- Дата: 2026-11-04
- Автор: не указан
- Связано: PR #19, задачи #10–#13

## Что увидели

В PR #19 F2 смешивает наличие алерта и своевременность, но не задаёт
полного подсчёта ранних и поздних срабатываний. Предложение F2-timely
опубликовано отдельно; оно пока не является решением команды.

CPE Match Rate требует эталонного числового скора. Если скор вычисляется
по фиксированной формуле, ожидаемое значение можно получить из эталонных
фактов и принадлежности человеку. Это проверяет реализацию формулы,
но не подтверждает качество её выбора. Для обученной шкалы числового
эталона из одной разметки момента алерта не следует.

В библиографии есть несовпадения с заголовками первоисточников.
Кроме того, источники описывают разные задачи: накопление риска по лицу,
покрытие повторных идентификаторов и маскирование текста нельзя считать
одним и тем же протоколом оценки.

## Что это значит для проекта

Рекомендация к обсуждению, не принятое решение:

- Согласовать полный протокол F2-timely, включая ранний, поздний и
  отсутствующий первый алерт; F2-session и offset оставить диагностическими.
- Offset считать на TP по F2-session, пропуски отражать отдельно.
- Разметчик фиксирует факты, принадлежность человеку и эталонный момент
  по согласованной инструкции; скор по фиксированной формуле считает скрипт.
- Не получать эталон теста из собственной шкалы каждой сравниваемой модели.
- CPE Match Rate убрать из обязательных метрик качества до выбора формулы;
  проверку фиксированной агрегации описать отдельно.
- Исправить библиографию и подкрепить каждый сильный тезис конкретным
  разделом источника; ограничения аналогов и отличие проекта ещё исследуются.

Разметка, принятые ADR и документы PR этой заметкой не изменяются.
