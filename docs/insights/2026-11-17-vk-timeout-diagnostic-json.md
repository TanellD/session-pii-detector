# Таймаут сети ломал запись диагностики, но не сохранённые страницы

- Дата: 2026-11-17.
- Автор: команда проекта.
- Связано: [план миллиона записей](../experiments/2026-11-16-vk-million-pair-sample.md), приложенный пользователем лог запуска.

## Что увидели

После повторных отказов VK с кодом 9 запрос завершился таймаутом TLS, упакованным в `urllib.error.URLError`. Затем обработчик остановки взял `error.reason` и передал его в JSON. У URLError это может быть объект TimeoutError, а не строка, поэтому возникла вторичная ошибка сериализации. Полученный лог не содержит успешных событий сохранения новых страниц.

## Доказательство

Сверка актуальных страниц плана показала прежний частичный корпус. Пересчитать сводку без сети:

```powershell
python -X utf8 tools/collect_vk_group_members.py --group vk --limit 1000000
```

Итог `complete_plan` относится к текущему плану, не к старому завершённому пилоту. `returned_items` показывает сумму полученных строк актуальных страниц до фильтрации; `pair_statistics.accounts` — принятые уникальные ID аккаунтов. Прежняя сводка без пересчёта отражала более раннюю выборку и могла вводить в заблуждение.

## Что это значит для проекта

Сохранённый кеш пригоден для офлайн-анализа; сетевой отказ не означает потерю предыдущих страниц или завершение миллиона. Добавлен `failure_summary`: в диагностику попадают только безопасный тип, целочисленный код и фиксированные обозначения `network_timeout`/`network_error` либо разрешённая причина ApiFailure. Произвольное содержимое исключений не выводится. Сетевые таймауты этим исправлением не устраняются, успешная новая выгрузка не заявляется.

Синтетическая проверка причины-исключения, сериализации и отсутствия чувствительного текста: `python -X utf8 -m unittest discover -s tests -p 'test_vk*.py'`.
