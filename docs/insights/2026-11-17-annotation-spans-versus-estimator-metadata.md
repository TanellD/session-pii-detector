# Минимальная разметка не требует ручных статистических атрибутов

- Дата: 2026-11-17.
- Автор: исследование проекта.
- Связано: [инструкция MVP](../data/annotation-guidelines.md), [формат](../data/schema.md).

## Что увидели

Пользователь ограничил MVP полными сущностями с границами, типом и принадлежностью. Поля полноты, роли, личного контакта и точности работодателя из исследовательского калькулятора не должны становиться обязательными ручными полями сущности.

Привязка в минимальном формате имеет заранее описанную семантику: личный контакт, адрес проживания, работодатель. Иной/неподтверждённый контекст сохраняется с неизвестной персоной. Неизвестные сущности не группируются автоматически в одно лицо. Полные технические/цитируемые сущности сохраняются без привязки к известному человеку; красное правило при этом остаётся самостоятельным по прежнему решению.

## Доказательство

Минимальный контракт и вымышленные сценарии с разногласиями:

```powershell
python -X utf8 tools/annotation_contract.py --check-cases tests/fixtures/annotation-mvp-cases.json
python -X utf8 -m unittest discover -s tests -p test_annotation_contract.py
```

## Что это значит для проекта

ФИО/пара с полным личным адресом даёт качественный алерт без знания числа жильцов. Статистические средние нужны для другого пути оценки; их отсутствие не блокирует качественное правило и не заполняется вымышленным коэффициентом. Организация остаётся жёлтой. Исправления сохраняются в новых спанах, а текущая часть ФИО обновляется без переписывания истории.
