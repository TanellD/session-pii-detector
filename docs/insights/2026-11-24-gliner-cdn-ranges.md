# Большой GET весов GLiNER зависает, диапазоны байтов проходят

- Дата: 2026-11-24.
- Автор: команда проекта.
- Связано: локальная установка GLiNER и повтор оценки сессионного сервиса.

## Что увидели

Подготовка модели через `snapshot_download` остановилась на большом файле
`model.safetensors` без записи байтов. Получение метаданных с Hugging Face
и GET небольшого диапазона с официального CDN проходили. Это указывает
на проблему способа доставки большого файла в этом окружении, но не
устанавливает её сетевую причину.

## Доказательство

`tools/download_gliner_ranges.py` получает размер, URL и ETag через
официальный API с закреплённой revision. Затем проверяет `Content-Range`
каждой части и SHA-256 собранного файла по ETag до включения весов в кеш.
Неполные части можно загрузить повторно. Скрипт не меняет checkpoint,
конфиг модели и правила сервиса; токен не требуется.

Воспроизведение из worktree:

```powershell
.\.venv-gliner\Scripts\python.exe -X utf8 tools/download_gliner_ranges.py
.\.venv-gliner\Scripts\python.exe -X utf8 -m unittest discover -s tests -p 'test_download_gliner_ranges.py'
```

Тесты без сети проверяют корректный файл, отказ при неверном диапазоне
и отказ при несовпадении хеша.

## Что это значит для проекта

При повторении такого зависания можно использовать загрузчик диапазонов,
после него запускать штатный `benchmarks.pii_smoke.prepare`. Проверка TLS
и проверка целостности остаются включёнными. Сырые веса, части и кеш
хранятся в игнорируемых каталогах вне Git.
