# Невалидный модельный кандидат блокирует корректный regex-результат

- Дата: 2026-11-24.
- Автор: команда проекта.
- Связано: [реальный прогон GLiNER](../experiments/2026-11-24-gliner-runtime-250.md).

## Что увидели

GLiNER успешно загрузилась и выполнила инференс, но часть выходов адаптера
не соответствует контракту сервиса. Pipeline валидирует каждый спан до
разрешения пересечений. Один неверный EMAIL или AGE останавливает обработку
сообщения с HTTP 502, даже если regex одновременно нашёл правильное значение.

## Доказательство

В синтетической `synthetic-1000-0006` модель пометила «Личная почта» как EMAIL,
а regex нашёл полный `owner2@example.invalid`. Ошибка первого кандидата не
позволила использовать второй. В `synthetic-1000-0092` модель выделила возраст
словами, который текущий контракт исключает.

Воспроизведение без нового инференса:

```powershell
.\.venv-gliner\Scripts\python.exe -X utf8 tools/evaluate_random_linker.py --directory data/experiments/random-linker-250-gliner-2026-11-24 --mode gliner --model-dir outputs/gliner-prepared --reuse-recordings
```

Причины и ID сессий — `evaluation.json`, `runs[].runtime_failures`.
Записанные реальные выходы — `detector-recordings.json`. Оценщик сохраняет
ошибки, проверяет их воспроизведение через HTTP и публикует метрики успешного
среза с покрытием. Сессия с ошибкой не объявляется безопасной отрицательной.

## Что это значит для проекта

Одной общей проверки PHONE недостаточно: аналогичная проверка формата нужна
для других модельных типов до их передачи в Pipeline. Либо потребуется
отдельно согласованное поведение обработчика для невалидного кандидата.
Правила адаптера и контракт сервиса этим экспериментом не менялись.
