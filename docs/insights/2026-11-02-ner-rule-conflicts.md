# Контрольная сумма и NER требуют разных проверок

- Дата: 02.11.2026.
- Автор: `Kopylov-Andrey`.
- Связано: #12, [CPU-эксперимент](../experiments/archive/2026-11-02-gliner-cpu-v1.md).

## Что увидели
GLiNER дал PHONE поверх диагностического ИНН; слияние по одному типу оставило
оба сигнала. Повторное суммирование такого фрагмента способно создать ложный алерт.

## Доказательство
`inn` в `runs/task12-smoke/combined.json`; команда:
`python -m benchmarks.pii_smoke.report --input runs/task12-smoke` для исходного v1.
Все агрегаты и скорость CPU приведены в отчёте с командами воспроизведения.
В combined: TP/FP/FN = 24/11/7 при точных границах, медиана CPU 268.971 ms,
p95 313.528 ms. Это диагностический набор коротких фраз, не сессионный F2.
Независимый повтор в новом окружении сохранил predictions и scores v1;
[v2 и таблица покрытия](../experiments/2026-11-02-gliner-cpu.md) вынесены отдельно.

## Что это значит для проекта
Нужны нормализация и конфликты между типами, а не только удаление дублей внутри
типа. Контрольная сумма подтверждает формат, не выдачу номера. Score модели не
является вероятностью правонарушения. Не складывать их в один показатель.
