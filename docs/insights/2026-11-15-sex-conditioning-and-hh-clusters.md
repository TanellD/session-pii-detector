# Пол учитывается условно; кластерные доли ролей не образуют готовый остаток other

- Дата: 2026-11-15.
- Связано: [формулы и запуск hh](../research/notes/sex-name-probabilities-and-hh-runbook-2026-11-15.md).

## Что увидели

Разделение пола и имени на маргинальные таблицы не делает их независимыми. При использовании общей частоты имени дополнительный множитель должен быть долей указанного пола среди носителей имени, а не долей пола во всём населении. Кластерные счётчики ролей hh также могут пересекаться; их сумма не является гарантированно знаменателем непересекающегося распределения.

## Доказательство

Точная формула условной вероятности и план проверки частот приведены в связанной заметке. [Документация hh](https://api.hh.ru/openapi/redoc#tag/Poisk-vakansij/operation/get-vacancies) описывает кластеризацию поиска и ограничения доступа. Пробный запуск `python -X utf8 tools/collect_hh_occupation_statistics.py` из текущей среды вернул HTTP 403; скрипт вывел диагностический блок без тела ответа и без персональных данных. Агрегаты вакансий не получены.

Синтетические проверки: `python -X utf8 -m unittest discover -s tests -p test_hh_occupation_statistics.py`. Они покрывают пересечения ролей, недоступный кластер, деление веса вакансии, повторные ID, отсутствие ID, частичный сбор и отсутствие токена/тела ошибки в логе.

## Что это значит для проекта

В калькуляторе сохраняется пол; выбирается согласованный путь условного расчёта. Для hh отдельно сохраняются маргинальные кластерные счётчики и распределение с разделённым весом в ограниченной выборке. По недостающим или пересекающимся агрегатам `other` не выдумывается.
