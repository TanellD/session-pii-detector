# Рабочий сервисный ключ не даёт доступ к users.search

- Дата: 2026-11-16.
- Автор: команда проекта.
- Связано: [проверка VK API](../research/notes/vk-api-name-pairs-setup-2026-11-16.md).

## Что увидели

Предоставленный пользователем сервисный ключ принят служебным методом времени, но отклонён поиском пользователей. Это отделяет неработающий ключ от недоступности конкретного метода для проверенного доступа приложения.

## Доказательство

Команда: `python -X utf8 tools/collect_vk_name_pairs.py --probe-service`. Обезличенный результат сохранён в `data/private/name-dependence/vk-service-token-access.json`: utils.getServerTime доступен, users.search возвращает 1051. Текстовое значение этого номера по неполной схеме не угадывается.

[Официальная схема методов users](https://raw.githubusercontent.com/VKCOM/vk-api-schema/master/users/methods.json) перечисляет для поиска только user, [схема utils](https://raw.githubusercontent.com/VKCOM/vk-api-schema/master/utils/methods.json) допускает service для времени. Секрет сохранён в `.env` отдельно от пользовательского токена и не включён в отчёт.

## Что это значит для проекта

Сервисный ключ не заменяет требуемый пользовательский доступ к поиску. Готовой выборки VK по этому тесту не получено. Не подменять токен VK ID ключом приложения и не считать успешный служебный запрос доказательством доступности всех методов.
