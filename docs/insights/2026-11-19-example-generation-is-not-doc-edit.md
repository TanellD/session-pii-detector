# Перегенерация примеров пересчитывает флаги

- Дата: 2026-11-19.
- Автор: команда проекта.
- Связано: [уточнения и проверка Gemma](../experiments/2026-11-19-annotation-100-gemma.md).

## Что увидели

`tools/build_annotation_mvp_examples.py` не только формирует текст инструкции: он повторно вызывает текущий `assess` и заменяет `case_flags` старых учебных кейсов. Поэтому его запуск для добавления поясняющей таблицы может попутно изменить исторические пометки, включая снятие прежней причины `person_attribution`.

## Доказательство

В функции `build` присваивание `case["annotation"]["case_flags"] = assess(...)["case_flags"]` выполняется перед записью `tests/fixtures/annotation-mvp-cases.json`. Затем из того же массива формируется `docs/data/annotation-synthetic-examples.md`. Проверить реализацию можно поиском `rg -n 'case_flags|write_text' tools/build_annotation_mvp_examples.py` без перезаписи файлов.

## Что это значит для проекта

Новая поясняющая таблица сохранена отдельно в `docs/data/annotation-boundary-examples.md`. Побочные изменения после пробной генерации отменены только в затронутых собственным запуском файлах; прежний набор и его флаги сохранены. Пересборку старого учебного набора следует рассматривать как отдельное изменение данных с разбором отличий, а не как способ отредактировать документацию. Сам генератор в этой задаче не изменён.
