# Почему высокая оценка Gemma-линкера не доказывает качество на сложных диалогах

Дата: 2026-11-24.

Проверены оценщик `tools/evaluate_gemma_linker.py`, `pairwise()` из `tools/evaluate_random_linker.py` и структура фиксированного снимка. Эталонные владельцы не передаются модели: ReferenceDetector возвращает только тип и границы спана, карточки предыдущих людей строятся из предсказаний. Это проверка пути подготовки входа, а не доказательство отсутствия всех возможных утечек.

Структура среза воспроизводится из корня worktree:

```powershell
.\.venv-gliner\Scripts\python.exe -X utf8 tools/profile_linker_snapshot.py
```

Из 250 сессий 58 не содержат эталонных сущностей, 134 содержат ровно одного известного владельца, 38 — несколько известных владельцев, 20 — только неизвестные атрибуты. Эти четыре группы образуют разбиение среза. В 111 сессиях меньше двух упоминаний с известным эталонным владельцем: такие сессии вообще не дают пар для pairwise. Есть 25 сессий с совместной принадлежностью; это пересекающийся дополнительный срез. Длины: 66 сессий по два сообщения, 153 по три, 28 по четыре и три по пять сообщений. Всего 40 семейств сценариев.

Следствия:

- Эталонные спаны исключают ошибки детекции и дают модели типы и границы. Эти метрики нельзя называть качеством полного NER-сервиса.
- У пустых сессий точное совпадение групп получается без вызова модели. Это повышает session exact match; pairwise F1 от пустых сессий не увеличивается, поскольку TN и пустые сессии не входят в его формулу.
- Pairwise оценивает пересечение владельцев у пары известных упоминаний. Неизвестные эталонные владельцы исключаются; сессии без пары не оцениваются этой метрикой. Это не точность назначения каждого атрибута и не полная оценка множеств владельцев общих атрибутов.
- Точное совпадение групп учитывает неизвестных и множественных владельцев, но не сравнивает флаг `service_contact`. Это отдельный пробел покрытия оценки.
- Ошибка владельца может не изменить первый алерт. F2 с весом recall может оставаться высокой при ложных алертах: для оценки обязательно смотреть Precision и исходные счётчики отдельно.
- Короткие шаблонные сценарии и отладка на части этого же среза ограничивают переносимость результата. Срез не является независимым holdout.

Следующий эксперимент: отдельно показать результаты на непустых сессиях, нескольких владельцах, совместных атрибутах и неизвестных; добавить оценку служебных контактов и независимые новые сценарии с длинным контекстом, неоднозначностями и сменой говорящего. Сравнить Gemma с простым baseline «все атрибуты одному человеку» на тех же входах. Качество полного сервиса измерить отдельно с выходами реального детектора. Текущий прогон и его промпт не меняются.
