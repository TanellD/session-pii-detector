# Сумма весов сервиса отличается от статистического эталона

- Дата: 2026-11-20.
- Автор: команда проекта.
- Связано: [контракт каркаса](../api/service-scaffold.md), PR #44.

## Что увидели

Сервису задана сумма весов 0,1/0,3/1,0 и два порога 0,5. Ранее обработчик использовал оценку круга лиц и сочетания. Это разные политики принятия решения; уверенность NER также не является весом риска.

## Доказательство

Синтетические случаи воспроизводятся командой `.venv-service\Scripts\python.exe -X utf8 -m unittest discover -s tests/service -p test_risk.py -v`.

Неизвестные телефон + email срабатывают по сумме, хотя правило сочетаний для неизвестных отключено. Адрес + телефон человека срабатывают по сумме, не входя в качественный список сочетаний. Сумма ровно на пороге не срабатывает. Отдельные части ФИО не учитываются повторно после сборки.

## Что это значит для проекта

Сервис возвращает версию `runtime-risk-v1`. Прежние эталоны и метрики нельзя объявить проверкой качества этой политики без подготовки эталона под неё. ТЗ разметки, исходные метки и принятые ADR не меняются. Подтверждённые служебные контакты линкер отличает от просто неизвестной принадлежности: первые не участвуют в сумме.
