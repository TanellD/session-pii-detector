# Изменение правил требует новой версии эталона

- Дата: 2026-11-22.
- Автор: команда проекта.
- Связано: PR #46, эксперимент 2026-11-22-corpus-finalization.

## Что увидели

Ранее списки совместных владельцев при оценке превращались в null, а неправильная checksum удаляла только основание алерта. Это расходилось с интеграционным контрактом. Сохранённый старый gold нельзя считать эталоном новой политики.

## Доказательство

Регрессии tests/test_corpus_finalization.py и tests/test_multi_owner_annotation.py, команда python -X utf8 -m unittest discover -s tests. Сборщик проверяет достаточность и активность опорных спанов отдельно для каждого владельца.

## Что это значит для проекта

Общий личный факт участвует в каждом профиле без объединения людей. Невалидные документы остаются в тексте как отрицательные примеры, без документного спана. Миграция сохраняет исходники и явно требует новой разметки первого алерта. Веса сервиса не являются источником gold.
