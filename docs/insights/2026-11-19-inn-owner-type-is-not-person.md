# Тип реквизита не определяет конкретную персону

- Дата: 2026-11-19.
- Автор: команда проекта.
- Связано: [сто синтетических сессий Gemma](../experiments/2026-11-19-annotation-100-gemma.md), PR #44.

## Что увидели

В учебном синтетическом кейсе «ИНН физического лица: 000000000000» модель создала безымянную персону. Авторский эталон оставил неизвестного владельца: «физического лица» обозначает тип реквизита, а не отдельного описанного человека. Пользователь подтвердил вариант `person_id=null`.

## Доказательство

Кейс `synthetic-002`, сообщение `m2`, источник `data/experiments/annotation-100-2026-11-19/`, ответ `data/experiments/radeon/2026-11-19-annotation-100-gemma-02/02-m02-model-output.json`. Это нулевой синтетический суррогат, а не реальный ИНН. Сравнение воспроизводится `python -X utf8 tools/report_annotation_100.py --check` после завершения запуска и построения отчёта.

## Что это значит для проекта

Рабочая инструкция явно запрещает создавать персону из одного названия типа реквизита. Красный алерт сохраняется независимо от владельца. Сессионное совпадение алертов само по себе не доказывает правильность привязки атрибутов. Эталон и промпт уже начатого запуска не переписываются после обнаружения расхождения.
