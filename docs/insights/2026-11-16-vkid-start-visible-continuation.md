# Явная страница продолжения вместо пустого шага /start

- Дата: 2026-11-16.
- Автор: команда проекта.
- Связано: `tools/authorize_vk_id.py`, `tests/test_vk_id_authorization.py`.

## Что увидели

Пользователь сообщил о пустом `localhost/start`. В этот момент локальные `/` и `/status` отвечали, состояние оставалось `waiting_for_application`; зависание сервера больше не воспроизводилось. Точный ответ, полученный браузером пользователя, не перехватывался. Ранее некоторые защитные отказы возвращали визуально пустую страницу, а успешный POST сразу перенаправлял во внешний провайдер.

## Доказательство

Изменена цепочка: POST `/start` → локальный `/continue` с явной ссылкой на официальный адрес авторизации. Для отклонённого Origin, устаревшей формы и неправильного адреса добавлены видимые сообщения. Защитные проверки не отключены. GET `/start` открывает страницу возврата к форме.

Команда проверки: `python -X utf8 -m unittest discover -s tests -p test_vk_id_authorization.py`. Синтетический HTTP-тест проверяет локальное перенаправление, ссылку продолжения и непустые ошибки при неверном nonce и Origin. После перезапуска реальные локальные страницы отвечали, данные авторизации при проверке не отправлялись.

## Что это значит для проекта

Обработка ошибок и переходы авторизации должны оставлять пользователю видимое состояние. Успешные HTTP-проверки локальной формы не доказывают завершённый вход VK ID: следующий шаг остаётся за пользователем в браузере.
