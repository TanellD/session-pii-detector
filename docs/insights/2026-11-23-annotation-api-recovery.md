# Проверка большого корпуса требует сохранения покрытия после сбоев API

- Дата: 2026-11-23.
- Автор: команда проекта.
- Связано: [сравнение корпусов](../experiments/2026-11-23-andrey-500-comparison.md).

## Что увидели

Первый массовый последовательный прогон Gemma после исправления JSON-схемы
получает валидные ответы, но затем останавливается на тайм-аутах и HTTP 429.
Это не даёт оснований объявить оставшиеся сессии отрицательными или модельно
проверенными. Причина квоты и поведение серверной задачи после тайм-аута не
установлены.

При проверке статуса в логах Qwen также найден `RemoteDisconnected`: сервер
закрывал соединение без HTTP-ответа. Этот тип не попадал в прежний список
обрабатываемых исключений, из-за чего процесс батча завершался без `finished_at`.
Он добавлен в сетевые повторные попытки и финальную фиксацию ошибки шага.
Неудачные старые батчи сохранены; восстановление включает их незавершённые сессии.

## Доказательство

В `data/experiments/radeon/annotation-1000-gemma-2026-11-23-v2/batch-001/run/manifest.json`
сохранены `TimeoutError` и HTTP 429. Внешние ответы не заменены авторским gold.
Проверка механизма продолжения без API:

```powershell
python -X utf8 -m unittest discover -s tests -p test_annotation_recovery.py
```

Тесты проверяют повтор того же запроса при временном отказе, ограничение числа
попыток, отказ от повторения постоянной ошибки авторизации и исключение только
полностью завершённых сессий из нового прогона. Частичные сессии не выдаются за
завершённые. Прежние файлы сохраняются.

## Что это значит для проекта

Модельную проверку нужно сопровождать покрытием и статусами запросов.
Повторы не должны зависеть от совпадения с gold: основание повторения —
незавершённая разметка, а не нежелательный результат.
Один логический запрос и число фактических API-попыток учитываются раздельно.
Временные ошибки повторяются с паузой; ошибки валидатора сохраняются и могут
потребовать разбора. Согласие оставшихся валидных сессий — условный результат,
а не качество на полном корпусе.
