# У маленького линкера размер модели не гарантирует короткий ответ

- Дата: 2026-11-25.
- Связано: [эксперимент MiniCPM](../experiments/2026-11-25-minicpm-linker-250.md).

## Что увидели

Доступная в настроенном API компактная `MiniCPM5-2B` с прежним бюджетом вывода израсходовала его на reasoning и не выдала итоговый JSON. С `reasoning_effort=none` ответ завершился, но назначения были пустыми при непустом входе. С `low` получен полный JSON исходного сообщения.

## Доказательство

Исходные запросы и ответы сохранены в `data/experiments/minicpm-linker-pilot-2026-11-25`, `minicpm-linker-reasoning-probe-2026-11-25` и `minicpm-linker-low-reasoning-probe-2026-11-25`. Полный запуск использует отдельный конфиг; порядок, промпт и данные Gemma не переписываются.

## Что это значит для проекта

Прежде чем запускать лёгкий линкер на всём наборе, нужно проверить завершённость ответа и соответствие списку кандидатов. Небольшая модель может тратить время на рассуждения и не давать ускорения. Сравнение должно включать ошибки контракта и покрытие, а не только качество успешных ответов.

Первые сессии полного запуска показали, что `low` не устраняет обрезание вывода полностью. Дополнительная доступная `MiniCPM-V-4.7-1B` с `none` вернула завершённый JSON, но оставила обоих явно названных людей неизвестными; ответ сохранён в `data/experiments/minicpm-v-1b-probe-2026-11-25`. Быстрая генерация и правильный JSON должны оцениваться отдельно от правильной атрибуции.
