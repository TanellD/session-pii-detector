# Заглушка компонента и недостаток статистики — разные состояния

- Дата: 2026-11-20.
- Автор: команда проекта.
- Связано: [каркас сервиса](../api/service-scaffold.md).

## Что увидели

Пустой список сущностей сам по себе не отличает чистое сообщение от незаполненной реализации NER. Если заглушка возвращает только пустой список, внешняя система может принять отсутствие выполненного анализа за проверенное отсутствие сигнала.

## Доказательство

`StubNER`, `StubRegexp` и `StubLinker` возвращают `complete=False` с отдельными машинными причинами. Проверки `test_default_stubs_are_explicitly_incomplete`, `test_unknown_contacts_do_not_form_person` и `test_proven_red_alert_survives_incomplete_components` в `tests/service/test_runtime.py` воспроизводятся командой `.venv-service\Scripts\python.exe -X utf8 -m unittest discover -s tests/service -v`.

## Что это значит для проекта

`coverage_complete` показывает полноту выполнения компонентов. `annotation_uncertain` относится к недостатку статистики при расчёте принятого вердикта; неизвестный владелец выражен через `person_id=null`. Эти состояния не подменяют друг друга. Достаточный красный алерт сохраняется и при неполноте других компонентов. HTTP-клиент должен отдельно обрабатывать неполное покрытие; отсутствие алерта при заглушках не является разрешением пропустить сообщение.
