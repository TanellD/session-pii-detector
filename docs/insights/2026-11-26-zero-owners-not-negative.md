# Ноль известных владельцев не гарантирует отсутствие алерта

- Дата: 2026-11-26.
- Автор: разбор правил при группировке корпуса.
- Связано: [политика генерации v3](../data/synthetic-session-generation-policy.md).

## Что увидели

При подсчёте людей по уникальным ненулевым `person_id` нулевая группа может содержать документ неизвестного владельца. По действующему ТЗ красное правило не требует установленного владельца.

## Доказательство

В [правилах разметки](../data/annotation-guidelines.md) прямо указано: полный красный маркер с допустимой контрольной суммой даёт алерт и при неизвестном владельце. Неизвестные упоминания при этом сохраняют `person_id=null` и не образуют одного общего человека.

## Что это значит для проекта

Для группы только с FP/TN нужны специально отрицательные нулевые контроли. Существующие положительные документы с неизвестной принадлежностью нельзя переобозначать отрицательными или удалять при группировке; они отмечаются исключениями. Это ограничение состава контролей, а не изменение семантики алерта.
