# Перенос модели и bypass должны быть явными частями конфигурации

- Дата: 2026-11-26.
- Связано: [runtime Docker v2](../api/docker-service-v2.md).

## Что увидели

Подготовленный GLiNER содержит абсолютный Windows-путь в model_name.
Неизменённый каталог нельзя просто смонтировать в Linux по другому пути.
При локальном Windows-запуске сторонняя библиотека также прочитала UTF-8
конфигурацию неверной кодировкой без режима Python UTF-8; startup завершился
до открытия API. Readiness не должна подтверждать такую модель.

В проверке Docker Desktop загрузка из Windows bind-mount не подтвердила
readiness до остановки теста; копирование тех же проверенных весов в Linux
volume и запуск текущего кода завершили startup. Поэтому для модельного Compose
выбран read-only Linux volume. Конкретный механизм разницы отдельно не изолирован.

Обход линкера оставляет неизвестных владельцев, но не делает обработку полной.
Латенси такого режима нельзя публиковать как время настоящего линкера или
качественную оценку владельцев.

## Доказательство

tools/relocate_prepared_model.py проверяет исходные хеши, создаёт отдельную
копию конфигурации для /models/gliner/backbone и пересчитывает manifest копии.
Тест test_relocation_retains_source_and_weight_hash проверяет неизменность
источника. tests/service/test_docker_runtime.py проверяет bypass без вызова API,
неполноту, readiness, лимит конкурентных запросов и отсутствие значений в логах.

Команда:

```powershell
python -X utf8 -m unittest discover -s tests/service -q
```

## Что это значит для проекта

Сохранять исходные исследовательские веса/manifest и переносимую копию отдельно.
Прогрев выполнять до готовности; на Windows запускать Python с -X utf8.
В отчёте нагрузки отдельно показывать HTTP-успехи, неполноту и выбранный режим
компонентов. Включение fallback не устраняет ошибку NER/нормализации.
