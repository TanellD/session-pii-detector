# Для проверки весов недостаточно воспроизвести их же порог в эталоне

- Дата: 2026-11-25.
- Связано: [корпус сочетаний](../experiments/2026-11-25-weight-combinations-300.md).

## Что увидели

Нужны разные основания: накопление только жёлтых, один оранжевый с жёлтыми, повторы и раздельные владельцы. Если метки получить текущей суммой сервиса, высокий результат будет показывать воспроизведение формулы, а не обоснованность весов.

## Доказательство

В новом корпусе метки заданы отдельно как предварительная авторская гипотеза; генератор не загружает runtime-веса. При подаче правильных спанов и владельцев текущая политика расходится с авторским моментом алерта. Числа и команды — в связанном эксперименте, oracle-risk.json содержит шаги и причины. Положительные решения для профессиональных профилей без контактов ещё не согласованы с командой и не подтверждены статистикой уникальности.

NER на этом корпусе существенно лучше, чем на предыдущих сложных диалогах с искусственными именами, хотя модель и обе ревизии не менялись. Обычные имена и явные формулировки полей облегчают извлечение. Межкорпусную разницу нельзя выдавать за эффект доработки NER; для причинного сравнения нужны одинаковые тексты и одинаковый эталон.

## Что это значит для проекта

Раздельно исследуем качество извлечения/линковки, вычисление текущей формулы и согласие с авторскими предложениями. Рабочие веса нельзя обосновать только согласованностью с неподтверждённой авторской гипотезой: нужно ревью меток, затем отдельные данные для подбора и проверки. Инструкция annotation-guidelines.md и принятые ADR этим экспериментом не меняются.
