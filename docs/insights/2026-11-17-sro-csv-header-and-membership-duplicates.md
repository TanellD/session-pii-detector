# Реестр СРО: заголовки HTML и строки членства требуют отдельной проверки

- Дата: 2026-11-17.
- Автор: исследование проекта.
- Связано: [эксперимент ФНС/СРО](../experiments/2026-11-17-fns-sro-patronymics.md).

## Что увидели

У реестра Гильдии кадастровых инженеров заголовки находятся непосредственно в `thead`, без обрамляющего `tr`. Парсер, собирающий только строки `tr`, не увидел заголовок и отверг таблицу. Это ошибка предположения о разметке страницы, а не отсутствие ФИО в источнике. Добавлена синтетическая проверка такого случая.

CSV не следует интерпретировать по предполагаемым номерам столбцов: поля проверялись по совпадению с подписанной HTML-таблицей. Ячейка аттестата CSV содержит поясняющий текст; сравнение всей ячейки с номером не сработало. Для итогового корпуса использована штатная пагинация HTML. Строки действующего и предыдущего членства могут относиться к одному аттестату и одному написанию ФИО.

## Доказательство

[Открытый реестр и ссылка выгрузки](https://kadastrsro.ru/index.php/reestr/). Проверка без вывода персональных строк:

```powershell
python -X utf8 tools/study_fns_sro_patronymics.py --download-sro
python -X utf8 -m unittest discover -s tests -p test_fns_sro_patronymics.py
```

## Что это значит для проекта

Структурный отказ старого инспектора не доказывает непригодность источника. Перед частотным анализом нужны проверка соответствия полей, сворачивание согласованных повторных регистраций и исключение конфликтов. В итоговом сборе пройдена вся доступная HTML-пагинация; неполные CSV-попытки не использованы как полный реестр. Сырые CSV и HTML с дополнительными полями на диск не сохраняются.
