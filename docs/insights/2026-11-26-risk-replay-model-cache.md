# Пороги риска можно менять без повторного вызова моделей

- Дата: 2026-11-26.
- Связано: [прогон validation с кэшем](../experiments/2026-11-26-cached-validation-risk-calibration.md), PR #47.

## Что увидели

В текущем Pipeline линкер получает кандидатов, факты и прошлые сообщения, но не оценку риска. При обработке всех сообщений до конца изменение весов и порогов риска не меняет извлечение и владельцев. Меняется только первое сообщение алерта при локальном повторном накоплении тех же фактов.

## Доказательство

Контракт находится в `src/session_pii/pipeline.py` и `src/session_pii/gemma_linker.py`. Тест `test_cached_risk_calibration.py` сравнивает локальный матричный расчёт с реальным RiskEvaluator, включая строгое сравнение на границе порога. Команда теста и воспроизведения — в связанном эксперименте.

## Что это значит для проекта

Сохранять модельный этап отдельно от риск-решений. Кэш ответа линкера должен включать весь запрос, а не только текст текущего сообщения: изменение кандидатов или прошлой линковки меняет задачу. Нельзя переносить обещание повторного использования риска на произвольное изменение confidence NER или промпта.

При восстановлении `Span` из JSON строгая модель Pydantic требует JSON-валидации: `model_validate_json` восстанавливает кортеж provenance, тогда как `model_validate` над прочитанным словарём отвергает JSON-массив. Это проверяется тестом roundtrip кэша. Ошибка чтения не требует повторять уже сохранённый NER.
