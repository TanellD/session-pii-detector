# Порядок сценариев попал в значения контактов и связан с меткой

- Дата: 2026-11-26.
- Связано: [содержательный аудит пилота](../experiments/2026-11-26-difficulty-pilot-quality-audit.md).

## Что увидели

Генератор детерминированно назначает значения по индексу семейства, а положительные семейства в плане стоят раньше отрицательных. В результате числовые части телефонов, email и других полей различаются между классами. При этом формальные проверки схемы, checksum, алертов калькулятора и разделения семейств успешно проходят.

## Доказательство

`tools/audit_dialogue_fairness.py` из связанного эксперимента извлекает коды из самих сообщений и показывает непересекающиеся диапазоны для покрытых им положительных и отрицательных диалогов. Это не признак реальной идентифицируемости. Инструмент не доказывает, что оцениваемая модель уже использует этот признак, но показывает доступную ей искусственную зависимость.

## Что это значит для проекта

Значения нужно назначать независимо от класса, сложности и порядка семейств, сохраняя безопасную синтетичность. Разделение по ID и профилям недостаточно для честного benchmark. До расширения необходимо проверять распределения значений и содержательные подсказки; структурную корректность и пригодность для оценки нужно фиксировать раздельно.
