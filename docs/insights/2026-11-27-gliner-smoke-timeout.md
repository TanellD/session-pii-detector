# Таймаут smoke-клиента не доказывает отказ GLiNER

- Дата: 2026-11-27.
- Автор: команда проекта.
- Связано: PR #48, [Docker runtime v2](../experiments/2026-11-26-docker-service-v2.md).

## Что увидели

Первый smoke модельного Docker API прервался на analyze по клиентскому таймауту.
Повтор с увеличенным явным лимитом прошёл, включая retry, историю и выделение
синтетического СНИЛС с алертом. Причина первой задержки отдельно не установлена.

## Доказательство

При работающем GLiNER-контейнере воспроизводится проверка, но сама задержка
может не повториться:

```powershell
python -X utf8 tools/smoke_service.py --base-url http://127.0.0.1:8022 --expect-adapter
python -X utf8 tools/smoke_service.py --base-url http://127.0.0.1:8022 --expect-adapter --timeout 60
```

Первый запуск использует стандартный лимит 10 секунд; второй задаёт 60 секунд
для каждого HTTP-вызова. Результат повторной проверки: status=ok, mode=gliner,
exact_retry=true, extraction_checked=true; linker bypass явно сообщает неполноту.

## Что это значит для проекта

Функциональный smoke и стабильность latency нужно оценивать отдельно. Увеличение
лимита клиента не меняет таймауты сервиса и не устраняет причину задержки.
