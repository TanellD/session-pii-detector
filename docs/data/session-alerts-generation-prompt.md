# Промпт для синтетических сессий

Этот промпт относится к пилотному корпусу. Для новых наборов используйте [переиспользуемую политику и шаблон задания](synthetic-session-generation-policy.md): состав, сложность и объём задаются параметрами, эталонные алерты рассчитываются существующим калькулятором.

Составь русскоязычные сессии пользователя для оценки извлечения атрибутов,
линковки и первого алерта. Используй ТЗ проекта и правила версии корпуса
из [описания набора](session-alerts-pilot.md).

Сначала задай для каждой сессии сценарий, вымышленных людей, их локальные
ID, типы атрибутов и реплики, на которых они появятся. Раздели сценарии на
development и test по семействам и профилям. Напиши реплики после плана.

- Покрой независимые личные контакты разных людей, общий телефон и личную
  почту одного владельца, повтор общего контакта и общий адрес проживания.
- Добавь неизвестного владельца с поздним уточнением. Не меняй владельца
  старого спана задним числом. Новое явное упоминание разметь отдельно.
- Подготовь полные синтетические ИНН, СНИЛС и карты с валидной и невалидной
  контрольной суммой. Держи положительные и отрицательные проверки в разных
  сессиях. Добавь короткие и длинные телефоны, имя рядом со словом «фамилия»,
  общий PERSON и пересечение типов. Для полного адреса выделяй адрес целиком.
- Для известного владельца запиши локальный ID, для общего атрибута —
  список известных владельцев, для неизвестного — `null`. Список означает
  явную совместную принадлежность. Границы задай по точной цитате в
  исходной реплике.
- Используй вымышленные имена, адреса, почту в `example.invalid` и
  синтетические номера. Не бери данные из реальных переписок и профилей.
  Проверяй контрольные суммы локально функциями
  `benchmarks/pii_smoke/regex_detector.py`.

Верни `scenario-plan.json` и `authored-dialogues.json` в формате корпуса.
Для этой схемы добавь в сценарный план `"review_policy": "pr46-review-v2"`.
Поле `version` используй для версии нового набора.
Сверь реплики с планом и убери незапланированные атрибуты. После проверки
спанов запиши авторскую разметку первого алерта в отдельный
`author-alert-ledger.json`. Оценивай каждый префикс на момент его появления
по ТЗ. Записывай основание, опорные спаны и причину неуверенности. Результаты
сервиса и его веса не используй как эталон.

## Уточнения текущей версии

Невалидный документ оставь в исходной реплике как отрицательный пример, но не создавай для него документный спан. У общего личного атрибута список владельцев означает участие в каждом их профиле; остальные факты владельцев не объединяются. Общая служебная линия не становится личным телефоном. Общий person сохраняется без назначения частей имени и не образует правило пары частей. Извлечение, владельцев и эталонные алерты проверяй раздельно. Старые решения по другой политике не копируй автоматически.
