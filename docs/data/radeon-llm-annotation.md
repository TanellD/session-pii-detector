# Разметка через Radeon Cloud и собственный сервер

Точные ID из предоставленных пользователем карточек Radeon Cloud: `Gemma-4-31B-IT` и `Qwen3.8-27B`. Общий адрес: `https://developer.amd.com.cn/radeon/api/v1`. В карточках points названы относительным расходом, а не денежной ценой. Эти значения не задают суточную квоту и не гарантируют постоянную бесплатность.

Конфиг провайдеров: `configs/llm-annotation-providers.json`. Новый runner — `tools/run_compatible_annotation_pilot.py`; прежний OpenAI Responses runner сохранён отдельно. Контракт разметки, промпт, валидатор и обработчик правил общие.

## Ключ и проверка без сети

Добавьте только в локальный `.env`:

```dotenv
RADEON_API_KEY=
```

Заполните значение локально, не отправляя его в чат. `.env` не входит в Git. Runner также читает одноимённую переменную окружения. Для собственного сервера необязательный ключ задаётся как `LLM_API_KEY`.

Из корня проекта:

```powershell
python -X utf8 tools/run_compatible_annotation_pilot.py --model Gemma-4-31B-IT --dry-run
python -X utf8 tools/run_compatible_annotation_pilot.py --model Qwen3.8-27B --dry-run
```

Вход по умолчанию — исходные синтетические `sessions.json` первого пилота. Ожидания и сохранённые аннотации в модель не передаются. Если этого локального файла нет, создайте новый пилот командой `python -X utf8 tools/build_llm_annotation_pilot.py --output data/experiments/radeon-source-01` и добавьте `--input data/experiments/radeon-source-01/sessions.json` к командам runner. Существующий каталог генератор не перезаписывает.

## Сетевая проба и запуск

Сначала один короткий синтетический запрос на модель:

```powershell
python -X utf8 tools/run_compatible_annotation_pilot.py --model Gemma-4-31B-IT --probe
python -X utf8 tools/run_compatible_annotation_pilot.py --model Qwen3.8-27B --probe
```

По умолчанию запрашивается `response_format=json_schema`. Успешный JSON в пробе подтверждает приём запроса и корректный ответ на него, но не доказывает принудительное исполнение схемы сервером или качество разметки. Если провайдер не поддерживает этот режим, используйте явно `--response-format json_object` либо `--response-format prompt` после проверки причины ошибки. HTTP-ошибка сама по себе не доказывает отсутствие Structured Outputs. Автоматического переключения формата нет; выбранный режим записывается в манифест.

Небольшой раздельный запуск:

```powershell
python -X utf8 tools/run_compatible_annotation_pilot.py --model Gemma-4-31B-IT --span-mode quotes --limit 2 --output data/experiments/radeon/gemma-run-01
python -X utf8 tools/run_compatible_annotation_pilot.py --model Qwen3.8-27B --span-mode quotes --limit 2 --output data/experiments/radeon/qwen-run-01
```

Выберите новый каталог для каждого следующего прогона. По умолчанию между сессиями есть пауза; запросы последовательные. Настройки `--delay`, `--timeout`, `--max-tokens` и `--temperature` доступны явно. Параметры thinking провайдеру не навязываются: их фактический режим и поддержку нужно уточнить отдельно. Если лимит ответа израсходован, результат не принимается за завершённую разметку.

Сохраняются исходный запрос без заголовка авторизации, полный ответ, проверенная аннотация, расчёт алерта и манифест. Последний содержит полный ID модели из запроса/ответа, формат, параметры, хеши входа/промпта/схемы/политики, usage и статус проверки человеком. Модель и ревизия локальных весов не считаются доказанно совпадающими с облачным alias.

По умолчанию при HTTP-ошибке, отказе, незавершённом или невалидном ответе runner сохраняет уже полученное и останавливается. Для сравнения всего набора доступен явный `--continue-on-failure`: после невалидного ответа или тайм-аута перейти к следующей сессии без повторения запроса; HTTP-ошибки всё равно останавливают прогон. Runner не удаляет Markdown, не исправляет границы сущностей и не меняет сообщения. Новый запуск не перезаписывает старый. Тела HTTP-ошибок и ключи в консоль не выводятся. Выход допускается только в игнорируемый новый каталог внутри `data/`.

## Повтор на своём сервере

Для границ доступны два явных режима. `--span-mode offsets` (по умолчанию) принимает числовые позиции модели без исправлений. В рекомендуемом `--span-mode quotes` модель возвращает транспортный `annotation-quotes-v1`: точную цитату `mention` и номер её вхождения `occurrence` в сообщении. Инструмент находит только это точное вхождение и создаёт финальный `annotation-mvp-v2` с Unicode-границами. Нормализация, поиск похожих слов и исправление цитаты не выполняются; отсутствующее вхождение отклоняется. Исходный транспортный ответ сохраняется отдельно. Это не оценка умения LLM самостоятельно считать позиции символов.

Нумерация `occurrence` ведётся отдельно для каждой точной строки: «Соня», «Соне», «Соню», встретившиеся по одному разу, имеют `occurrence=1`. Для двух точных повторов «Соня» нужны номера 1 и 2. Формы одного имени не образуют общий счётчик.

После развёртывания выбранных весов с Chat Completions API:

```powershell
python -X utf8 tools/run_compatible_annotation_pilot.py --provider local --base-url http://127.0.0.1:8000/v1 --model Qwen/Qwen3.8-27B --revision YOUR_CHECKPOINT_COMMIT --span-mode quotes --limit 2 --output data/experiments/local/qwen-run-01
```

ID должен совпадать с моделью, которую обслуживает ваш сервер. Для удалённого кластера используйте HTTPS и при необходимости `--api-key-env ИМЯ_ПЕРЕМЕННОЙ`. Значение ключа не передавайте аргументом. Зафиксируйте дополнительно версию runtime, тип квантизации и параметры контекста; `--revision` — запись оператора, а не автоматическая проверка весов.

## Что проверять в результатах

Формальная валидность не является качеством разметки. Человек проверяет границы и типы сущностей, принадлежность людям, флаги кейса и первый алерт. Сравнение двух моделей не заменяет независимый gold. Численность и причины алерта считает наш обработчик. Используйте только синтетический вход; реальный исследовательский кеш ФИО не входит в разрешённый набор этого runner.

Проверки реализации: `python -X utf8 -m unittest discover -s tests -p test_compatible_annotation_pilot.py`.
