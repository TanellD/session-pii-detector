# Синтетические атрибуты для проверки адаптера

Назначение: проверить преобразование меток и границ адаптера, но не качество детектора.
Набор не имеет `t_gold`, не является blind test и не является независимой оценкой.

## Вход

Файл `../../benchmarks/pii_smoke/data/synthetic-attributes.json` содержит сообщения
и аннотации преобразования для тестовой проверки. Все имена, адреса и номера
вымышленные или диагностические.

## Формат

```json
{
  "synthetic": true,
  "contract_version": "1.0.0",
  "cases": [
    {
      "id": "full_name",
      "text": "Меня зовут Лада Олеговна Макетова.",
      "transformation_hint": ["FIRST_NAME", "PATRONYMIC", "LAST_NAME"],
      "requires": "model"
    }
  ]
}
```

`transformation_hint` фиксирует ожидаемый проектный тип только для проверки
adapter-разборов. Он не является разметкой сессионного момента, не содержит
`t_gold` и не используется метриками качества модели.

`requires` задаёт режим проверки:

- `"regex"` — кейс проверяется и без модели, и с моделью;
- `"model"` — без `--with-model` кейс пропускается (`skipped`), чтобы не давать
  ложный failure; с `--with-model` проверяется.

## Выход

Проверка выводит JSON-сериализуемые Mention поля: `id`, `type`, `text`, `start/end`,
`confidence`, `confidence_kind`, `source`, `detector_version`.

## Ограничения

Набор маленький и специально составлен. Успешная проверка означает только совпадение
с заранее подготовленной трансформацией. Для отчета о качестве нужны независимые
данные и протокол из `docs/kb/metrics.md`.
