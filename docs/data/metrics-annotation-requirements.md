# Требования к разметке для расчёта метрик

Статус: проект требований для подготовки полного ТЗ в задаче данных #13.
Полной инструкции пока нет: [страница инструкции](annotation-guidelines.md)
имеет статус «не составлена». Этот файл её не заменяет и не является
готовой машинной схемой.

Основание: [метрики](../kb/metrics.md), обсуждение с лидом 08.11.2026.
Только синтетические данные согласно ADR-0002.

Перечень классов MVP берём из [PR #16](https://github.com/TanellD/session-pii-detector/pull/16),
с учётом [общего одобрения ментора](https://github.com/TanellD/session-pii-detector/blob/docs/mentor-round2-and-presentation/docs/meetings/2026-11-05-mentor-answers.md).
Не требуется заново выбирать все классы; нужны их машинные метки, правила границ
и согласование политики алерта отдельно от перечня извлекаемых атрибутов.

## Сессия и момент

- Устойчивый `session_id`, порядок и роли сообщений.
- На каждом шаге доступны текущее сообщение и предыдущий контекст,
  без пересмотра прошлого на основании будущих сообщений.
- Статус сессии: положительная, отрицательная или `unknown`.
  Для положительной — первый `t_gold` и основание по версии политики.
- Исправление факта позднее не стирает прошлый момент. Пока записываются
  первый момент и флаг дополнительных положительных моментов;
  дополнительные позиции не обязательны.
- Определение дополнительного момента согласуется до использования флага.
- Неуверенность отмечается у конкретного решения с причиной. Если она мешает
  определить наличие алерта или первый момент, сессия получает `unknown`.
  Неуверенный атрибут не делает всю сессию автоматически unknown.

## Атрибуты и люди

- Упоминание атрибута: устойчивый ID, сообщение, границы, тип.
- Новому человеку — локальный порядковый ID, его атрибутам — ссылки на ID.
  Номера людей между эталоном и системой могут различаться.
- Один атрибут допускает нескольких явно указанных владельцев.
- Неизвестная принадлежность — служебное «неопределённо», а не единый человек.
- Принадлежность на каждом шаге должна восстанавливаться без будущего контекста;
  формат хранения исправлений требуется согласовать.
- Разметчики не задают числовой скор: он вычисляется из атрибутов после
  выбора формулы.

## Перед выпуском версии данных

Согласовать каталог оснований алерта и спорных сценариев, соответствие
существующих классов машинным меткам, границы,
дедупликацию, исправления, неуверенность, разрешение разногласий,
дополнительный положительный момент и машинную схему.
