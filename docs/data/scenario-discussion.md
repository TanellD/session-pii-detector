# Сценарии для командного обсуждения

Для [#13](../project/data-research-summary.md) и
[#26](https://github.com/TanellD/session-pii-detector/issues/26).
Статус: материал к брейншторму, не утверждённый каталог и не инструкция разметчика.

Команда определяет, какие факты и их комбинации достаточны по принятой трактовке
ФЗ-152. Нельзя заранее считать каждый фрагмент безопасным: один признак может
оказаться достаточным в конкретном контексте. `n` галочек не универсальный порог.
В чеклисте нужны уникальные факты по отдельному человеку, а также отдельные правила
для признаков, которые требуют немедленного алерта.

Методический ориентир:
[Lee, Park, Son](https://doi.org/10.3390/app16083680),
[карточка источника](../research/notes/dialogue-onset-data.md).
Из него используем идею запланированных раскрытий и усложнения диалогов;
правила достаточности определяем для нашего проекта.

## Как читать примеры

Все фразы ниже придуманы для обсуждения и содержат плейсхолдеры.
`А` и `Б` обозначают разных вымышленных людей, `T` порядок сообщений.
Плейсхолдеры не являются готовыми тестами NER.
«Кандидат T» обозначает место проверки будущего правила, а не установленный момент ПДн.
Если правило не согласовано, эталон не назначается.

| ID | Сценарий и условный пример | Что обсуждаем о моменте |
|---|---|---|
| S-SELF | О себе: T1 «Работаю в [ОРГ_А]»; T2 «Моя должность [РОЛЬ_А]»; T3 «В нашем [ПОДРАЗДЕЛЕНИИ_А] я единственный с такой ролью» | Достаточна ли комбинация? Кандидат T3 только при принятии соответствующего правила; возможно, достаточно раньше |
| S-THIRD | О третьем лице: T1 «Моя коллега работает в [ОРГ_Б]»; T2 «Она [РОЛЬ_Б]»; T3 «Её имя [ИМЯ_Б]» | Принадлежность фактов Б и достаточность его профиля; не приписывать пользователю |
| S-MULTI | Несколько людей: T1 «Я работаю в [ОРГ_А]»; T2 «Коллега [ИМЯ_Б] работает в другом месте»; T3 «У него [РОЛЬ_Б]» | Не собирать чеклист А из фактов Б. Контрольная пара: в T3 заменить «у него» на «у меня» и проверить изменение основания |
| S-NOW | Сильный признак: T1 «Мой номер документа: [ДОКУМЕНТ_А]» | При включении этого типа в список немедленного алерта кандидат T1. Для телефона/почты отдельно согласовать контекст; рекомендация ментора о телефоне не завершает всю политику |
| S-CHUNK | Дробление: T1 «Начало моего [ИДЕНТИФИКАТОРА_А]: [ЧАСТЬ_А]»; T2 «Продолжение: [ЧАСТЬ_Б]» | Проверить порядок склейки и принадлежность; фрагменты сами могут быть ПДн в контексте. Кандидат T2 только если правило требует завершённой сущности |
| S-DUP | Повтор: T1 «Живу в [ГОРОД_А]»; T2 «Как уже писал, город тот же» | Повтор не добавляет независимый факт и не должен сам достраивать комбинацию |
| S-CORR | Исправление: T1 «Коллега работает в [ОРГ_Б]»; T2 «Поправка: это моя организация, не его» | Отдельно размечать принадлежность до и после T2. По проекту требований Олеси позднее исправление не стирает уже возникший исторический момент |
| S-AMB | Неясный владелец: T1 «Участник А и участник Б заполняют анкеты»; T2 «Вот адрес: [АДРЕС_X]» | Не объединять неизвестного владельца с А или Б. Нужно ли уточнение; когда ставить неопределённую разметку |
| S-PUBLIC | Публичный контекст: T1 «Обсуждаем биографию [ПУБЛИЧНОГО_ЛИЦА]»; T2 «Мне прислали его частный контакт [КОНТАКТ_X]» | Публичность сама по себе не отрицательная метка. Разделить публичный факт и новое частное раскрытие; в данных использовать вымышленный аналог |
| S-FICT | Персонаж: T1 «В моём рассказе герой [ИМЯ_ГЕРОЯ]»; T2 «Его адрес [АДРЕС_ГЕРОЯ]» | Согласовать правила вымышленности и цитирования; не объявлять отрицательным только из-за слова «рассказ» |
| S-LONG | Длинная история: T1 факт А; T2 нейтральный разговор; T3 ещё один факт А | При неизменном наборе фактов нейтральная вставка меняет индекс, но не основание момента. Длину и расстояния зададим в пилоте; TTL пока открыт |
| S-AGENT | Код и логи: T1 код с `[TEST_FIXTURE]`; T2 результат инструмента с `[КОНТАКТ_А]` | Согласовать доверие к роли/источнику, тестовый литерал и реальный контекст. Расширение после чатового MVP, не обязательное условие первого корпуса |

## Что должно выйти из брейншторма

- Утверждённые типы фактов, правила немедленного алерта и комбинации, включая исключения.
- Правила принадлежности, повтора, исправлений, цитат и неопределённости.
- Для каждого принятого сценария положительный пример и близкий отрицательный
  либо неопределённый вариант с обоснованием по каждому префиксу.
- Эталонный момент или отсутствие момента, записанные по версии политики,
  с согласованием #10, #11 и #25.
- Приоритеты первого эксперимента и отложенные расширения для #26.

Числовые пороги и юридические выводы не должны появляться в синтетике только
потому, что их предложила генерирующая модель.
