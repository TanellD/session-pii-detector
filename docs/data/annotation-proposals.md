# Предложения к разметке для #13

Статус: список на обсуждение с #10/#11/#25, не действующая инструкция.
`annotation-guidelines.md` и принятые ADR не изменяются.

Основа: работа Олеси,
[PR #19](https://github.com/TanellD/session-pii-detector/pull/19),
[проект требований к разметке](https://github.com/TanellD/session-pii-detector/blob/04e6c9f522d1c5ce7d0e7a08d502902caae70567/docs/data/metrics-annotation-requirements.md).
Поля окончательной машинной схемы и порядок согласования относятся к
[#25](https://github.com/TanellD/session-pii-detector/issues/25).

- Хранить версию политики и основание момента. Индекс сообщения без правила
  не объясняет, почему возникли ПДн; порог не назначает LLM-генератор.
- Для эталонного момента проверять каждый префикс без будущего контекста.
  Отдельно сохранять события уточнения: поздняя реплика не даёт системе
  права использовать своё содержание в более раннем префиксе.
- Разделять людей локальными идентификаторами. Упоминание и факт связывать
  с доказательством в сообщении; допускать неизвестного или нескольких
  возможных владельцев. Не склеивать всех неизвестных в одного человека.
- Отличать уникальный факт, его повтор, изменение значения и изменение
  принадлежности. Сохранять историю. В соответствии с проектом требований
  Олеси не стирать исторически возникший `t_gold` последующим исправлением.
- Различать положительную, отрицательную и неопределённую сессию. Отсутствие
  момента у отрицательной сессии не равно отсутствию завершённой разметки.
  Неопределённый отдельный атрибут не всегда делает неопределённой всю сессию.
- Раздельно проверять момент немедленного алерта по сильному признаку и момент
  накопления комбинации. Добавлять близкие отрицательные варианты с пропуском
  признака, другим владельцем, повтором и неоднозначным контекстом.
- Признаки публичности, цитаты, вымышленности и происхождения из кода/логов
  фиксировать как контекст. Правило итоговой метки согласовать с командой;
  публичность не задаёт отрицательную сессию автоматически.
- Выделять независимую проверку validation/test и разбор разногласий.
  Происхождение, шаблон, профиль, prompt/revision и seed сохранять для контроля
  пересечений, не предъявляя скрытый план аннотаторам при первом проходе.
- Сверить итоговые метки с принятым протоколом #11 и его единицей индексации.
  В этой ветке метрики не определяются и не считаются заново.
