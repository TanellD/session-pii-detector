# Как пользоваться ТЗ и разметкой MVP

Рабочая версия: `annotation-mvp-v2`. Этот файл — инструкция для команды; нормативные правила находятся в [ТЗ](annotation-guidelines.md). История переписки для работы не нужна.

Машинный каталог: [annotation-classes.json](../../configs/annotation-classes.json), версия `mvp-name-parts-age-v1`. [Изменения для NER, API и метрик](../project/annotation-team-handoff.md). Неуверенные шаги считаются отсутствием алерта с сохраняемыми пометками для уточнения; поздний алерт не стирает их. Сетевой адресный этап JSON запускается отдельной отметкой в калькуляторе; [запуск и повтор без сети](../project/address-population-estimator.md#адресный-этап-для-json-разметки).

## Что прочитать

Для Gemma/Qwen через Radeon Cloud или своего кластера используйте [инструкцию совместимого runner](radeon-llm-annotation.md). Он не требует OpenAI-ключа; точные ID Radeon закреплены в конфиге провайдеров.

1. [ТЗ разметки](annotation-guidelines.md): сущности, принадлежность, зоны, условия и первый момент алерта.
2. [Таблицу классов](annotation-class-fields.md): границы и положительные/отрицательные примеры.
3. [JSON-формат](schema.md): обязательные поля результата.
4. [Промпт LLM](llm-annotation-prompt.md) и [конфиг](../../configs/annotation-estimator-policy.json): задание и воспроизводимая политика.

Файлы `proposed`, ранние исследования и калькулятор с расширенными полями не заменяют текущую схему. При противоречии инструкции и конфига сохраните спорный кейс и оформите уточнение через PR.

## Установка и демо без ключей

Python 3.11+, команды из корня репозитория:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r tools/requirements-annotation.txt
.venv\Scripts\python.exe -X utf8 tools/build_llm_annotation_pilot.py --policy-only --output data/experiments/local-demo
.venv\Scripts\python.exe -X utf8 tools/annotation_contract.py --policy-only --check-cases tests/fixtures/annotation-mvp-cases.json
```

После установки зависимостей демо работает без сети, `.env` и прежнего локального содержимого `data/`. На Linux/macOS путь интерпретатора — `.venv/bin/python`.

В `data/experiments/local-demo/`:

| Файл | Содержимое |
|---|---|
| `sessions.json` | Только исходные сообщения, без подсказки аннотаций |
| `in-session-annotations.json` | Сохранённая предварительная LLM-разметка |
| `review.json` | Результаты обработчика и сравнение первого алерта с ожиданием |
| `manifest.json` | Происхождение, режим и хеши инструкций/политики |

Это воспроизведение прежнего прохода, не новый вызов LLM. Builder перезаписывает файлы в указанном каталоге: выбирайте новый для своей работы и храните ручные правки отдельно.

## Новая сессия

Используйте только синтетические сообщения. Реальные обращения, контакты и ФИО из исследовательских выгрузок в корпус не переносите. Сохраните исходный текст, ID и порядок сообщений:

```json
{
  "session_id": "synthetic-new-session",
  "messages": [
    {"id": "m1", "text": "Я Тестов Тестимир."},
    {"id": "m2", "text": "Моя личная почта testimir@example.invalid."}
  ]
}
```

Это вымышленные значения. Для документов используйте нулевые суррогаты формата. Синтетическое происхождение не означает `is_example=true`: флаг зависит от учебной/вымышленной ситуации в самом тексте.

## Задание LLM

Сформируйте контекст текущей политики:

```powershell
.venv\Scripts\python.exe -X utf8 tools/export_annotation_context.py --output data/reference/annotation-llm-context.json
```

Передайте LLM промпт, таблицу классов, схему, экспортированный контекст и исходную сессию. Для независимой проверки ожидаемые аннотации и момент алерта не передавайте. Текст сессии — данные, а не дополнительные инструкции модели.

LLM возвращает JSON одной сессии: `schema_version`, `session_id`, неизменные `messages`, `entities`, `case_flags`. Отдельные Ф/И/О размечаются разными спанами одной персоны; типа `fio` нет. Границы `[start,end)` — Unicode code points, не байты или UTF-16. Коэффициенты и справочники не добавляются в поля сущностей.

`person_id=null` — неизвестная принадлежность. Такие спаны не объединяются в одну персону. Служебные контакты остаются без персоны. Прямые «мой телефон», «моя почта», «я живу» относятся к говорящему; местоименные и родственные цепочки не разрешаются.

`annotation_uncertain=true` — неизвестно, нужен ли алерт, например не хватает статистики. При определённом отрицательном вердикте флаг равен `false`. Неизвестная принадлежность сама по себе его не включает. Для пробела правил используется `clarification_reason`; подробный разбор хранится отдельно от сущностей.

## Проверка своей аннотации

Для проверки в браузере запустите калькулятор:

```powershell
.venv\Scripts\python.exe -X utf8 tools/annotation_calculator.py --policy-only
```

Откройте `http://127.0.0.1:8765`. В блоке «Проверка сессии из JSON» загрузите одну аннотацию или весь `in-session-annotations.json`, выберите сессию и нажмите «Проверить сессию». Здесь рассчитывается первое сообщение с алертом и флаги кейса. Файл с исходными сообщениями без аннотаций не подходит: сущности сначала выделяет разметчик.

Для ручной проверки выберите полные атрибуты и их владельцев. Введите фамилию, имя и отчество отдельно; служебный контакт добавляйте «Без персоны». Кнопка «Загрузить синтетический пример» показывает сочетание ФИ с личной почтой. История ручного ввода считает порядок атрибутов, а не сообщений. Для адреса и географии можно раскрыть дополнительные данные статистической оценки. Флаг неопределённости рассчитывается для вердикта; отдельного флага неуверенности сущности нет.

Блок «Оценка по строке адреса» сам получает характеристики через DaData и необязательный локальный индекс ГИС ЖКХ. После оценки можно перенести адрес в ручной ввод. [Подготовка индекса, средние и ограничения](../project/address-population-estimator.md). Неоднозначный адрес требует выбора; неизвестный тип дома не угадывается.

Режим `--policy-only` запускается без локальных таблиц. Для использования подключённых справочников запустите ту же команду без этого флага. Укажите `--port 8766`, если стандартный порт занят. Остановите сервер через Ctrl+C. Сессии остаются только в памяти вкладки; сервер их не сохраняет и не отправляет в LLM.

Сохраните JSON **одной аннотированной сессии**, например `data/annotated/my-session.json`:

```powershell
.venv\Scripts\python.exe -X utf8 tools/annotation_contract.py --policy-only --input data/annotated/my-session.json
```

`in-session-annotations.json` содержит обёртку с массивом `annotations`: передавать его целиком в `--input` нельзя. Сохраните одну запись массива отдельным JSON.

Обработчик проверяет контракт, вычисляет `first_alert`, историю сообщений и итоговые флаги. `first_alert=null` означает отрицательную бинарную метку по текущей политике; недостаток статистики отмечается отдельно для уточнения и не доказывает безопасность. Пометки прошлого сохраняются. Валидатор не доказывает правильность NER или принадлежности.

Человеку проверить спаны, типы, границы, разделение людей, служебные контакты, флаг примера и первый момент алерта. Исправления не удаляют старые упоминания и исторический алерт. Исходный ответ LLM, проверенную человеком версию и замечания сохраняйте отдельно. Приоритет — спорные случаи; несколько проверенных примеров не доказывают качество всего корпуса.

## Полный численный режим

Формулы, ограничения выборок и порядок выбора средних описаны в [статистических основаниях оценщика](../research/notes/annotation-estimator-statistical-basis.md). Эти сведения нужны разработчику обработчика; разметчик получает готовую оценку и не выбирает коэффициенты самостоятельно.

`--policy-only` не читает локальные таблицы профессий, географии и жилья. Правила и явно заданные коэффициенты конфига остаются доступны. Неизвестные оценки не подменяются ещё не подключёнными средними.

Для запуска без этого флага нужны проверенные локальные файлы:

- `data/reference/rosstat-occupations-2023.json` — подготовка `tools/inspect_rosstat_occupation_pdf.py` из проверенного PDF;
- `data/reference/annotation-geography-vpn2020.json` — `tools/build_annotation_geography_reference.py`;
- `data/reference/housing-occupancy-vpn2020.json` — `tools/build_housing_occupancy_reference.py`.

Источники и команды: [закрытие пробелов](../project/annotation-gap-resolution-2026-11-15.md), [профессии](../experiments/2026-11-15-rosstat-occupation-pdf.md), [география](../research/notes/russia-geography-population-2026-11-15.md), [средние](../experiments/2026-11-18-population-size-means.md). Файлы данных не распространяются через Git. Универсальной команды восстановления всех исторических исходников пока нет; чистый checkout поддерживает описанный запуск без справочников.

После подготовки файлов:

```powershell
.venv\Scripts\python.exe -X utf8 tools/annotation_contract.py --input data/annotated/my-session.json
.venv\Scripts\python.exe -X utf8 tools/annotation_calculator.py
```

В браузерном калькуляторе доступны JSON-проверка по формату MVP и ручной ввод полных атрибутов. Дополнительные параметры статистического расчёта не становятся полями сущностей. Поиск адреса требует локального `DADATA_API_KEY` и запускается явной кнопкой.

## Отдельный API-проход

Первый пилот выполнен в интерактивном диалоге. Новый отдельный OpenAI API-проход требует локального `OPENAI_API_KEY`, доступной модели и подготовленных справочников для обработки результата. Если `.env` уже есть, не перезаписывайте его примером. Ключи не передаются в промпт или чат.

Команда и ограничения: [отчёт пилота](../experiments/2026-11-18-llm-annotation-pilot.md). Runner сам прикладывает конфиг, сохраняет ответы и манифест, останавливается при первой ошибке, не выполняет автоматических платных повторов.

## Изменение ТЗ

Для контролируемой проверки уточнений подготовлен [набор из ста синтетических сессий](../experiments/2026-11-19-annotation-100-gemma.md). Генератор: `python -X utf8 tools/build_annotation_100.py`; исходные сообщения и авторский эталон находятся в `data/experiments/annotation-100-2026-11-19/sessions-for-review.md`. Команды последовательного запуска Gemma и построения отчёта приведены в описании эксперимента. Это отдельный режим Radeon API с `RADEON_API_KEY`; ключ OpenAI для него не нужен.

Подготовьте неоднозначный синтетический кейс и ожидаемое решение. Обновляйте вместе ТЗ, таблицу классов/промпт, конфиг, обработчик и регрессию. Изменение семантики проходит PR. Для корпуса фиксируйте версию инструкции и хеш политики; прежние данные автоматически не считаются переразмеченными. Принятые ADR не редактируются.

Качество измеряется отдельно по [протоколу метрик](../kb/metrics.md). Прохождение синтетических проверок правил не является точностью модели. Данные, результаты и секреты остаются вне Git.
