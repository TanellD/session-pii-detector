# Синтетический набор сессий для первого алерта

Задачи [#33](https://github.com/TanellD/session-pii-detector/issues/33) и
[#40](https://github.com/TanellD/session-pii-detector/issues/40). Версия
`session-alerts-v1`, схема `annotation-mvp-v2`, классы `mvp-name-parts-age-v1`.
ТЗ и политика зафиксированы на коммите `022bf6290c8107149200efcc436c782da7c2995f`
из [PR #44](https://github.com/TanellD/session-pii-detector/pull/44).
За основу сценариев взяты план генерации и промпты #13 на коммите
[`0929e1e`](https://github.com/TanellD/session-pii-detector/tree/0929e1e3b2d28772ddceac1cccd751ba315e41de/docs/data).

Реплики и разметку составили в Codex по заранее заданным сценариям.
Внешний API не использовали. Имена и адреса вымышлены. Для почты взят
домен `example.invalid`, для телефонов и документов — тестовые номера по ТЗ.

В корпусе 16 сессий, 46 сообщений и 41 спан по 15 классам. В development
и test по 8 сессий. Семейства и профили между частями не пересекаются.
Команда собирает корпус, сверяет спаны с планом и записывает покрытие
классов в `manifest.json`.

```powershell
python -X utf8 tools/prepare_session_corpus.py data/session-alerts-v1
```

Сценарии покрывают одного и нескольких людей, накопление между репликами,
повторы, общий телефон, неизвестного владельца, позднее уточнение,
исправление адреса, прямой идентификатор и разговор без алерта.

## Передача набора

Каталог `data/session-alerts-v1/` хранится вне Git.

| Файл | Назначение |
|---|---|
| `scenario-plan.json` | Семейства, профили, разбиение и ожидаемые классы и владельцы по репликам. |
| `authored-dialogues.json` | Исходный текст, точные цитаты спанов и авторская принадлежность. |
| `sessions.json` | Корпус #33 без меток алерта. |
| `manifest.json` | Версия, хеши, разбиение, роли, общие владельцы и покрытие. |
| `author-alert-ledger.json` | Авторские решения по каждому префиксу с обоснованием и ID опорных спанов. |
| `gold.json` | Авторская разметка первого алерта #40. |
| `independent-review.md` | Реплики для независимой проверки без авторских ответов. |

Все реплики имеют роль `user`. В `sessions.json` общий телефон имеет
`person_id=null`. Для него поле `shared_owners` в манифесте перечисляет
обоих владельцев. При неизвестной принадлежности этой записи нет.
Совместимость манифеста с реализациями
[#34](https://github.com/TanellD/session-pii-detector/issues/34) и
[#36](https://github.com/TanellD/session-pii-detector/issues/36) предстоит
подтвердить при передаче набора.

## Сверка первого алерта

```powershell
python -X utf8 tools/prepare_session_corpus.py data/session-alerts-v1 --with-alerts
```

Реестр фиксирует основание алерта или причину неуверенности после каждой
реплики. `t_gold` — индекс первого сообщения, на котором сработало правило.
Калькулятор в режиме `policy_only` сверяет решения. Сборщик проверяет, что
опорные спаны ещё действуют в текущем префиксе и обосновывают правило.
На этом наборе расхождений нет. Численные правила с
адресными и статистическими справочниками в прогон не входили.

Проверяющему передайте только ТЗ и реплики. Он записывает решение после
каждого сообщения перед тем, как открыть следующее. Сверьте ответы с
авторской разметкой по ID сессии и сообщения. Для каждого расхождения
запишите обе версии, пункт ТЗ и итоговое решение. Если разметка изменилась,
выпустите новую версию и повторите оценку.

Независимая проверка ещё не проведена. Порог модели на `test` не подбирался.

## Версия v2 по замечаниям к PR #46

Версия `session-alerts-v2` использует локальную схему
`annotation-mvp-v2-review46`. Сборщик выбирает её по полю
`"review_policy": "pr46-review-v1"` в сценарном плане. В `person_id` общий
атрибут содержит список владельцев. `null` означает
неизвестную принадлежность. Общий `PERSON` хранится как жёлтый тип
`person` без вывода частей ФИО.

У явно названных документов с неверной контрольной суммой сохранены спаны.
В проверке первого алерта v2 такой документ не даёт красного основания.
Если это поправка документа того же владельца, она заменяет его активное
значение, сохраняя историю уже сработавших алертов. Валидные тестовые номера
проверяются в отдельных сессиях.

Для локальной оценки использованы качественные правила ТЗ #44 и
[уточнения из ревью](https://github.com/TanellD/session-pii-detector/pull/46#issuecomment-7064173740).
Общий телефон или адрес хранится как один спан и не добавляется к личному
профилю каждого владельца. Веса сервиса в расчёте не участвуют.
Для импорта в сервис потребуется сверить эту схему с его обновлённым контрактом.

```powershell
python -X utf8 tools/prepare_session_corpus.py data/session-alerts-v2 --with-alerts
```
