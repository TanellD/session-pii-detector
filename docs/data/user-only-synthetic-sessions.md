# Синтетические сессии только из пользовательских сообщений

Общие требования и настраиваемое задание для новых наборов находятся в [политике генерации](synthetic-session-generation-policy.md). Эта страница сохраняет разговорные заготовки и инструкции конкретных ранних запусков.

Для генерации уже есть [учебные сценарии ТЗ](annotation-synthetic-examples.md), [первый пилот](../experiments/2026-11-18-llm-annotation-pilot.md) и [авторский набор сравнения](../experiments/2026-11-19-ten-session-model-comparison.md). Они помогают выбрать основания и исключения, но не заменяют естественные обращения в поддержку.

Из внешних материалов ранее проверен [синтетический русский срез CONFIDE](../experiments/2026-11-19-confide-annotation-audit.md). Он может служить примером более длинных разговоров, но терапевтический домен отличается от поддержки. Авторские NER-классы нельзя переносить напрямую; после отбора клиентских реплик нужен новый эталон по нашему ТЗ. Происхождение и ограничения закреплены в указанном аудите на конкретной ревизии источника.

## Шаблоны разговорных сценариев

| Контекст | Развитие пользовательских сообщений | Что проверять |
|---|---|---|
| Настройка продукта | Вопрос о функции → уточнение → благодарность | Чистый отрицательный пример без сущностей |
| Доставка | Просьба изменить доставку и представление → домашний адрес → исправление квартиры | Части имени, полный адрес, первый алерт и неизменность старых спанов |
| Запись на консультацию | Выбор времени и имя → отчество → личная почта для подтверждения | Постепенное накопление ИО и контакта |
| Старые заметки | Почта неизвестного владельца → позднее раскрытие владельца и имя → личный телефон | Старый `null` не перепривязывается и не создаёт ранний алерт |
| Восстановление доступа | Представление → общий телефон и email службы | Служебные контакты остаются без персоны |
| Возврат оплаты | Нейтральный вопрос → полный красный маркер | Самостоятельное красное правило |

Варьируйте длину реплик, порядок фактов, повторы, исправления и число отвлекающих бытовых деталей. Не превращайте каждое сообщение в анкету. Значения всегда синтетические: тестовые домены `.invalid`, заведомо нерабочие телефоны, нулевые документы. Реалистична структура разговора, а не существование указанных контактов.

## Заготовка задания генератору

> Создай последовательность сообщений одного пользователя в чат поддержки. Ответы помощника не пиши. Задай понятную задачу и постепенно добавь нужные факты по выбранному сценарию. Каждая реплика должна интерпретироваться по предыдущим пользовательским репликам без недостающего вопроса помощника. Не добавляй все персональные сведения сразу. Используй только вымышленные значения; не вставляй описание ожидаемого алерта в текст диалога. Отдельно от исходных сообщений составь эталон: точные сущности, владелец по доступному префиксу и ожидаемый первый алерт. Старые неизвестные атрибуты после позднего раскрытия владельца не меняй.

Набор с эталоном нужно проверять до модельного прогона. Он является авторским диагностическим материалом, а не независимо проверенным benchmark. При переносе шаблонов из внешнего корпуса отдельно проверяются происхождение, синтетичность и лицензия.

## Отбор из готового чата

Сначала отберите сообщения с явной ролью `user`, сохранив их исходные ID, порядок, текст и соответствие исходному диалогу в отдельном манифесте. `assistant`, `system`, `tool` и неизвестные роли не включайте автоматически. Модель не должна получать отброшенные реплики в других полях запроса. Не переносите факты, встречавшиеся только в ответе помощника, в пользовательский эталон.

Фильтрация может лишить короткое «да» или «вот номер» смысла. Если принадлежность без удалённой реплики не установлена, её нельзя восстановить из скрытого ответа помощника. Сохраняйте `null` либо отправляйте случай на разбор. Новые синтетические сессии строятся так, чтобы этого скрытого контекста не требовалось.

## Создание и последовательная разметка

```powershell
python -X utf8 tools/build_user_only_sessions.py
python -X utf8 tools/run_sequential_annotation.py --input data/experiments/user-only-sessions-2026-11-19/sessions.json --output data/experiments/radeon/2026-11-19-user-only-gemma-sequential-01 --dry-run
```

Тексты и эталон создаются в `data/experiments/user-only-sessions-2026-11-19/sessions-for-review.md`. Генератор отказывается перезаписывать каталог; для нового набора нужен новый `--output`.

Для вызовов API уберите `--dry-run`; ключ читается из локального `.env` по существующим настройкам Radeon. Runner отправляет только доступный префикс и своё предыдущее предсказание, без эталона. Модель возвращает новые сущности только текущего сообщения. Старые сущности заморожены, прежние флаги сохраняются; обработчик добавляет свою часть пометок и рассчитывает алерт. ID упоминаний назначает инструмент. Все запросы и исходные ответы сохраняются для проверки.

После ошибки сессия останавливается: дальнейшие сообщения без достоверного предыдущего состояния не размечаются. Следующая сессия начинается с пустого состояния; HTTP-ошибка останавливает весь прогон. Автоматических повторов нет. Частичные результаты сохраняются, но не объявляются полными отрицательными сессиями.

Точные команды и результаты — в [отчёте последовательного пилота](../experiments/2026-11-19-user-only-sequential-pilot.md).
