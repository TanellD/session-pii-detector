# Изменения разметки для разработчиков извлечения, API и метрик

Рабочая политика находится в `configs/annotation-estimator-policy.json`, перечень классов — в `configs/annotation-classes.json`. Минимальная структура спанов сохраняется: `annotation-mvp-v2`. Версия таксономии — `mvp-name-parts-age-v1`. Эти изменения согласованы пользователем в рабочей ветке; они не объявляют завершённым ревью команды или перенос в основной сервис.

## Классы и извлечение — задачи #36 и #37

Жёлтые спаны: `first_name`, `last_name`, `patronymic`, `sex`, `age`, `geography`, `occupation`, `organization`. Оранжевые: `phone`, `email`, `address`. Красные: `passport`, `snils`, `individual_inn`, `bank_card`.

ФИО и пары ФИ/ИО/ФО — вычисляемые сочетания частей одного человека, отдельных спанов для них нет. `PERSON/FULL_NAME` старого NER требует семантического разделения частей; простое переименование некорректно. Дата рождения, родство и специальные категории вне текущего MVP. Старый smoke остаётся историческим набором; для текущих классов нужны отдельная версия gold и отчёт покрытия.

Возраст добавлен как жёлтый признак: только явно названные полные годы («37 лет»), без дат рождения, интервалов и вычисления возраста. [Росстат публикует данные по полу и однолетним возрастам](https://rosstat.gov.ru/compendium/document/13284). Проверенный машиночитаемый справочник ещё не подключён, поэтому численный вклад возраста пока неизвестен. Быстрый расчёт возможен после разовой подготовки таблицы: поиск готового счётчика по возрасту, полу и территории; независимое перемножение маргинальных долей запрещено. Профессию/работодателя с возрастом дополнительно не сужаем без совместных данных. Свежесть и доступность отдельных файлов требуют проверки, наличие каталога не означает импорт.

Новое определение документа: полное явно названное значение выделяется независимо от контрольной суммы; сумма не доказывает выдачу документа. В `benchmarks/pii_smoke/regex_detector.py` для новой интеграции использовать `predict(text, require_valid_checksum=False)`. Исторический режим по умолчанию оставлен для повторения старого benchmark. Контекст, полноту и принадлежность всё равно нужно проверять по ТЗ; распознавание произвольной последовательности цифр документом не становится.

## Неуверенность и метрики — задачи #39, #40 и #41

Неуверенность — пометка для уточнения ТЗ/статистики. Пока достаточное правило не сработало, бинарный алерт равен `false`. Поздние данные не снимают старые пометки. В результате у каждого сообщения есть `annotation_uncertain` и причина; кейсовый флаг сохраняет наличие пометок истории/входной разметки и может сочетаться с поздним алертом.

Первый момент — первое сообщение с достаточным принятым основанием. Эти кейсы не исключаются автоматически из F2-session/F2-timely/FP0, но доли и причины пометок публикуются отдельно. Это новая рабочая версия протокола, а не утверждение, что неуверенные случаи безопасны. Ранее сохранённые пилоты и метрики не переименовываются в результаты новой политики.

## JSON, адреса и API — задача #42

Общий адресный этап подключён к JSON: `POST /api/annotation/enrich` либо CLI `tools/annotation_address_enrichment.py`. Он использует тот же оценщик, что отдельная адресная форма. Сохранённый `address_enrichment` можно повторно передать с аннотацией без сети; хеши аннотации, политики и жилищного справочника проверяются. Спаны и принадлежность не меняются. Нет однозначного адреса/характеристик — нет произвольного коэффициента. Сетевой этап запускается явно.

Draft `docs/api/session-api.md` и его JSON Schema **нужно модифицировать**: они всё ещё содержат старые классы/причины и смешивают неизвестного владельца с неопределённостью вердикта. В начале API-документа перечислены обязательные изменения. Причины текущего обработчика: `red_rule`, `combination_rule`, `candidate_count_rule`. Число кандидатов — отдельное поле; его нельзя напрямую назвать `risk_score`.

## Проверка и оставшаяся работа

Воспроизведение: `python -X utf8 -m unittest discover -s tests`. Приоритетные проверки совместимости — `test_annotation_policy_alignment.py`. Пилот остаётся отладочным: нет независимого gold, нового измеренного F2, подтверждённого возрастного коэффициента и готового production API. Следующий шаг — реализовать адаптер классов, подготовить новый синтетический gold с проверкой человеком и запустить сессионный оценщик по обновлённому протоколу.
