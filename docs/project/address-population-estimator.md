# Оценка жителей по строке адреса

Калькулятор принимает строку адреса проживания, разрешает её через DaData и применяет среднюю заселённость подходящего типа жилья. Для дома дополнительно используется локальный индекс ГИС ЖКХ по идентификатору дома. Расчёт не показывает зарегистрированных жителей и не доказывает фактическую занятость жилья.

## Действующие средние

Среднее работодателя уже включено в `configs/annotation-estimator-policy.json`: **454,070508887227 работника**, взвешивание по числу работников. Воспроизведение источника: `python -X utf8 tools/summarize_organization_sizes.py --show`.

Средние жилья также хранятся в конфиге и доступны без локального файла жилищной таблицы:

| Тип занятого жилья | Жителей | Расчёт по переписи |
|---|---:|---|
| Квартира | 2,315294915890968 | 99 496 891 / 42 973 744 |
| Индивидуальный дом | 2,7118277715712282 | 42 083 643 / 15 518 553 |
| Коммунальная квартира целиком | 2,890470297029703 | 1 527 417 / 528 432 |

Источник и SHA-256 зафиксированы в `housing_defaults`. Дата переписи — 2021-10-01. Воспроизведение: `python -X utf8 tools/build_housing_occupancy_reference.py`. При подключённом жилищном справочнике используется региональное среднее при точном совпадении региона, иначе общероссийское; охват показывается в результате.

Для целого МКД используется число квартир × среднее квартиры. Все квартиры предполагаются занятыми. Среднее целого неизвестного МКД около 427 жителей этим изменением не включается: отсутствие числа квартир не заменяется этой величиной.

## Порядок автоматического определения

1. Отправить строку адреса в DaData. Если вариантов несколько, предложить выбор; однозначный полный адрес можно уточнить автоматически.
2. Уточнить выбранный адрес запросом `count=1`, используя его `unrestricted_value`. [Документация DaData](https://dadata.ru/api/suggest/address/) определяет такой запрос как выбор конкретной подсказки. Поле `house_flat_count` означает число квартир; оно может отсутствовать.
3. Сопоставить `house_fias_id` с локальным индексом ГИС ЖКХ. Изменение идентификатора при уточнении не принимается молча.
4. Если явно указана квартира (`flat_type=кв`), применить среднее квартиры. Отдельная комната или помещение неизвестного типа не считаются квартирой.
5. Для подтверждённого МКД получить положительное число квартир из реестра или DaData. Несколько квартир, указанных DaData, также позволяют использовать формулу квартирного дома с явной пометкой основания классификации.
6. Среднее индивидуального дома использовать только при явном подтверждении этого типа в реестре или при ручном подтверждении типа в калькуляторе. Само слово «дом», отсутствие квартиры, единственная квартира и сельский адрес не доказывают индивидуальный тип. Обобщённый тип реестра «Жилой» автоматически индивидуальным не считается.

Если характеристики неизвестны, источники расходятся, реестр содержит несколько совпадений, дом не подтверждён как эксплуатируемый либо адрес вне России — оценка неизвестна. Отсутствие строки в ГИС ЖКХ не доказывает отсутствие дома или жителей.

## Подготовка и запуск

Для DaData нужен локальный `DADATA_API_KEY` в `.env`. Ключ не передаётся браузеру. Адрес отправляется внешнему провайдеру только по явной кнопке; запросы и ответы с адресами не записываются в файлы или журналы.

Локальный индекс не обязателен для явно указанной квартиры или достаточного числа квартир из DaData, но повышает покрытие домов. Если архив ГИС ЖКХ уже скачан:

```powershell
python -X utf8 tools/build_address_house_index.py
```

Вход по умолчанию: `data/external/annotation-size-statistics/data_gisgkh_157_v20260917_parquet.zip`; выход — `data/reference/gisgkh-address-index.sqlite`. Индекс содержит только ID дома, его тип, число квартир, состояние, регион и метаданные источника. Названия управляющих организаций и ФИО не включаются. Повторяющиеся ID не объединяются произвольно: поиск возвращает неоднозначность.

Архив можно получить существующей командой `python -X utf8 tools/research_population_size_means.py --download --housing`, которая также готовит исследовательские средние. Наличие этого файла не включает все исследовательские коэффициенты в правила алерта.

```powershell
python -X utf8 tools/annotation_calculator.py --policy-only --port 8766
```

Открыть `http://127.0.0.1:8766`, ввести строку в блок «Оценка по строке адреса», нажать «Найти адрес и оценить». Вариант выбирается только при неоднозначности. Показаны число жителей, тип жилья, число квартир при необходимости, дата среднего и допущения. Кнопка «Подставить в ручную проверку» переносит вычисленные характеристики; затем нужно выбрать персону и добавить атрибут. Адрес сам по себе не вызывает алерт.

Режим `--policy-only` не читает прежние файлы профессиональных, географических и жилищных таблиц, но использует средние конфига и необязательный индекс домов для явного адресного поиска.

## HTTP API

`POST /api/address/estimate`, JSON:

```json
{"query": "г. Макетоград, ул. Примерная, д. 1"}
```

Это синтетический адрес формы запроса, а не обещание совпадения в реестре. Результат: `estimated`, `unknown`, `selection_required` либо статус недоступности провайдера. `population_estimate` — число или `null`. Для выбора варианта передаются его `unrestricted_value` в `query`, `selected=true` и при наличии `expected_house_id`. Автоматического выбора первого из нескольких разных адресов нет.

Оценщик возвращает внутренний `address_fact` для исследовательского калькулятора; это не расширяет поля сущности в `annotation-mvp-v2`. Загрузка JSON-аннотации не вызывает внешнее разрешение всех адресов автоматически. Для этого используется отдельная явная операция адресной оценки.

## Адресный этап для JSON-разметки

В калькуляторе отметьте «Передать адреса с известной персоной в DaData…» перед проверкой JSON. Запрос `POST /api/annotation/enrich` принимает ту же аннотацию, выполняет общий адресный оценщик и возвращает оценку с отдельным `address_enrichment`. Сущности, их границы и принадлежность не меняются. Адреса без персоны не отправляются. Неоднозначная подсказка даёт пометку для уточнения, а не автоматический выбор первого дома.

Для повтора без сети передайте в `POST /api/annotation` объект `{"annotation": <исходная аннотация>, "address_enrichment": <сохранённый этап>}`. Этап проверяется по хешам аннотации, политики и жилищного справочника. Смешивание несовместимых версий отклоняется. Старые результаты не переписываются.

CLI для одной сессии:

```powershell
python -X utf8 tools/annotation_address_enrichment.py --input path/to/annotation.json --output data/private/address-stage/run-01.json
python -X utf8 tools/annotation_contract.py --input path/to/annotation.json --address-enrichment data/private/address-stage/run-01.json
```

Первая команда явно обращается к внешнему сервису и требует ключа. Вторая использует сохранённый этап без сети. Результат сохраняется только в новом игнорируемом файле внутри `data/`. Для режима `--policy-only` используйте этот флаг в обеих командах: жилищные справочники должны совпадать. Исправление разметки или изменение источников оформляется новым прогоном; исторические пометки старого прогона сохраняются.

Проверки: `python -X utf8 -m unittest discover -s tests -p test_address_population_estimator.py` и `python -X utf8 -m unittest discover -s tests -p test_annotation_policy_alignment.py`.
