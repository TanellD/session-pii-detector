## Что уже есть

Перечень классов MVP подготовлен в [PR #16](https://github.com/TanellD/session-pii-detector/pull/16)
и в целом одобрен ментором: [ответы второго раунда](https://github.com/TanellD/session-pii-detector/blob/docs/mentor-round2-and-presentation/docs/meetings/2026-11-05-mentor-answers.md).
Заново выбирать весь перечень для PR метрик не требуется. Одобрение классов
не определяет автоматически веса, пороги и достаточные сочетания для алерта.
Страница инструкции разметки пока имеет статус «не составлена»;
проект требований ниже — вход для подготовки полного ТЗ, не готовая инструкция.

## До оценки частей сервиса

- [ ] Сопоставить существующие классы с машинными метками извлечения и разметки;
  зафиксировать границы спанов, вложенность, нормализацию и дубли.
- [ ] Подтвердить единицу линковки: упоминание атрибута или нормализованный факт.
- [ ] Проверить pairwise с несколькими владельцами; определить необходимость
  отдельной оценки связей «атрибут → человек».
- [ ] Выбрать обычную B-cubed на однозначном срезе или расширение для
  пересекающихся групп; определить покрытие и сопоставимость систем.
- [ ] Утвердить неизвестного владельца и отдельную политику алерта для
  «неопределённо». Повышенный порог пока гипотеза.
- [ ] Утвердить оценку по шагам, агрегацию повторных пар и вес длинных сессий.
- [ ] Для явных связей с людьми определить сопоставление ID, ничьи,
  разделение и объединение предсказанных групп.
