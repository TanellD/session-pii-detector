## Последовательность

1. Зафиксировать требования и допущения; проверить рабочую среду.
2. Разобрать статью: постановка, состояние, линковка, метрики, ограничения,
   доступность кода и переносимость результатов на русский язык.
3. Проверить первичные источники по аналогам и детекторам. Различать анализ
   отдельного текста, доступ к истории и накопление признаков по человеку.
4. Подготовить генератор синтетического набора, фиксированные ожидания и CPU-прогон
   regex + GLiNER. Зафиксировать модель, revision, зависимости, команды,
   хеш данных, ошибки и время. Данные и сырые результаты — вне git.
5. Описать API: одиночный и пакетный запросы, сущности, вердикт,
   момент срабатывания, повторы, порядок, исправления и сброс состояния.
6. Предложить ADR о независимости сессионного модуля от детектора.
7. Сопоставить результат со всеми пунктами #12, выполнить проверки,
   подготовить содержание слайдов и оформить локальные коммиты.

- [ ] Черновик API с согласованными примерами запроса и ответа.
- [ ] ADR со статусом `proposed`.
- [ ] Эксперимент и инсайт содержат команду, конфиг, хеш данных и версию кода.
- [ ] Краткие выводы для презентации.
- [ ] Проверки пройдены, рабочее дерево чистое, коммиты только локальные.

## Подтверждено и открыто

Подтверждено ментором: русский; идентификатор сессии; обработка нового сообщения
без повторного NER истории; данные третьих лиц; F2 — основная метрика.
Ориентир существующего сервиса — не обещание скорости нашего CPU-прототипа.

Открыто: точные правила алерта и порог, состав классов, роли assistant/tool,
жизненный цикл сессии и формат интеграции HiveTrace. В API предлагаются варианты,
а не утверждается согласование. Полный сервис и обучение моделей не входят в #12.
