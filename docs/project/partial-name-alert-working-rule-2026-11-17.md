# Рабочее правило: неполное имя и дополнительный личный атрибут

- Дата: 2026-11-17.
- Статус: рабочее решение пользователя; последующие уточнения сведены в [единую инструкцию MVP](../data/annotation-guidelines.md). Она имеет приоритет при расхождениях с историей обсуждения.
- Основание: ответ пользователя на выбор достаточного дополнительного атрибута — «Только признак из согласованного списка: полный адрес, точная организация, полный личный телефон или email».
- Область: качественное правило сервиса; частоты частей имени остаются только исследовательскими. Пользователь подтвердил, что полное ФИО остаётся с дополнительным признаком, самостоятельный алерт не включён.

## Условие

Дополнение, согласованное пользователем: **ФИ, ИО и ФО включены в оранжевый список** наряду с полным ФИО, телефоном, email и полным адресом. Каждая пара — один составной маркер одного человека, а не два оранжевых маркера. Отдельные Ф, И и О остаются жёлтыми; они сохраняются в истории разметки, но не учитываются повторно поверх составного маркера.

| Оранжевое сочетание | Полные компоненты |
|---|---|
| ФИ (`fi`) | Фамилия + имя |
| ИО (`io`) | Имя + отчество |
| ФО (`fo`) | Фамилия + отчество |

Это производные сочетания имеющихся сущностей, а не требование добавить новые классы NER или повторно разметить спаны. Части могут появиться в разных сообщениях, но должны быть отнесены к одному человеку. При появлении третьей полной части активным маркером становится только ФИО: одновременно ФИ, ИО и ФО не создаются. Появление пары само по себе не вызывает алерт; цвет не вводит универсальное правило «любые два оранжевых». Достаточные сочетания остаются перечисленными ниже.

В конфигурации пары перечислены в `partial_name_plus_attribute.combinations`, зона — `orange`. В ответе калькулятора `active_name_marker` показывает один активный составной маркер (`fi`, `io`, `fo` или `fio`) и его зону; `null` означает отсутствие такого маркера.

Алерт возникает, если одному выбранному человеку отнесены как минимум две разные полные части имени — ФИ, ИО или ФО — и хотя бы один атрибут из списка:

| Дополнительный атрибут | Обязательные условия |
|---|---|
| Телефон | Полный, личный, непустое значение; `complete=true`, `usage=personal`. |
| Email | Полный, личный, непустое значение; `complete=true`, `usage=personal`. |
| Адрес | Полный личный адрес проживания. По последнему уточнению пользователя для качественного сочетания с ФИО/парой число жителей не требуется. |

Организация по уточнению пользователя остаётся жёлтой и исключена из достаточного дополнения к ФИО/парам; её отдельные статистические сочетания не отменены. Полное ФИО с дополнительным оранжевым атрибутом удовлетворяет условию. Одно ФИО без дополнения не является самостоятельным основанием. Одна часть имени не образует пару; инициалы и неполные значения в MVP как полные типы не размечаются. Старые флаги калькулятора — техническая совместимость, не требование к минимальной разметке.

Пол, широкая география, профессия и родство сами по себе не завершают это качественное сочетание. Это не отключает другие принятые правила: например, самостоятельное достаточное статистическое основание или красный маркер.

## Линковка и момент алерта

Пара и дополнительный атрибут должны относиться к одному `person_id`. Атрибуты без выбранного человека или разных людей не соединяются. Минимальный формат включает границы, тип и персону; дополнительных ручных флагов нет.

Порядок появления не важен: основание возникает на первом префиксе, где собраны оба условия. Два упоминания одного имени не заменяют две разные части. При наличии всех полных компонентов они объединяются в ФИО без повторного учёта. История исходных упоминаний сохраняется. Позднее значение того же типа и роли заменяет активное значение; ранее зафиксированный первый алерт сессии не исчезает.

Для MVP не вводится отдельная ветка по популярности: отсутствие пары в доступном корпусе не делает её редкой в России.

## Численная оценка и объяснение

Причина: `partial_name_plus_attribute_policy` в `rule_codes`. Объяснение в `reasons` указывает подходящий дополнительный атрибут. Это отдельное достаточное основание, а не утверждение о числе совместимых россиян.

Когда нет самостоятельной принятой численной оценки в пределах порога, результат сочетания содержит `candidate_count=null`, `status=policy_only`. Отдельные оценки работодателя, территории и другие промежуточные величины сохраняются в `estimates`; они не выдаются за численную оценку всего сочетания. Принятая адресная или другая достаточная численная оценка может отображаться одновременно с качественным основанием. Условное число «около порога» не назначается.

## Реализация и проверка

- Конфигурация: `configs/annotation-estimator-policy.json`, секция `partial_name_plus_attribute`.
- Расчёт и HTTP: `tools/annotation_calculator.py`.
- Минимальный формат и проверка сообщений: `tools/annotation_contract.py`; исследовательский интерфейс калькулятора сохраняется отдельно.
- Изменение применяется после перезапуска уже запущенного калькулятора.

```powershell
python -X utf8 -m unittest discover -s tests -p test_annotation_calculator.py
python -X utf8 -m unittest discover -s tests -p test_annotation_calculator_http.py
python -X utf8 tools/annotation_calculator.py
```

Проверяются порядок атрибутов, разные люди, неизвестная принадлежность, неуверенность, неполные/общие контакты, повтор части имени, точность работодателя, адресные ограничения, объединение полного ФИО и отсутствие вымышленного численного результата.

[Исследовательское основание и ограничения](../research/notes/fns-sro-patronymic-study-2026-11-17.md). Исследование мотивирует отдельное правило, но не доказывает выбранный список достаточных сочетаний; список является согласованным решением сервиса.
