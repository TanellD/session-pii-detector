# Данные и сценарии сессий: промежуточный ответ по #13

Дата проверки: 09.11.2026. Статус: исследовательский черновик для ревью, задача не закрыта.

Основание: [issue #13](https://github.com/TanellD/session-pii-detector/issues/13),
[постановка](brief.md), [ADR-0002](../decisions/0002-no-real-pii.md),
[ответы ментора от 05.11](https://github.com/TanellD/session-pii-detector/blob/e078a8257d7509d4c5d49394592f60ebf854db86/docs/meetings/2026-11-05-mentor-answers.md).
Ссылки на незамерженные работы ниже зафиксированы на проверенных коммитах.

Рабочие ограничения по согласованию с исполнителем: используем русский язык;
зарубежные определения PII не переносим на ФЗ-152; берём готовые русские данные
надлежащего качества, а сессионное накопление и момент возникновения ПДн преимущественно
генерируем. Каталог сценариев и правила достаточности обсуждает команда.
Начинаем с чатового MVP. Агентные логи остаются расширением.

## 1. Какие готовые данные подходят

Пул и первичные источники собраны в [реестре](../research/sources.md),
обоснования и TODO по допуску в [обзоре русских данных](../research/notes/russian-pii-datasets.md).

Для первичной проверки выделены русская часть Scanpatch, русская конфигурация
Meddies и собственные русские синтетические сессии CONFIDE. Redmadrobot также
остаётся кандидатом, но требует отдельной проверки происхождения: карточка описывает
смесь синтетики и исходных логов с заменёнными идентификаторами, без построчного признака источника.
Ни один из этих наборов этим исследованием не допущен автоматически в train или validation.

Разметка NER полезна для извлечения отдельных признаков. Она не задаёт эталонный
момент возникновения ПДн в сессии и сама по себе не является разметкой по ФЗ-152.
Для validation нужна независимая проверка разметки и отсутствия пересечений с train;
для оценки сессионного момента потребуется дополнительная разметка.
Новостные корпуса с реальными людьми оставлены как методические источники,
без включения исходных текстов в наш датасет по ADR-0002.

## 2. Есть ли данные с моментом возникновения ПДн

Готового открытого русскоязычного датасета с размеченным моментом возникновения
ПДн в исследованном пуле не найдено. Это результат ограниченного поиска,
а не доказательство отсутствия таких датасетов вообще.

Близкий аналог: Lee, Park, Son,
[Early Detection of Re-Identification Risk in Multi-Turn Dialogues via Entity-Aware Evidence Accumulation](https://doi.org/10.3390/app16083680).
Его синтетические `woz_synthetic` и `woz_stress` включены в исследовательский пул
как методический источник. Открытая выгрузка не найдена; скрипты предлагаются по запросу.
Русский язык не подтверждён, опубликованные примеры английские.

Из статьи берём логику планирования фактов и усложнения примеров для собственной
русской синтетики. Краткая карточка и границы переноса:
[исследовательская заметка](../research/notes/dialogue-onset-data.md).
Адаптация с примерами и промптами:
[план генерации](../data/synthetic-generation-plan.md).

## 3. Какие сценарии покрывать

Подготовлена [основа для брейншторма](../data/scenario-discussion.md):
раскрытие о себе, третьи лица, смешение людей, повтор, дробление, исправления,
неоднозначная принадлежность, контекст публичных лиц и персонажей, длинная история,
агентные логи как расширение. Есть условные примеры для обсуждения.

Итоговый каталог и юридически обоснованные моменты пока не согласованы.
Команда должна определить достаточные комбинации и признаки, требующие немедленного алерта.
Публичное лицо не считается автоматически отрицательным примером.

## 4. Что берём и что генерируем

Берём все прошедшие аудит русские синтетические источники из пункта 1,
с сохранением происхождения и лицензий. Сессионные переходы генерируем по
согласованным сценариям с помощью few-shot-промптов, затем независимо проверяем.
Подробности: [план](../data/synthetic-generation-plan.md),
[черновик промптов](../data/prompts/session-generation.md).

Сначала нужен небольшой пилот, по которому измерим выход пригодных примеров,
токены, время разметки и разброс F2. Объём и бюджет пока не оценены численно:
нет замеров и согласованного каталога. План содержит формулы расчёта и условия
выбора объёма. Обещать устойчивый F2 или срок готовности корпуса сейчас рано.
Детализация выборок и бюджета относится также к
[#26](https://github.com/TanellD/session-pii-detector/issues/26).

## 5. Поля данных и связь с метриками

Используем работу Олеси в
[PR #19 к #11](https://github.com/TanellD/session-pii-detector/pull/19):
[требования к разметке](https://github.com/TanellD/session-pii-detector/blob/04e6c9f522d1c5ce7d0e7a08d502902caae70567/docs/data/metrics-annotation-requirements.md).
Это ответ на требования к полям для метрик; здесь его не переопределяем.

Для генерации учитываем идентификатор сессии, порядок и роли сообщений,
положительную/отрицательную/неопределённую сессию, `t_gold` и основание по версии
политики, отдельных людей и принадлежность фактов. При проверке префикса нельзя
использовать будущие сообщения. Предложения собраны
[отдельным списком](../data/annotation-proposals.md).

В PR #19 требования названы проектом и явно отделены от полной машинной схемы.
[schema.md](../data/schema.md) в текущей основной ветке ещё шаблон.
Финализация схемы и разметки относится к
[#25](https://github.com/TanellD/session-pii-detector/issues/25).
Пункт 5 считаем покрытым ссылкой на работу Олеси в части требований,
но готовность машинной схемы этим не утверждается.
Метрики не пересчитывались: [единый документ](../kb/metrics.md) пока не заполнен
в основной ветке, а протокол из #19 находится на ревью.

## Как проверить артефакты

Начать с этой сводки, затем пройти по ссылкам на реестр, сценарии и план.
Команды проверки документационного изменения после установки pre-commit:

```sh
git diff --check origin/main...HEAD
pre-commit run --all-files
```

Здесь нет результатов эксперимента или заявленных метрик качества. Проверки файлов
не заменяют аудит датасетов, согласование политики и пилот.
