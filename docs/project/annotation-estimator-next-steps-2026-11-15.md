## Самые последние доступные данные

Принято направление: для каждого показателя и территории выбирать последнюю **проверенную** публикацию, а не единый год для всех показателей. Различать дату публикации/обновления страницы, дату наблюдения и период отчётности. План выпуска, пустая колонка текущего года и прогноз не подтверждают доступность наблюдений этого года.

Хранить у каждого значения `source_url`, `reference_date`, `retrieved_at`, `coverage`, `method`, `source_hash`. При отсутствии свежего источника показывать `not_covered` либо явно разрешённый устаревший срез с его датой. Переписной справочник остаётся воспроизводимой исторической основой; он не переименовывается в текущую оценку.

Официальные точки проверки:

- [Численность по муниципальным образованиям](https://rosstat.gov.ru/compendium/document/13282).
- [Демография Росстата](https://rosstat.gov.ru/folder/12781).
- [БД ПМО](https://rosstat.gov.ru/storage/mediabank/MUNST.htm) и региональные публикации из подготовленного реестра.

Проверка доступности без сохранения исходных страниц и контактов:

```powershell
python -X utf8 tools/check_annotation_source_access.py --source rosstat_population_catalog --source rosstat_demography_catalog
```

Во время проверки каталог муниципального населения вернул ссылки на `BUL_MO_2024.xlsx` и более ранние файлы; более свежая федеральная выгрузка через эту страницу не подтверждена. Это результат проверки данного каталога, а не доказательство отсутствия новых региональных данных. Планы региональных публикаций с указанием текущего года не заменяют проверку самих таблиц.

Демографический каталог также проверен: он содержит ссылку на ряд `popul_1897+.xlsx`, но прямая загрузка во время проверки вернула HTTP 404. Поэтому ни один новый общероссийский показатель на основании этой ссылки не импортирован. Изменено правило выбора источников, а не дата прежнего справочника.

## Группы населённых пунктов по размеру

Указанные лидом границы оформлены без пересечений и с заполнением промежутка между верхними и нижними группами:

| Группа | Границы населения |
|---|---|
| Менее тысячи | `0 <= N < 1000` |
| От тысячи до десяти тысяч | `1000 <= N < 10000` |
| От десяти до ста тысяч | `10000 <= N < 100000` |
| От ста до пятисот тысяч | `100000 <= N < 500000` |
| От пятисот тысяч до миллиона | `500000 <= N < 1000000` |
| От миллиона | `N >= 1000000` |

Это выбранные категории, не измеренные результаты; машиночитаемые границы находятся в конфиге. Неизвестная численность не попадает в минимальную группу. Нулевая опубликованная численность сохраняется отдельно: заявленное проживание требует проверки, а не автоматического алерта.

Группа — удобное представление для разметчика. Если известно точное население поселения, в расчёте использовать его. Если известна только группа, её граница не становится точечной оценкой: потребуется согласованное среднее внутри группы. Для случайного жителя оно взвешивается населением поселений, аналогично выбору работодателя через работника. Реестр поселений с актуальными числами для вычисления такого среднего пока не подготовлен.

## Мини-сервис для разметчика: предложение

Да, отдельный локальный калькулятор упростит применение одинаковых оснований. Он принимает уже выделенные и отнесённые к человеку атрибуты; NER для ручного ввода не требуется. Сам по себе интерфейс не создаёт недостающие частоты.

Предлагаемый контракт: `POST /estimate`, вход — люди, упоминания с типом, значением, `person_id`, `uncertain`, порядком и смысловой ролью. Выход по человеку: `candidate_count`, `status` (`estimated`/`insufficient_data`/`conflict`), `alert` (`true`/`false`/`null`), использованные основания, источники и даты, допущения и неучтённые атрибуты. Отдельно сохраняется исторический первый алерт. Неподдержанный атрибут не получает множитель ноль.

В интерфейсе нужны: выбор человека, добавление атрибута, нормализованная география, список оснований расчёта и причины неопределённости. Повтор и поздняя замена одного смыслового атрибута обрабатываются по уже выбранным правилам; прошлые упоминания не переписываются. Неуверенный атрибут выбранного человека учитывается. Контакты и реальные персональные записи не должны попадать в примеры, тесты и журналы.

Пока это описание контракта, веб-сервис не реализован. По последующему уточнению лида пол остаётся входным атрибутом калькулятора. [Условные вероятности без повторного учёта, подтверждение ФИО и запуск сборщика hh](../research/notes/sex-name-probabilities-and-hh-runbook-2026-11-15.md).

## Без обязательного возраста и пола

Лид подтвердил: возраст не используем как отдельный критерий, частоты имени нужны для населения России всех возрастов; дополнительно ищем частоты фамилий/отчеств и совместные частоты полного ФИО. Следовательно, никакое возрастное условие к человеку не применяется. Статистические возрастные группы могут оставаться внутренним способом получить общую частоту имени по всем поколениям. Это не требует нового класса разметки. Исключение возраста зафиксировано в рабочей политике; опубликованная схема разметки пока не переписана.

Для случайного жителя России без дополнительных условий: `N_hat(x) = N_Russia * p_population(x)`. Если имеются качественные частоты по непересекающимся группам, `p_population(x) = sum_g w_g * p(x | g)`, где веса отражают всё население, а не современную рождаемость. Без возрастной привязки не значит «усреднить все поколения поровну».

При наличии только частот по полу сначала получаем общую частоту через взвешивание обоих полов. Если пол отдельно не используется, не умножаем затем ещё раз на долю пола. При частоте имени из разрозненной выборки нормирование `count / sum(count)` даёт долю **выборки**, а не доказанную национальную частоту.

Базовая популяция проекта — жители России, а не только граждане: слово «россиянин» здесь не вводит новый фильтр гражданства. Если нужен именно критерий гражданства, потребуется другое определение знаменателя.

## Частоты частей ФИО и полного сочетания

Новый конкретный кандидат: [datacoon/russiannames](https://github.com/datacoon/russiannames). Наличие отдельных `names.parquet`, `midnames.parquet`, `surnames.parquet` подтверждено через дерево репозитория. [Каталог имён](https://data.apicrafter.ru/tables/russiannames/names) и [фамилий](https://beta.apicrafter.ru/tables/russiannames/surnames) описывает поле `count`; [схема](https://data.apicrafter.ru/tables/russiannames/names/schema) подтверждает счётчик. Доступ к данным описан также через `https://api.crftr.net/open/rawapi/v3/russiannames/{collection}` с коллекциями `names`, `surnames`, `midnames`.

```powershell
python -X utf8 tools/check_annotation_source_access.py --source name_frequency_files --source name_frequency_schema
```

Это отдельные агрегаты по частям имени. Подтверждённого распределения троек ФИО среди всего нынешнего населения России не получено. Указанный каталог описывает разрозненные источники; современность кода библиотеки не означает современность выборки. Следующий шаг — проверить происхождение, дату, знаменатель, дубли, ошибки редких значений, охват и права на использование; затем импортировать только агрегаты частей. Идентифицирующие записи людей и неизвестные архивы `data/raw` не скачиваются. До этой проверки кандидат не становится принятым национальным коэффициентом.

Профильное исследование полного ФИО уже описано в справочнике. Сам факт исследования не означает наличия опубликованной полной частотной таблицы. Без неё возможны согласованная факторизация/аппроксимация и сглаживание, но не автоматическое заявление независимости частей.

## Размер работодателя: выбранное значение

Лид выбрал среднее с весом численности: **454,070508887227**. Воспроизведение: `python -X utf8 tools/summarize_organization_sizes.py --show`, поле `size_weighted_mean`. Параметр закреплён в конфиге с источником и отчётной датой. Он используется как приближение для места работы выбранного человека, не для организации без связи с человеком.

Основание выбора: прочие рассмотренные средние давали бы самостоятельное срабатывание по месту работы из-за принятого порога. Это продуктовое решение; выбранное число не доказывает размер конкретного работодателя. Нельзя ещё раз умножить его на долю работодателя в России. Если место работы известно, география компании не становится автоматически местом проживания сотрудника.

## Должности через hh и `other`

**Заменено последующим решением лида:** основной источник — [численность занятых по группам занятий Росстата](../research/notes/rosstat-occupation-reference-2026-11-15.md). hh для коэффициентов не используется. Ниже сохранена история рассмотренного варианта.

Последующее уточнение пользователя: поддержка API для соискателей прекращена 15 декабря 2025 года. Применимость доступа приложения к агрегатам поиска не подтверждена; hh остаётся кандидатом источника, а не гарантированно доступной основой. [Исправленное описание сборщика](../research/notes/sex-name-probabilities-and-hh-runbook-2026-11-15.md).

[Официальная документация hh](https://api.hh.ru/openapi/redoc) описывает поиск вакансий, профессиональные роли и кластеризацию. Для проверки: `GET /professional_roles`; `GET /vacancies?area=113&per_page=1&clusters=true`. Территория поиска должна быть Россия; работа из другого региона и удалённая работа требуют одинакового правила включения. Прямая проверка поиска из текущей среды вернула HTTP 403; актуальные доли не получены.

Предлагаем использовать hh как отдельное приближение спроса на профессии. `q_vacancy(role)` не равно доле работников: влияют текучесть, активность найма, покрытие платформы и дубли публикаций. Вакансия также не обязательно соответствует одному рабочему месту.

`other` полезен для несопоставленных текстовых должностей, но он не компенсирует работников, не представленных на hh. Если оценивается распределение ролей, считать уникальные вакансии и назначать каждой одну группу по зафиксированному правилу либо делить её вес между ролями; сумма результатов отдельных поисков может содержать пересечения. Остаток допустим только после построения непересекающейся классификации общего знаменателя. Для нераспознанной должности безопаснее не уменьшать круг, сохранив `unmapped`, чем приписать ей маленькую частоту `other`.

Нормативное значение для расчёта пока не назначено. Проверка hh не заменяет поиски занятости по ОКЗ; сравнение двух источников позволит оценить смещение. Новая сущность NER `other` не нужна: это значение классификатора внутри атрибута должности.

## Полный / неполный адрес и оценщик

Принято направление: `full` — однозначно указанный адрес до дома, с квартирой при наличии; `partial` — дом не установлен. Квартира не обязательна для `full`. Один номер дома без достаточного географического контекста не подтверждает полный адрес. Это две категории детализации одной адресной сущности, не два независимых атрибута человека.

Предлагаемые поля: `completeness`, `resolved_level`, `gar_id`, `residence_role`, `resolution_status`. Даже при общей категории `full` сохранить различие «дом»/«квартира» для расчёта: их число жителей может существенно различаться. Два отдельных коэффициента пока не назначены: данные нужны для их получения.

Для поиска кандидаты подтверждены:

- [Поиск ФИАС/ГАР](https://fias-file.nalog.ru/Search), [расширенный поиск](https://fias-file.nalog.ru/ExtendedSearch): адресная иерархия и идентификаторы; не число жителей.
- [DaData, поиск по коду адреса](https://dadata.ru/api/find-address/): документированный API нормализации/поиска по идентификатору. Не подключён; условия доступа проверяются перед интеграцией.
- [ГИС ЖКХ, открытая информация о доме](https://cdn.dom.gosuslugi.ru/webhelp/topics/houses/och/r_card-och.html), [характеристики домов](https://cdn.dom.gosuslugi.ru/webhelp/topics/about_gis/r_required_info_zastr-zastr.html): в составе сведений есть количество квартир. Это основание для приближения, не реестр жильцов.

Предлагаемая последовательность: разрешить адрес → установить конкретную территорию/объект и детализацию → взять свежую численность территории либо число жилых единиц и согласованную оценку заселённости → вернуть оценку с источниками. Для района использовать его население, для дома — его характеристики. Не подменять жителей дома населением административного района, население улицы — числом адресов, а квартиру — средним размером дома. При неоднозначном адресе показать варианты/неопределённость.

Оценщик не реализован; внешние адресные сервисы не подключены. Даже если оценка мала, **адрес без других личных признаков не вызывает алерт**. Коэффициенты контактов и сочетаний остаются открытыми по пункту «пока не ясно».
