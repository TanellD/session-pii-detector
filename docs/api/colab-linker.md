# Локальный линкер в Google Colab

Подготовлен `notebooks/qwen3_linker_colab.ipynb` для запуска `Qwen/Qwen3-4B` на GPU Colab. Веса загружаются с Hugging Face, провайдер Gemma и его API-ключ не нужны. Конфигурация: NF4 с double quantization, FP16 либо BF16 по поддержке GPU, `enable_thinking=False`, greedy decoding, лимиты ввода и вывода. Можно выбрать `Qwen/Qwen3-1.7B`, используя отдельный каталог результатов. Потребление памяти и скорость надо проверить на выданном Colab GPU; гарантии конкретного GPU нет.

Основания: [официальная карточка Qwen3-4B](https://huggingface.co/Qwen/Qwen3-4B) описывает отключение thinking; [документация Transformers](https://huggingface.co/docs/transformers/v4.53.0/quantization/bitsandbytes) — загрузку в NF4. Notebook фиксирует Transformers, сохраняет версии остальных зависимостей, GPU и точную ревизию модели. При продолжении используется прежняя ревизия, а не обновившийся `main`.

## Подготовленные файлы

Актуальная версия — в `data/exports/colab-linker-250-2026-11-25-v2/`; первоначальный архив оставлен отдельно:

- `qwen3_linker_colab.ipynb` — копия notebook для загрузки в Colab.
- `qwen-linker-colab-bundle.zip` — переносимый код сервиса и оценщика, конфиги риска, синтетические данные, сохранённые предсказания Gemma и контрольные суммы файлов. Веса, `.env`, API-запросы провайдера и ключи не включены.
- `inference.json` — тексты и готовые спаны без владельцев, названий сценариев и алертов.
- `reference.json` — эталонные владельцы и заранее вычисленный эталон первого алерта для оценки после инференса.

Данные не добавляются в git. Notebook, экспортёр, исполнитель и документация находятся в одном наборе изменений.

## Порядок запуска

1. Откройте notebook через Colab → Upload notebook.
2. В Runtime → Change runtime type включите GPU.
3. Выполняйте ячейки сверху вниз. В диалоге загрузки выберите ZIP.
4. Для сохранения между runtime включите `USE_DRIVE=True`. Иначе результаты находятся во временном `/content` и их нужно скачать до отключения.
5. Выполните пробный запуск, посмотрите ошибки и сырые ответы. Затем запустите полную выборку.
6. Скачайте архив результатов последней ячейкой. Он содержит манифест, запросы, исходные ответы, предсказания, ошибки, времена и `summary.json`.

При повторном запуске завершённые сессии пропускаются. Ошибки также пропускаются по умолчанию; явный повтор — `retry_failed=True`. Прерванная сессия начинает новую попытку с сохранением старых файлов. Изменение модели, входа или параметров требует отдельного каталога. Загрузка модели не входит в замер генерации.

## Оценка и ограничения

Оценщик использует те же функции pairwise и алертов, что и локальные прогоны. Публикует число завершённых сессий и ошибки отдельно от Precision/Recall/F1, точного совпадения групп и Precision/Recall/F2-session/F2-timely. `common_subset` сравнивает с Gemma на одинаковых успешно обработанных ID. Неизвестные владельцы исключены из pairwise с указанием количества; точные группы их учитывают. Флаг служебного контакта отдельно не оценивается.

Это правильные спаны, а не выход NER. Данные короткие и синтетические, часть использовалась при отладке. Сервер Gemma использовал structured outputs, а HF generate получает схему в системном промпте и проходит строгую локальную проверку без constrained decoding и автоматического исправления JSON. Квантование тоже отличается. Поэтому измеряется переносимый baseline со своими условиями, а не влияние одного только размера модели. Время локальной генерации нельзя напрямую считать сетевым API RPS.

GPU-инференс в Colab при подготовке не выполнялся. Проверены Python-ячейки, автономный импорт архива, отсутствие владельцев во входном файле, сохранение/возобновление и воспроизведение метрик Gemma по сохранённым предсказаниям. Числа и проверка архива воспроизводятся из корня worktree:

```powershell

.\.venv-gliner\Scripts\python.exe -X utf8 -m unittest discover -s tests/service -p 'test_colab_linker.py'
```

## Уточнение локального промпта после первого запуска

В пользовательском Colab-пилоте локальная модель вернула `owners=[]` для обеих частей явно названного нового человека при пустом `known_people`. В локальный системный промпт добавлено определение владельца как субъекта сведений и различие между новым профилем и неизвестным владельцем. Для этого запуска нет доступа к его весам и GPU, поэтому исправление качества не подтверждено.

Новая версия notebook использует имя запуска `owner-v2` и контрольную сумму дополнительных инструкций. Старые ответы не перезаписываются и не участвуют в новом запуске. Фактические сообщения, переданные токенизатору, теперь сохраняются в `effective_messages` исходного ответа. Промпт API-прогонов Gemma и MiniCPM не менялся. Это доработка на основании тестового случая, поэтому повтор на тех же сессиях является отладкой, а не независимой проверкой качества.
