# Gemma как baseline линкера

Модель `Gemma-4-31B-IT` выбрана пользователем для экспериментального baseline.
Подключение — через настроенный Radeon Chat Completions API; локальные веса
этой LLM не устанавливались. Конкретная revision модели провайдером не сообщается.

## Контракт

`GemmaLinker` получает готовые кандидаты, текущее сообщение, известные факты
и ограниченный контекст предыдущих сообщений. Повторного извлечения NER нет.
Один запрос обрабатывает всех кандидатов сообщения. Если кандидатов нет,
внешний API не вызывается.

Модель возвращает владельцев для каждого `candidate_id`: существующие ID,
временные `new:N`, несколько подтверждённых владельцев либо пустой список
для неизвестного владельца. Пустой список переводится в `None`; новые ID
назначает код. Служебные телефон/email выделяются отдельным флагом и могут
иметь только неизвестную принадлежность. Существующие люди не объединяются,
прошлые факты не переназначаются.

Результат проверяется локально: нет пропущенных, повторных или лишних
кандидатов, придуманных существующих ID, повторных владельцев и недопустимых
служебных контактов. Изменение спанов или типа не входит в схему ответа.
Невалидный ответ или транспортная ошибка дают HTTP 502 без коммита состояния.
Нет скрытого перехода к случайному линкеру и автоматического исправления ответа.

## Состояние и контекст

Конфиг — `configs/linker-gemma-baseline.json`. `context_messages` задаёт
окно предыдущих сообщений. Оно хранится в памяти **внутри соответствующей
сессии**, обновляется после успешной обработки, очищается при reset и удаляется
вместе с записью сессии при очистке истёкшего TTL. После истечения TTL сессия недоступна.
Сообщения без кандидатов тоже входят в окно. GET истории по-прежнему возвращает
только сводки, без исходного текста. Другие линкеры без `context_window`
не включают хранение этого контекста.

Сам объект `GemmaLinker` не хранит прошлых сообщений, людей или счётчик ID.
Это позволяет использовать его между сессиями без переноса чужих карточек.
Окно не является полной историей: длинные ссылки на давние сообщения могут
остаться неразрешёнными. Число известных фактов и кандидатов ограничено
конфигом; превышение вызывает явную ошибку, а не молчаливое усечение людей.

## Подключение к сервису

Ключ передаётся через `RADEON_API_KEY`; в конфиг и журнал запросов не записывается.
Из корня worktree, когда переменная с ключом уже настроена:

```powershell
$env:PII_LINKER_MODE='gemma'
$env:PII_DETECTOR_MODE='gliner'
$env:PII_MODEL_DIR='outputs/gliner-prepared'
.\.venv-gliner\Scripts\python.exe -m uvicorn session_pii.app:app --app-dir src --host 127.0.0.1 --port 8000 --workers 1 --no-access-log
```

Линкер также можно явно передать в `create_app(linker=GemmaLinker(settings))`.
Режимы `stub` и `random` остаются доступны для контрольных проверок.
Транспорт ограничен одним запросом в работе на экземпляр; это настройка
эксперимента, а не подтверждение необходимой пропускной способности.
Полный API round-trip и ожидание внешней LLM нужно публиковать отдельно от
внутреннего бюджета сервиса, как указано в [методике](../kb/latency-budget.md).

## Оценка

`tools/evaluate_gemma_linker.py` проверяет изолированный линкер на правильных
спанах фиксированного синтетического снимка. Правильные владельцы, family,
будущие сообщения и ожидаемые алерты в API не передаются. Сохраняются
промпт, ответы, времена вызовов, предсказанные владельцы и счётчики по метрикам.
По умолчанию выбирается малый пилот сценариев. Полный срез:

```powershell
.\.venv-gliner\Scripts\python.exe -X utf8 tools/evaluate_gemma_linker.py --output data/experiments/gemma-linker-full --all-sessions --env-file '..\..\.env'
```

Продолжение того же запуска — та же команда с `--resume`. Успешные сессии
повторно не вызывают API; незавершённая сессия начинается заново в новом
каталоге попытки. Промпт, конфиг и входной снимок должны совпадать с manifest.
Числа пересчитываются без API через `--report-only`.

Ошибки показываются с покрытием, а не превращаются в отрицательные примеры.
Публикуются pairwise Precision/Recall/F1, точное совпадение групп владельцев
и F2-session/F2-timely цепочки с правильным извлечением. Это не качество
полной цепочки с реальным NER. Малый пилот используется для отладки и не
является независимым тестом. Живые проверки — в отдельном экспериментальном отчёте.
