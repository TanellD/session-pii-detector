# Архитектура решения

Статус: **не выбрана**. Заполняется на этапе 2 после ответов на исследовательские вопросы и согласования с ментором. Выбор фиксируется ADR.

Для обсуждения по #12: [предложение ADR-0003](../decisions/0003-detector-independent-session-layer.md),
[контракт API v0.1](../api/session-api.md), [сравнение детекторов](../research/notes/pii-detectors-comparison.md).
Это черновики; решение команды и совместимость с внутренним API HiveTrace не подтверждены.

Для интеграционной сборки реализован [HTTP-каркас](../api/service-scaffold.md): отдельные интерфейсы NER, regexp и линкера, состояние сессии в памяти и оценщик риска после линковки. Политика `runtime-risk-v2` задаёт сумму весов по каждому человеку и отдельную сумму неизвестных фактов; красные правила действуют в обеих ветках, согласованные сочетания — только у людей. Она отличается от статистического эталона разметки. По умолчанию подключён regex-адаптер, GLiNER включается явно для локальных весов. Для линкера доступны заглушка, случайный контроль и [Gemma baseline](../api/gemma-linker-baseline.md), включаемый явно через PII_LINKER_MODE. Для Gemma обработчик хранит ограниченный контекст внутри сессии; полный текст истории в GET не возвращается. Пересечения обрабатываются до линковки, происхождение упоминаний сохраняется. Эта реализация не переводит предложенный ADR в статус принятого решения и не подтверждает готовность production-развёртывания.
