## Содержание

1. Части сервиса: извлечение → нормализация → линковка → состояние → политика.
2. Метрики компонентов: Precision/Recall/F2 извлечения, pairwise P/R/F1 линковки;
   P и R на одной строке; границы задержки всего сервиса.
3. F2-timely с формулой и таблицей исходов; диагностика F2-session, offset и FP0.
4. Прогресс данных: подготовленные документы, кандидаты на аудит, путь к пилоту.
5. Текущее распределение обязанностей; следующий шаг — документ о моменте ПДн,
   линковщик и адаптация NER к нашим классам. Пока завершаем начатое;
   новые задачи добавятся на следующем синке.

B-cubed и ограничения интерпретации метрик объяснены в заметках PowerPoint.
На слайде ранний алерт обозначен FP. Численные цели качества и задержки не заданы.
По правкам пользователя CPE и технические статусы репозитория убраны из слайдов
и текста выступления; цепочка генерации и оговорка о незапущенном пилоте сняты.

## Воспроизведение и проверка

Из корня репозитория, при наличии указанных git-коммитов и шрифтов Segoe UI:

```powershell
python -m pip install --target outputs/presentation-deps -r tools/requirements-presentation.txt
python tools/build_progress_sync_presentation.py
```

Команда создаёт ровно пять слайдов, проверяет количество страниц PDF и слайдов
PowerPoint, наличие заметок, ширину строк и границы текстовых блоков.
Формулы заданы по `docs/kb/metrics.md` из принятого коммита; это не новый
оценщик метрик и не эксперимент. Слайд с данными опирается на артефакты ветки,
а не на повторный аудит внешних датасетов. Визуальная проверка — по `preview.png`.
